# Onboarding

- **First run** (`isFirstRun`, `markFirstRunDone`, `<FirstRun>`): shown once, in an interactive terminal only, before the app. One sentence, one command to try (`centcom init`), where to read more. Any key closes it. `<state dir>/state.json` remembers it (`firstRunCompletedAt`); if that cannot be written, the app says once that the screen may show again. Waving half-block Cento from 30 rows up, the ASCII Cento below that and under `NO_COLOR`, none when the mascot is off, plain text with `plain`.
- **`centcom init [--yes] [--force] [--dry-run]`** (`runInit`; wiring in `apps/cli/src/commands/init.ts`): creates `.centcom/config.json` in the repository's top folder (or the current folder outside git, with a note that checkpoints and worktrees need git), the project memory file (`CLAUDE.md`, through the memory-files lane), and adds `/.centcom/*` and `!/.centcom/config.json` to `.git/info/exclude`, so Centcom's local files stay out of `git status` while the shared config can be committed. Never edits tracked files. Running it again prints `Already set up.` and changes nothing. Without a terminal it needs `--yes` (exit 2 otherwise). An existing config is only replaced with `--force`, after a `.bak` copy. Exit codes: 0 done or already done, 1 a step failed (the others still ran), 2 bad usage.
- **Empty states** (`<EmptyState kind>`, `emptyText`): the DESIGN §13.3 wording for no sessions, no results and no team, with the small ASCII Cento only where the mascot is allowed. Used by `/resume` and the command palette.
