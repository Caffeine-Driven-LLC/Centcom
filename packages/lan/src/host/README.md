# LAN host server (lane C072)

`new LanHostServer({ sessionId, sessionName, hostMember, tokens, transcriptPath, clock, ids, port?, bind?, allowWan?, maxMembers?, pairing?, bans?, interceptor?, snapshots?, logger? })`, then `start()` gives `{ port, addresses }` and `stop()` ends it. It does the relay's job on a local network.

- **Listening:** `ws://` only, subprotocol `centcom.v1`, port 7070 (a free port if that is taken), all interfaces by default, `bind` to restrict. A public address is refused (`PublicBindRefusedError`) unless `allowWan`, which warns once. At most 8 live members (the host's own loopback counts). A banned address is turned away at the door.
- **Connecting:** hello within 5 s (else close 4408); before it only `lan.pair.*` frames, handed to the pairing handler; the hello `ticket` is the LAN reconnect token (`tokens.validate`): unknown is `sys.error` and 4401, revoked is 4403, a second connection of the same member and device ends the first with `sys.bye superseded` and 4409. The welcome carries protocol 1, heartbeat 20 s / 50 s, the limits and the lowest free slot.
- **Numbering:** one counter from 1 for `event`, `queue` and `control` frames in arrival order; `from` and `ts` are stamped by the server (anything the client claims is ignored), the sender gets its own frame back with the number, everyone gets the same order; a repeated frame id gets its first number. Presence is never numbered. Server-only kinds sent by a client are ignored; unknown kinds are numbered and passed on.
- **Resume:** the last 5,000 frames or 10 minutes (whichever is more) are kept; `last_seq` inside them replays what was missed and then `sys.resumed {from_seq, to_seq, count}`; outside, `sys.resumed {snapshot_required, snapshot_seq}`, and `lan.snapshot.get` answers with `lan.snapshot.begin`, base64 `lan.snapshot.chunk` frames (128 KiB each) and `lan.snapshot.end` from the snapshot provider (`lan.snapshot.none` when there is none). Every numbered frame is also written to a JSONL transcript with mode 0600, exactly as it went out.
- **Limits:** pings every 20 s, a connection silent for 50 s is closed (1001); sequenced frames 30 a second with a burst of 100 (`sys.slow_down` over that; the frames are still numbered), presence 10 a second (extras dropped); a client that lets 2 MiB pile up is closed 4429; every inbound frame is checked against the envelope schema (`invalid_frame`, more than 10 a minute closes 4400); frames over 256 KiB are refused.
- **Presence:** the newest update per member goes out at most every 500 ms and the newest cursor every 100 ms; a typing indicator not refreshed ends after 5 s with an idle update; a new member gets everyone's latest update. A member gone for 10 s is announced with `control.member_left`.
- **For the host engine (C075):** `interceptor.onInbound` accepts, rejects (with a problem body) or replaces a frame before it is numbered; `broadcast(frame)` sends a numbered server frame (`from: "srv"`), `sendTo`, `kickConnection`, `members()`, `headSeq()`, and `createLoopbackLink()` gives the host's own member a `FrameLink` that goes through memory down the same path.

Tests use the real `RelayClient` and reliable channel from `@centcom/net` and raw sockets for abuse cases, on a virtual clock where time matters.
