# Pull request description

Use this when asked to open or describe a pull request.

1. Title: what the change does, in the imperative, at most 70 characters.
2. Body, in short sections: **What** changed, **Why** it was needed, **How it was checked** (tests run, what you tried by hand), and **Not done** (anything left out on purpose).
3. Link the lane card or issue it belongs to.
4. Keep it to what a reviewer needs; do not paste the diff or long logs.
5. Never include secrets or private paths.
