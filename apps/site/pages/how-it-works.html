How it works

From one agent to a whole room of them

A session is a working room: one host, several people, any number of agents. This page walks through starting one and what everyone in it can see and do.

Four steps

  1. Install and start. Make sure claude or codex works on its own, then run centcom in a project folder. No account is needed for this.
  2. Work as usual. Type what you want done. When the agent wants to run a command or change a file, Centcom asks first.
  3. Share the session. Start sharing and Centcom shows a pairing code. On the same network people find it with centcom lan scan; further away a hosted session needs a plan.
  4. Join. Others join with the code or a link, from the terminal, the desktop app or the browser.

What the team sees in branch mode

  • That an agent exists, and whether it is working, waiting for approval or idle.
  • Which branch it is on and how far it is ahead of or behind the base.
  • Which files it has open. A second agent about to touch the same file is warned first.
  • Shared notes and decisions, which reach every agent with its next message.
  • An agent's activity too, while its owner has sharing switched on. The owner can turn it off at any time.

Files' contents, diffs, private notes, environment variables and secrets are never shared. A teammate sees code only if its owner puts it in a message that is shared.

What the relay can and cannot see

Every frame of a hosted session is encrypted with a key the relay never has. The relay reads only a small, unencrypted part of each frame: ids, states, counts and keyed hashes of lock paths. Work content, such as code, file paths, branch names, model names and message text, stays inside the encrypted part. The exact lists are in the documentation.

Working alone or on your own network never touches the relay or any server, and is never limited by a plan.
