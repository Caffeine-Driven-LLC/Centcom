## Goal
A pure validation layer that checks agent.state values against the state-map contract and the wire-vs-client-local split, so the relay never forwards invented states and never emits client-local states as agent state.

## In scope
- Build-time loader that derives the allowed-state set from contracts/state-map.json keys and the wire/local split from contracts/09-state-map.md categories.
- validateAgentState(state: string): StateVerdict with outcomes accepted, client_local (rejected as agent state) and unknown.
- Policy for unknown states: tolerate and forward as opaque (unknown enum values are tolerated), but count and log at debug; never invent states.
- Rate and de-dup helper: identical consecutive state per agent suppressed; at most 2 changes per agent per second.
- Test that the generated p_agent_state enum equals the state-map keys (drift guard in CI).

## Out of scope
- Agent registry and ownership checks: B057.
- Mapping states to animations or copy (client concern).
- Emitting sys.notice for quota or rate limits: B076 / relay notices.
- Editing contracts/state-map.json (read-only).

## Build against (no counterpart needed)
Reads contracts/state-map.json and generated packages/contracts types directly; no network. Table-driven tests with the full key list.

## Interfaces (the only surface other lanes may use)
- validateAgentState(state: string): {verdict:'accepted'|'client_local'|'unknown'}

- createStateGate(opts:{clock: ClockPort}): { admit(agentId: string, state: string): 'send'|'drop_duplicate'|'drop_rate' }

## Acceptance criteria
1. Every key in contracts/state-map.json is classified exactly once as wire or client_local (no key in both, none unclassified) and the test fails if a key is added without a classification entry.
2. validateAgentState('thinking') and ('awaiting-approval') are accepted; 'offline', 'reconnecting', 'quota-reached' and 'teammate-joins' return client_local; 'dancing' returns unknown.
3. The gate admits a first state, drops an identical consecutive state (drop_duplicate), and admits at most 2 distinct changes within any 1 s window per agent (third returns drop_rate); windows are per agent.
4. The enum in p_agent_state of contracts/schemas/events.schema.json equals the key set of state-map.json (drift test).
5. Handling unknown: the relay integration path forwards unknown states with a debug log and counter relay_agent_state_unknown_total and never errors.
6. Module has no I/O and no global state; 100 000 validations run in < 200 ms in the unit suite.

## Tests required
- state.classification.test.ts: exhaustive over state-map keys
- state.gate.test.ts: rate/dedupe with fake clock, property test on random sequences
- state.drift.test.ts: schema enum vs state-map keys
- state.unknown.test.ts: tolerance behaviour

## Guardrails (MUST / MUST NOT)
- MUST NOT hand-copy the list of state names; derive from state-map.json and fail the build on drift.
- MUST NOT add, rename or map states; animation values in state-map.json are never read by the backend.
- MUST treat unknown states as tolerated input (CT-STATE-MAP rule 1), not as protocol errors.
- The client-local list MUST be reconciled with the category text in 09-state-map.md in a single constants file with a comment citing the section.

## Failure modes
- state-map.json missing or unparsable at startup -> fail fast with a clear config error; the relay refuses to start.
- A new state key appears after a contract bump without classification -> CI drift test fails; runtime treats it as unknown (forwarded).
## Notes
CONTRACT GAP: 09-state-map.md lists wire categories in prose only (idle, work, human-needed, outcome, merge-conflict, deploying, saving); individual keys such as `listening`, `prompt-received` and `host-session` are not explicitly assigned. This lane classifies by category text and records the ambiguous keys in a constant with a TODO-free comment citing the contract; a human should confirm.
