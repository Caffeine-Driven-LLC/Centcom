## Goal
Per-user notification preferences (channels by category, quiet hours) with GET/PUT endpoints and a pure evaluator the dispatcher uses to decide whether a push or os notification is suppressed.

## In scope
- GET and PUT /v1/notification-preferences (PUT replaces the whole document).
- Preference document validation: known categories only, channels limited to inbox|push|email|os, quiet hours with IANA timezone and HH:MM start/end.
- Defaults per CT-NOTIF-PAYLOAD (approval_needed -> inbox+push+os; billing_issue -> inbox+email; everything else inbox) returned when the user never saved preferences.
- Server-enforced invariants: security_alert and billing_issue always keep `inbox`; quiet hours can never suppress them.
- Pure functions isQuietNow(prefs, now) (handles overnight ranges and DST via the timezone database) and the PreferencesPort implementation for B063.
- ETag on GET and If-Match on PUT.

## Out of scope
- Inbox API: B065. Dispatcher routing code: B063. Push registry: B064.
- Client-side OS notification suppression logic.
- Email unsubscribe links/compliance footer (email service, B032).

## Build against (no counterpart needed)
Postgres container or in-memory repository, fixed clocks with explicit time zones (Europe/Berlin, America/New_York, Pacific/Auckland) in tests, Fastify inject.

## Interfaces (the only surface other lanes may use)
- GET /v1/notification-preferences -> 200 {channels: Record<NotifCategory, ('inbox'|'push'|'email'|'os')[]>, quiet_hours: {enabled:boolean, start:'HH:MM', end:'HH:MM', timezone:string, allow_high_approval:boolean}} with ETag
- PUT /v1/notification-preferences (If-Match optional) -> 200 same shape

- PreferencesService.get(userId): Promise<UserNotificationPrefs>  // implements B063's PreferencesPort

## Acceptance criteria
1. GET for a user with no row returns the contract defaults for all 14 categories, with quiet_hours.enabled=false.
2. PUT with an unknown category or channel 'sms' returns 422 with errors[].pointer such as '/channels/approval_needed/0'; unknown extra top-level fields are ignored on read per the robustness rule but not persisted.
3. PUT that removes `inbox` from billing_issue or security_alert is stored with `inbox` re-added and the response shows it; quiet hours never alter their delivery (test via isQuietNow + decideChannels contract in B063 fixture).
4. isQuietNow with start 22:00 end 07:00 Europe/Berlin returns true at 23:30 local, true at 06:59, false at 07:00, and handles a DST changeover day without throwing or being wrong by an hour.
5. start == end is rejected 422 (zero-length window) ; an invalid timezone string is rejected 422.
6. PUT with stale If-Match returns 412 `precondition_failed`; a successful PUT changes the ETag.
7. Document size limit 8 KiB enforced (413/422) and the endpoint is rate limited per CT-PAGE.

## Guardrails (MUST / MUST NOT)
- MUST keep security_alert and billing_issue deliverable regardless of user prefs (inbox always on).
- MUST validate the time zone against the platform IANA database, never trusting client-provided offsets.
- MUST NOT store anything beyond the preference document (no device names, no tokens).
- Defaults MUST be code-level constants tested against the contract, not rows seeded in the DB.

## Failure modes
- Stored document fails validation after a code change (stale shape) -> service returns defaults merged with valid parts and logs a warning, never a 500.
- Concurrent PUTs -> last write wins unless If-Match given; version increments atomically.
