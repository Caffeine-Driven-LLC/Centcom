## Goal
A view-only guest who opens a share link can check who signed each frame, so the guest sees the session instead of a stream of unknown-sender warnings.

## In scope
- `GET /v1/share-links/{token}/members` (public, rate-limited like `join`): the live members of the link's session as `SessionMemberPage` without `user`, with display name, device, role, slot, join order and device keys; nothing else.
- Unknown, revoked or expired token: the same 404/410 answers as `join`; no information about the session.
- Uses B068's token lookup and B054's member store; no new table.

## Out of scope
- Changing the relay or the ticket.
- Fingerprint comparison for guests (they trust the server's key list; CT-CRYPTO §4a).

## Build against (no counterpart needed)
The in-memory share-link and session stores used by B068 and B054 tests.

## Deliverables
- `apps/api/src/routes/share-links/members.ts`
- `apps/api/test/routes/share-links/members.test.ts`

## Interfaces (the only surface other lanes may use)
- HTTP: `GET /v1/share-links/{token}/members`.

## Acceptance criteria
1. A valid token returns the live members' ids, display names, slots, roles, device ids and device keys, and no `user` field, no e-mail and no workspace data (schema test).
2. A revoked token is 410, an expired one 410, an unknown one 404, with the bodies `join` gives.
3. Members who left or were removed are not listed; the response is `Cache-Control: no-store`.
4. The route is rate-limited per address like `join` (test).
5. With the client's guest connected through B103's relay, frames from members verify (no `unknown_sender`).

## Tests required
- members.test.ts: valid token returns only the contract fields
- members.test.ts: revoked, expired and unknown tokens give the answers `join` gives
- members.test.ts: members who left are not listed, and the rate limit holds
- two-accounts guest step: the guest reads the host's message

## Guardrails (MUST / MUST NOT)
- MUST NOT put tokens, tickets, invite or link secrets, key material or e-mail addresses in logs.
- MUST keep contracts/ as it is: this lane builds against the contract text and fails closed where the contract is silent.
- MUST NOT return user ids, e-mail, workspace data or members that are not live.

## Failure modes
- Database slow -> 503 with `retry_after_s`.
- Token valid but the session ended -> 410.
