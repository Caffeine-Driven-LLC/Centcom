## Goal
Redis access sits behind one interface with an in-memory implementation for tests and a Redis implementation for production, including atomic rate-limit and set-if-absent primitives.

## In scope
- Interfaces `KeyValue`, `PubSub`, `RateLimitStore` in packages/core/src/redis/types.ts.
- In-memory implementation (fake clock aware, TTL expiry, pub/sub in-process) used by all unit tests.
- ioredis implementation: connection with reconnect backoff, 2 s command timeout, TLS support, key prefix `ct:<env>:`, separate subscriber connection.
- Rate-limit primitive: sliding-window counter implemented as one Lua script (atomic), returning `{allowed, limit, remaining, resetS}`.
- `setIfAbsent` with TTL (for idempotency and single-use jti), `incr` with TTL, and a health ping.

## Out of scope
- The rate-limit middleware and bucket policy (B023) and idempotency middleware (B024).
- Relay replay buffers and presence (relay lanes).

## Build against (no counterpart needed)
Run the same contract test suite against the in-memory impl always, and against a real Redis 7 when REDIS_URL is set (CI service container).

## Interfaces (the only surface other lanes may use)
- `interface KeyValue { get(k): Promise<string|null>; set(k, v, opts?:{ttlMs?: number}): Promise<void>; setIfAbsent(k, v, ttlMs): Promise<boolean>; del(k): Promise<number>; incr(k, ttlMs): Promise<number>; ttl(k): Promise<number|null> }`.
- `interface PubSub { publish(channel, msg: string): Promise<void>; subscribe(channel, handler:(msg:string)=>void): Promise<() => Promise<void>> }`.
- `interface RateLimitStore { consume(key: string, limit: number, windowS: number, cost?: number): Promise<{allowed: boolean; limit: number; remaining: number; resetS: number}> }`.
- `createMemoryRedis(clock?: () => number)` and `createRedis(cfg:{url: Secret<string>; keyPrefix: string})` both returning `{kv, pubsub, rateLimit, ping(), close()}`.

## Acceptance criteria
1. The shared contract suite passes identically for memory and real Redis (set/get/ttl/setIfAbsent/incr/pubsub/rateLimit).
2. `setIfAbsent` called 100 times concurrently on one key returns true exactly once.
3. `consume('k', 30, 60)` allows 30 calls inside one window and denies the 31st with `remaining:0` and `resetS` between 1 and 60.
4. Sliding window: after advancing the fake clock by a full window, the counter is empty again.
5. A Redis command exceeding 2 s rejects with a typed unavailable-class error and does not hang the caller.
6. The subscriber reconnects after the server restarts and receives messages published afterwards within 5 s (integration test).
7. All keys written carry the prefix `ct:<env>:` and a TTL.

## Tests required
- kv.contract.test.ts (shared across impls).
- ratelimit.contract.test.ts with fake clock and concurrency.
- pubsub.contract.test.ts: ordering per channel, unsubscribe, reconnect.
- failure.test.ts: command timeout, connection refused.

## Guardrails (MUST / MUST NOT)
- MUST make rate-limit consume a single atomic operation (Lua); MUST NOT implement it as get-then-set.
- MUST give every key a TTL; unbounded keys are a bug.
- MUST NOT log key values or pub/sub payloads (they may carry session metadata).
- MUST NOT use Redis as the source of truth for money, membership or entitlements (cache only).

## Failure modes
- Redis down -> methods reject with a typed unavailable error; callers (B023/B024) choose fail-open/closed explicitly, this layer never decides.
- Lua script evicted (NOSCRIPT) -> reload and retry once.
- Pub/sub handler throws -> error is caught, logged without payload, subscription continues.
