## Goal
Provide the workspace CRUD surface of CT-API-WORKSPACES (list, create, read with ETag, rename, delete) with correct ownership rules, optimistic concurrency and a safe delete that hides the workspace immediately and purges asynchronously.

## In scope
- GET /v1/workspaces (cursor-paginated, caller's memberships only), POST /v1/workspaces, GET /v1/workspaces/{id}, PATCH /v1/workspaces/{id}, DELETE /v1/workspaces/{id}.
- Create: one transaction inserts workspace and an `owner` membership for the caller; slug auto-generated (`[a-z0-9-]{3,40}`, numeric suffix on collision).
- ETag on GET/PATCH; PATCH requires `If-Match`, mismatch -> 412 `precondition_failed`.
- Delete (owner only): set `deleted_at`, publish `workspace.deleted` on Redis channel `centcom:workspace-events`, enqueue BullMQ job `workspace-purge`; reads return 404 immediately.
- A purge-hook registry (`registerPurgeHook`) so later lanes (history, snapshots, billing wind-down) plug into the purge job.
- A PATCH extension registry so B034 can add the `settings` object without editing this lane's files.

## Out of scope
- Members and role changes (B028), invites (B029), settings semantics (B034), projects (B035).
- Audit emitter internals (B036) and the audit read API.
- Stripe cancellation and the 7-day billing wind-down logic (B070-B073); only a hook point is provided.
- Purging session history and snapshots (B055, B056, B090) - they register hooks.

## Interfaces (the only surface other lanes may use)
- HTTP: the five routes above; request/response shapes from the generated CT-API-WORKSPACES types (B003).
- TS: `interface WorkspaceService { create(userId: string, input: { name: string }, ctx: RequestCtx): Promise<Workspace>; get(wspId: string): Promise<Workspace | null>; rename(wspId: string, name: string, ifMatch: string, ctx: RequestCtx): Promise<Workspace>; softDelete(wspId: string, ctx: RequestCtx): Promise<void>; listForUser(userId: string, page: PageRequest): Promise<Page<Workspace>>; }`
- TS: `registerPurgeHook(name: string, fn: (wspId: string, ctx: PurgeCtx) => Promise<void>): void` and `registerPatchExtension(ext: { key: string; schema: JsonSchema; apply(trx: Trx, wspId: string, value: unknown): Promise<void> }): void`.
- Redis pub/sub channel `centcom:workspace-events` payload `{type: 'workspace.deleted', wsp: string, at: string}`.
- DB: tables `workspaces(id, name, slug unique, created_by, created_at, updated_at, deleted_at, version int)`; the `version` column is the ETag source.

## Acceptance criteria
1. POST /v1/workspaces returns 201 with the caller as `owner`; replaying the same Idempotency-Key returns the same body with `Idempotency-Replayed: true`; names of 0 or 61 chars return 422, 60 chars returns 201.
2. A name containing a control character U+0007 is rejected 422; a name with decomposed Unicode is stored NFC-normalised.
3. GET /v1/workspaces returns only the caller's workspaces, `limit` default 50 and max 200, with `next_cursor`/`has_more`; a cursor reused with a different filter returns 400.
4. GET /v1/workspaces/{id} returns an `ETag`; PATCH without `If-Match` returns 428-equivalent per registry (400 class), with a stale `If-Match` returns 412 `precondition_failed`, with the right one returns 200 and a new ETag.
5. PATCH by a `member` role returns 403; by `admin` returns 200; GET by a non-member returns 404 (not 403).
6. DELETE by `admin` returns 403; by `owner` returns 204; the very next GET returns 404 and the `workspace-purge` job exists in the queue.
7. The purge job runs registered hooks in registration order, is idempotent when re-run, and ends by hard-deleting the workspace row; a failing hook is retried 5 times (backoff + jitter) then dead-lettered.
8. A user already owning 20 workspaces (config `WORKSPACES_MAX_OWNED`) gets 409 on the 21st create.

## Tests required
- workspaces.routes.test.ts: CRUD happy paths, ETag/If-Match matrix, role matrix from CT-RBAC (owner, admin, member, billing, guest).
- workspaces.pagination.test.ts: 120 workspaces, limit/cursor stability, cursor-filter binding.
- workspace-purge.job.test.ts: hook ordering, idempotency, dead-letter after 5 failures.
- workspaces.validation.test.ts: name length, NFC, control chars, slug collisions (property test over random names).
- Contract: response bodies validate against the CT-API-WORKSPACES validators.

## Guardrails (MUST / MUST NOT)
- Non-members MUST get 404, never 403, so workspace existence is not leaked.
- Delete MUST hide the workspace in the same transaction that sets `deleted_at`; purge work happens only in the job.
- The sole-owner invariant MUST hold: exactly one `owner` membership per workspace, enforced by a partial unique index, not just code.
- MUST authorise through the B021 RBAC engine only; no inline role comparisons in route handlers.
- MUST NOT accept `settings` in PATCH unless a registered extension owns it; unknown fields are ignored per CT-VER, never stored.

## Failure modes
- Redis publish fails after commit -> log at error, rely on the purge job to re-publish `workspace.deleted` as its first step.
- Two concurrent PATCHes with the same ETag -> exactly one 200, the other 412.
- Slug collision race -> retry with a new suffix up to 5 times, then 409.
- Purge hook throws -> job retries; workspace stays hidden (404) throughout.
