## Goal
A relay-side queue service that orders, de-duplicates, caps and approves command-post queue items, emits the authoritative queue.state after every change, and applies the session's auto-approve policy.

## In scope
- Queue state machine per CT-WS-QUEUE: queued -> approved -> running -> done|failed, plus canceled, rejected, dropped and held.
- Handlers for queue.submit, queue.cancel, queue.approve, queue.reject, queue.reorder, queue.drop, queue.claim, queue.done with role checks (submit: editor/host; others host-only; cancel: submitter only).
- Idempotency on (sid, from, que id); caps: 5 live items per member, `queue_limit` (default 20) per session, ciphertext size <= 192 KiB.
- Auto-approve policy (ask, trusted, everyone) with server-emitted queue.approve frames audited as policy actions.
- Authoritative queue.state {version, items} emitted after every change and on join; position derived only from approve/reorder order.
- Host-loss handling: approved/running items become held when the host disconnects and return on host reconnect; new host sees them as approved.
- Hook to pause approvals when the quota service says so (setApprovalsPaused) and a relay-side queue_items counter.

## Out of scope
- Policy storage and the control.policy command: B051 (read via PolicyReader port).
- Quota warning logic and notices: B076; usage aggregation: B075.
- Frame sequencing, ack and fan-out: B041/B044.
- Client-side display of queue bodies.
- Trusted-list management endpoints (CONTRACT GAP, see notes).

## Acceptance criteria
1. Replaying the same queue.submit (same sid, from, id) 10 times yields one item and one seq; the 9 repeats are no-ops that return the existing seq.
2. A 6th live item from one member returns sys.error `queue_full`; with queue_limit=20 the 21st item from any member also returns `queue_full`; a member with 5 live items can submit again after one is canceled.
3. queue.submit with p.size 196609 (192 KiB + 1) is rejected `invalid_frame` and never stored; 196608 passes.
4. Viewer or muted member submit, and any submit when policy.locked=true, are rejected `forbidden` and audited.
5. Host queue.approve of an unknown or finished item sends sys.error `queue_item_gone` to the host only and emits no queue.state.
6. Two reorder frames with seq 100 and 101: the order from seq 101 wins; replaying all frames from seq 1 into a fresh QueueService rebuilds a byte-identical queue.state (property test, 200 random frame sequences).
7. policy auto_approve='everyone': an editor submit produces queue.submit then a server-sent queue.approve (from = server) with consecutive seq; with 'ask' nothing is auto-approved; with 'trusted' only listed members are.
8. Host disconnect marks approved/running items held in queue.state within 1 s; host reconnect restores them; after control.host_changed the held items show as approved.
9. queue.state.version increases by exactly 1 per state-changing frame and is not incremented by rejected frames.
10. With setApprovalsPaused(sid,true), host queue.approve and auto-approvals leave items queued; cancel and drop still work.

## Guardrails (MUST / MUST NOT)
- MUST derive item order only from approve/reorder frames processed in seq order; never from client timestamps.
- MUST NOT read or store `ct` bodies of queue.submit; store id, size, kind, submitter, state only.
- MUST enforce roles from live membership; approve, reject, reorder, drop, claim, done are host-only and denials are audited.
- MUST emit auto-approvals from the server identity so the audit trail shows the policy, never as the submitter.
- MUST NOT let paused approvals (quota) block LAN or cancel/drop operations on hosted sessions.
- Each item may be claimed at most once and one agent may hold only one running item; a second claim returns sys.error `forbidden`.

## Failure modes
- Sequencer failure mid-batch (submit + auto-approve) -> neither frame is visible; client retries with same id and gets a consistent result.
- DB write fails -> frame rejected with 503-class sys.error; in-memory state is not advanced.
- Instance restart -> queue rebuilt from queue_item rows plus frames after updated_seq; version continues without gaps.
- Reorder lists unknown item ids -> unknown ids ignored, known items keep relative order, sender gets sys.error `queue_item_gone` once.
