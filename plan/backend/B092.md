## Goal
Ship every release through a repeatable pipeline: build, stage deploy, smoke and gate checks, manual-approved prod blue/green, safe expand/contract migrations, and a rollback that completes in under 5 minutes.

## In scope
- GitHub Actions workflows `deploy-stage.yml` (auto on main after CI green) and `deploy-prod.yml` (manual approval, same artifact digest as stage), plus `rollback.yml`.
- Build once, deploy by digest: container images for api, relay, worker, admin tagged with the git SHA, signed (cosign) and scanned (trivy) before deploy.
- Migration safety: `migration-lint` script rejecting `DROP COLUMN`, `RENAME`, `SET NOT NULL` without default/backfill, non-`CONCURRENTLY` index creation on large tables, and anything that breaks the previous release; migrations run as a release command before traffic shifts.
- Blue/green for api and worker (`fly deploy --strategy bluegreen`), rolling per-region for relay with connection draining (SIGTERM -> `1001` closes with jitter) limited to one region at a time and <= 25 % of connections shed per minute.
- Post-deploy verification: smoke script (healthz/readyz/status, auth device-code start, JWKS fetch, a WS handshake with a stage test ticket), then SLO guard for 5 min (5xx rate < 1 %, p95 latency within 2x baseline) with automatic rollback on breach.
- Release gate input: the pipeline requires a passing `conformance-report.json` (schema defined in B100) for the same commit and a clean `pnpm infra:check` before prod.
- Rollback tooling `infra/deploy/rollback.sh <service> [digest]` and runbook entry; deploy lock to avoid concurrent deploys.

## Out of scope
- Terraform and base infrastructure (B091); CI build/test stages (B002).
- Authoring migrations (B007) and application changes.
- Alert rules and on-call (B094); load and chaos tests (B095, B096).
- Client release/auto-update artifacts.

## Build against (no counterpart needed)
Run the scripts locally against the compose stack (B012) and a dry-run mode (`DEPLOY_DRY_RUN=true`) that prints Fly/GitHub commands; a fixture `conformance-report.json` in test data stands in for the real suite output; workflows are validated with `actionlint`.

## Interfaces (the only surface other lanes may use)
- Scripts: `infra/deploy/deploy.sh <env> <service> <digest>`, `infra/deploy/smoke.mjs --env <env>`, `infra/deploy/slo-guard.mjs --env <env> --window 300`, `infra/deploy/rollback.sh <service> [digest]`, `infra/deploy/migration-lint.mjs <files...>`.
- GitHub environments `stage` and `production` with required reviewers on `production`; repository variables `FLY_ORG`, `IMAGE_REGISTRY`.
- Deploy lock: Redis/GitHub concurrency group `deploy-<env>`; exit codes: 0 ok, 10 gate failed, 20 smoke failed, 30 SLO breach (rolled back).
- Artifact `deploy-record.json` `{env, service, digest, git_sha, started_at, finished_at, result}` uploaded per run.

## Acceptance criteria
1. Merging to main with green CI deploys the same digest to stage without manual steps and runs smoke + SLO guard; total pipeline time from merge to green stage <= 20 min.
2. `deploy-prod` refuses to start if the digest was never deployed to stage, if `conformance-report.json` is missing, stale (> 24 h) or has `summary.failed > 0`, or if `infra:check` failed.
3. `migration-lint` fails on each of: drop column, rename column, add NOT NULL column without default, `CREATE INDEX` without `CONCURRENTLY` on an existing table; passes for additive migrations (table-driven tests with 12 SQL samples).
4. A deploy where `/readyz` of the new version fails is not promoted: traffic stays on the old version and the job exits 20 within 5 min.
5. An injected 5xx rate of 5 % during the SLO guard window triggers rollback and the previous digest serves traffic again within 5 min of detection; `rollback.sh` run manually completes in <= 5 min.
6. Relay deploy never restarts relays in two regions at once and honours `kill_timeout`; during the stage drill the simulator clients (B011) reconnect and resume with no gap in `seq`.
7. Only one deployment per environment runs at a time; a second concurrent run queues or fails with a clear message.
8. Images in the deployed digest are signed and have no critical vulnerabilities per trivy; otherwise the pipeline stops.

## Tests required
- unit: migration-lint table-driven cases; version/semver and digest parsing helpers.
- workflow lint with actionlint and a dry-run test of each script.
- integration (compose): deploy dry run, smoke against compose stack, SLO guard with injected failures.
- gate test: pipeline blocked with missing/failed/stale conformance fixture reports.
- rollback drill executed in stage and recorded in `docs/ops/deployment.md` with measured time.

## Guardrails (MUST / MUST NOT)
- MUST deploy the exact image digest promoted from stage; MUST NOT rebuild for prod.
- MUST keep every migration backward-compatible with the previous release (expand -> migrate -> contract in separate releases) and MUST NOT run destructive contract steps in the same release as the code that stops using the old shape.
- MUST use short-lived OIDC credentials for Fly/registry access; no long-lived deploy tokens in repo secrets beyond the Fly deploy token scoped per environment.
- MUST NOT print secrets in logs; mask all env values; the smoke test uses a dedicated test user and never real customer data.
- MUST require human approval for production and record approver and digest in `deploy-record.json`.
- MUST NOT allow rollback of a database migration automatically; schema fixes are forward-only (rollback note per migration is the manual path).

## Failure modes
- Migration fails halfway -> release command aborts, traffic remains on old version, migration runner's lock released, alert raised.
- Fly API outage -> deploy retried 3 times with backoff, then fails without changing traffic.
- SLO guard cannot read metrics (observability down) -> treat as breach for prod (fail safe: rollback) but only warn in stage.
