## Goal
Keep connections honest after the handshake: run server pings, detect dead peers, drive a small connection state machine, and make every close follow the CT-WS-ENVELOPE close-code table with the right preceding frame.

## In scope
- Per-connection state machine: `awaiting_hello -> authenticating -> active -> draining -> closed` with legal transitions enforced.
- Server `sys.ping` every `ping_ms` (20000) with `p.t` (server monotonic ms), `sys.pong` echo check, answers client `sys.ping` with `sys.pong`; any inbound frame counts as activity.
- Dead-peer detection: when there is no inbound activity for `dead_ms` (50000) the server closes with 1000 and reason `dead_peer`, and counts it in a metric.
- `closeConnection(conn, spec)` helper: sends `sys.error` or `sys.bye` as required, then closes with the CloseCode, removes from registry, idempotent.
- Error-to-close mapping table and a per-connection timer wheel (single shared timer per node, not one timer per socket).
- Ping jitter (+-10 %) to avoid synchronised bursts.

## Out of scope
- Handshake timeout and ticket logic (B038).
- Seq/ack handling and rate limits (B041, B046).
- Client-side reconnection (the real client).

## Build against (no counterpart needed)
The mock client simulator from B011 (scripted fake clients speaking the WS protocol), the in-memory B009 KV/pub-sub implementations, and the frame fixtures in contracts/fixtures/events/; no real client is needed. Time is driven by the fake clock injected through `RelayContext.clock`; the simulator can be told to stop answering pings.

## Interfaces (the only surface other lanes may use)
- TS: `type ConnState = 'awaiting_hello' | 'authenticating' | 'active' | 'draining' | 'closed'`; `interface ConnectionMachine { state: ConnState; transition(to: ConnState): void; touch(): void }`.
- TS: `closeConnection(conn: RelayConnection, spec: { code: number; errorCode?: string; bye?: string; retryAfterS?: number }): void`.
- TS: `export default relayModule: RelayModule` (order 12) registering heartbeat scheduling on `onConnection` and on state `active`.
- Wire: `sys.ping {p:{t:number}}`, `sys.pong {p:{t:number}}`, `sys.bye {p:{reason:string}}`.
- Env: `RELAY_PING_MS` (20000), `RELAY_DEAD_MS` (50000); values are advertised in `welcome.heartbeat`.

## Acceptance criteria
1. A connected idle client receives its first `sys.ping` between 18 s and 22 s (20 s +-10 %) after `welcome` and one every 20 s thereafter.
2. A client that answers every ping stays connected for 10 minutes of fake time; a client that goes silent is closed at 50 s (+-1 s) with no inbound activity, with the close recorded in `relay_closes_total{code}`.
3. A client `sys.ping` gets a `sys.pong` echoing `p.t` within 50 ms and resets the dead timer; non-ping inbound frames also reset it.
4. Calling `closeConnection` twice sends one close; the connection is removed from the registry exactly once and its timers are cleared (no timers left after 1 000 connect/disconnect cycles - leak test).
5. Illegal transitions (`closed -> active`, `active -> authenticating`) throw `IllegalTransitionError` in unit tests.
6. 10 000 simulated connections are served by one shared timer; ping scheduling CPU for 10 000 idle connections stays under 5 % of one core in the benchmark.
7. Each close path emits the matching frame first: 4401/4403/4404/4426/4429 get a `sys.error`; superseded/going-away get `sys.bye`.

## Tests required
- heartbeat.schedule.test.ts: fake clock, jitter bounds.
- heartbeat.dead-peer.test.ts: silence and slow-pong cases.
- connection.state-machine.test.ts: legal/illegal transitions (table-driven).
- connection.close.test.ts: idempotency, frame-then-close order, registry cleanup.
- connection.leak.test.ts: timers and listeners after churn.
- heartbeat.bench.ts: 10 000 connections.

## Guardrails (MUST / MUST NOT)
- Ping/pong MUST NOT be sequenced, buffered or replayed (CT-WS-ENVELOPE); they are written directly to the socket.
- Dead-peer detection MUST be driven by server time only; the client-supplied `p.t` is echoed, never trusted.
- A close MUST be preceded by the correct `sys.error`/`sys.bye` where the table requires it, and the `sys.error` body MUST be a valid CT-ERR problem+json.
- MUST NOT leak timers or listeners; every close path goes through `closeConnection`.
- Heartbeat values advertised in `welcome` MUST equal the values actually enforced.

## Failure modes
- Socket write fails during close -> terminate the socket after 1 s, still clean up state.
- Timer drift under event-loop lag -> a ping may be late but the dead timer uses elapsed time since last activity, so a lagging server does not mass-close healthy clients (grace: skip dead check when loop lag > 5 s).
- Pong with wrong `p.t` -> ignored but counts as activity.
