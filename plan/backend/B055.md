## Goal
Durable, encrypted-at-rest storage and retrieval of per-session ciphertext frame history, served through GET/DELETE /v1/sessions/{id}/history, with retention metadata and no ability to read content.

## In scope
- History writer that receives each sequenced frame from the relay (header fields plus raw ct JSON) and appends it to batched blob objects in S3-compatible storage.
- Index table with exactly the fields the contract allows: seq, id, from, ts, kind-class (event|queue|control), size, kid, blob key.
- GET /v1/sessions/{id}/history?after_seq&limit paginated per CT-PAGE, returning ciphertext frames in seq order.
- DELETE /v1/sessions/{id}/history for host or workspace owner: purge blobs and index, write audit event.
- Retention metadata (expires_at derived from entitlement history_days at session end) for the retention job to act on.
- Blob storage adapter interface with S3/R2 and in-memory implementations.

## Out of scope
- Hot buffer and WS replay: B042.
- Snapshots: B056.
- Retention purge scheduling and downgrade notice: B090.
- Producing ciphertext, signing or any decryption: client side (CT-CRYPTO).
- Entitlement computation: B069.

## Build against (no counterpart needed)
In-memory BlobStore fake and Postgres container; frames come from contracts/fixtures/envelope/ and contracts/fixtures/events/ (encrypted samples) or the B011 simulator. Authorisation via fake membership port.

## Interfaces (the only surface other lanes may use)
- HistoryStore.append(sid: SessionId, frames: StoredFrame[]): Promise<{lastSeq: number}>  // idempotent on (sid, seq)
- StoredFrame = {seq:number, id:'msg_…', from:'mem_…', ts:string, kindClass:'event'|'queue'|'control', size:number, kid:string|null, ct:CtObject|null, p:object|null}
- HistoryStore.read(sid, afterSeq: number, limit: number): Promise<{frames: StoredFrame[], nextAfterSeq: number|null}>
- HistoryStore.purge(sid): Promise<{deleted:number}>; HistoryStore.setExpiry(sid, at: Date)
- BlobStore { put(key: string, body: Uint8Array, opts?): Promise<void>; get(key): Promise<Uint8Array>; delete(keys: string[]): Promise<void> }
- GET /v1/sessions/{id}/history?after_seq=<int>&limit=<1..200>&cursor -> {data: Frame[], next_cursor, has_more}; DELETE /v1/sessions/{id}/history -> 204
- Table history_index(session_id, seq, msg_id, member_id, ts, kind_class, size, kid, blob_key, pk(session_id,seq)); blob key pattern history/{sid}/{seq_start}-{seq_end}.bin

## Acceptance criteria
1. Appending 1 000 frames then GET after_seq=0&limit=200 returns frames 1..200 in order, next_cursor set, and following the cursor 5 times returns all 1 000 with no gap or duplicate.
2. Appending the same (sid, seq) twice stores one row; appending seq 5 when 4 is missing is accepted but read reports a gap-free range only from contiguous data and exposes `from_seq` of earliest retained frame.
3. A viewer, editor and host of the session may GET history; a non-participant gets 404; a share-link guest token (B068) is a viewer and may read only when session policy share_history is true.
4. DELETE as editor returns 403; as host or workspace owner returns 204, subsequent GET returns an empty page, blob store lists zero keys for the session, and one audit event is written.
5. The history_index table has no column for text, paths, or p payload bodies of encrypted kinds; a schema test fails if a column outside the allowed list is added.
6. For hybrid frames only the cleartext p object defined by the contract is persisted alongside ct; for clear-kind frames p is persisted; `presence` frames are never passed to or stored by append.
7. Blob batches are written at most 2 s or 500 frames after the first frame in the batch; a crash between batch flush and index insert is repaired on restart without duplicate index rows.
8. GET returns ct unchanged byte-for-byte compared with what was appended (round trip test over 100 random binary-ish base64url values).

## Guardrails (MUST / MUST NOT)
- MUST treat ct as opaque bytes: never decode, decrypt, truncate or normalise it, and never log it.
- MUST NOT store plaintext message text, paths or branch names; reject (and alert) any frame whose kind is encrypted but carries a non-empty p.
- MUST NOT store ephemeral frames (presence, ping) or sys.* frames.
- Blob object keys MUST NOT contain user-provided strings; only sid and numeric seq.
- Purge MUST delete blobs before index rows so a failed purge can be retried and never leaves unreachable blobs.
- Server-side encryption at rest MUST be enabled on the bucket; documented in README.

## Failure modes
- Blob store put fails -> retry with backoff + jitter (max 5), keep frames in the relay hot buffer, raise a metric/alert; do not ack durability to the relay until stored.
- Blob get fails on read -> 503 with retry_after_s; partial page is never returned.
- Purge partially fails -> response 202-style retry via job; GET during purge returns only frames not yet deleted and the purge is resumable.
