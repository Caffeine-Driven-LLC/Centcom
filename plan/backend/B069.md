## Goal
The plans and entitlements model: database tables, seed data from the contract's default plan table, a pure resolver from subscription state to the entitlement object with rev, and the public plans and entitlements endpoints.

## In scope
- Tables plan, plan_limit, workspace_entitlement (plan, status, period, grace_until, seats add-on, rev) and seed migration with the free/pro/team reference values.
- resolveEntitlements(input): pure function from {plan, status, period, grace_until, addonSeats, now} to the entitlement limits including status behaviour (active, trialing, past_due 7-day grace, canceled until period end, none -> free defaults).
- applySubscriptionState(workspaceId, state): updates workspace_entitlement, increments rev only if the resolved limits/plan/status changed, publishes invalidation on Redis channel `entitlements:invalidate`.
- GET /v1/plans (public) and GET /v1/workspaces/{id}/entitlements (workspaces:read, member+) returning the CT-ENTITLEMENTS object (usage and warnings filled by a UsageReaderPort, empty until B075).
- Free workspace bootstrap: every workspace has a row with plan free and status none.

## Out of scope
- Stripe calls and subscription rows: B070. Webhook ingestion: B072.
- Usage totals, warnings at 80/100: B075/B076.
- Per-request enforcement middleware and 30 s cache: B080.
- Coupons and trials: B079; dunning state machine: B078 (it calls applySubscriptionState).

## Interfaces (the only surface other lanes may use)
- resolveEntitlements(i: ResolveInput): {plan:'free'|'pro'|'team', status:'active'|'trialing'|'past_due'|'canceled'|'none', limits: EntitlementLimits, period: {start:string,end:string}|null, grace_until: string|null}

- EntitlementService.applySubscriptionState(workspaceId, s: SubscriptionState): Promise<{rev:number, changed:boolean}>

- Redis pub/sub channel `entitlements:invalidate` payload {workspace, rev}
- EntitlementLimits keys exactly: relay_access, lan_multiplayer, max_seats, max_session_members, max_concurrent_sessions, max_parallel_agents, history_days, hosted_minutes_month, queue_items_month, audit_log_days, webhooks_max, api_keys_max

## Acceptance criteria
1. resolveEntitlements for pro/active equals the contract Pro column (relay_access true, max_seats 1, max_session_members 4, max_concurrent_sessions 2, max_parallel_agents 8, history_days 7, hosted_minutes_month 6000, audit_log_days 0, webhooks_max 2, api_keys_max 5); team and free columns match likewise; lan_multiplayer is true in all.
2. past_due: limits unchanged and grace_until = past_due_since + 7 days; one second after grace_until the resolver returns the free (none) limits.
3. canceled: limits unchanged until period.end, free limits one millisecond after; none -> free defaults; trialing equals the trial plan's limits.
4. Team with 3 add-on seats resolves max_seats 8; negative or non-integer add-on seats throws a typed error.
5. applySubscriptionState called twice with identical state leaves rev unchanged and publishes no second invalidation; a plan change increments rev by exactly 1 and publishes {workspace, rev}.
6. GET /v1/plans is public (no token), returns all three plans with USD and EUR integer minor-unit Money objects and no floats; GET entitlements by a non-member returns 404, by a member 200 with `rev` and an ETag, and an If-None-Match hit returns 304.
7. Output validates against schemas/entitlements.schema.json and every fixture in contracts/fixtures/entitlements/ round-trips.
8. Unknown plan key in seed config fails startup validation; a limit missing for a plan fails a seed-completeness test.

## Guardrails (MUST / MUST NOT)
- MUST derive limits only from plan_limit rows and add-on seats; MUST NOT hard-code limits in route handlers or read Stripe objects here.
- MUST increment rev only on actual change, in the same transaction as the state write, before publishing invalidation.
- MUST treat `lan_multiplayer` as always true and never gate LAN behaviour server-side.
- Money MUST be integer minor units with ISO-4217 code; USD and EUR only.
- Adding a limit key is a contract change; this lane MUST NOT add keys.

## Failure modes
- Redis publish fails after DB commit -> state stays committed; consumers fall back to the <=30 s cache TTL; failure counted and retried once.
- Unknown plan id in subscription state -> typed error, state not applied, alert metric.
- Entitlements read for a deleted workspace -> 404.
## Notes
Price amounts are product decisions kept in seed-plans.ts config; the contract example shows 1900 USD only as shape.
