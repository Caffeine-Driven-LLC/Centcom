## Goal
Give Centcom staff a small, tightly controlled internal admin API for support: look up users, workspaces and subscriptions (metadata only), revoke access, manage flags and status incidents, with every call audited and no ability to read content or impersonate.

## In scope
- Internal-only Fastify plugin mounted under `/internal/admin/v1` on a separate listener (`ADMIN_API_PORT`) reachable only via the private network; disabled unless `ADMIN_API_ENABLED=true`.
- Staff authentication: access token with scope `admin` AND membership in table `staff_users` with role `support_ro`, `support_rw` or `superadmin`; step-up header `X-Admin-Reason` (10-500 chars) and optional `X-Admin-Ticket` mandatory on every call.
- Read endpoints: `GET /users/{id}` and `GET /users?email=`, `GET /workspaces/{id}` (members, roles, plan, subscription status, entitlements, usage totals), `GET /sessions/{id}` metadata (state, region, member count, timestamps), `GET /staff-audit`.
- Write endpoints (support_rw+): revoke a device or all refresh-token families of a user, disable a user login, end a session (metadata action), resend an invite, call `grantPromotion` (B079), set/delete flags via the B083 service, create/update status incidents via the B086 service.
- Response redaction: emails masked (`a***@d***.com`) for `support_ro`; no ciphertext, history, key material, join tokens, API key secrets, webhook secrets or payment data in any response.
- Audit: every request writes an audit event with `actor_type:'staff'`, reason, ticket, target, outcome; staff audit endpoint lists them.

## Out of scope
- The web UI (B088).
- Metadata search (B089); this lane mounts nothing for it but exposes the staff auth preHandler `requireStaff` it will use.
- Impersonation / acting as a user: explicitly forbidden and not built.
- The public RBAC matrix (B021) and the audit emitter implementation (B036); this lane consumes them.
- Billing mutations beyond promotion grants (Stripe dashboard remains the tool for refunds).

## Interfaces (the only surface other lanes may use)
- Base `/internal/admin/v1`; routes: `GET /users/{id}`, `GET /users?email=`, `GET /workspaces/{id}`, `GET /sessions/{id}`, `POST /users/{id}/revoke-tokens`, `POST /users/{id}/disable`, `POST /sessions/{id}/end`, `POST /invites/{id}/resend`, `POST /workspaces/{id}/promotions`, `PUT /flags/{key}`, `DELETE /flags/{key}`, `POST /incidents`, `POST /incidents/{id}/updates`, `GET /staff-audit`.
- `requireStaff(minRole: 'support_ro'|'support_rw'|'superadmin'): preHandler` exported for B089.
- Types exported from `apps/api/src/modules/admin/types.ts` (request/response DTOs) for the admin console.
- Table `staff_users(user_id PK, role, added_by, added_at, disabled_at)`.
- Config: `ADMIN_API_ENABLED`, `ADMIN_API_PORT`, `ADMIN_ALLOWED_CIDRS`; rate limit 60 requests/min per staff user.

## Acceptance criteria
1. A normal user token (without scope `admin`), a token with scope `admin` but no `staff_users` row, and a disabled staff user each receive 403 `forbidden`; no data is returned.
2. A request without `X-Admin-Reason` (or shorter than 10 chars) returns 422 and writes a denied audit event.
3. Every successful and denied call writes exactly one audit event containing actor, reason, ticket, target id and outcome; there is no code path that returns data without writing the event (test enumerates all routes).
4. `support_ro` gets masked emails and receives 403 on every write route; `support_rw` can write but cannot add staff or change roles; only `superadmin` can.
5. `GET /sessions/{id}` returns only metadata fields (id, workspace, state, region, created_at, ended_at, member_count, host member id); a JSON scan of all responses finds no field named `ct`, `p`, `secret`, `token`, `key_bundle`, or values with prefix `cen_live_`.
6. `POST /users/{id}/revoke-tokens` makes the user's next refresh attempt fail with `token_revoked` and the device sockets close with 4401 within 60 s.
7. The listener refuses connections from outside `ADMIN_ALLOWED_CIDRS` (connection-level test) and the plugin is not registered when disabled (404 on the public listener).
8. More than 60 calls/min from one staff user returns 429 with `Retry-After`.

## Tests required
- authz matrix: roles x routes x token types, including expired and wrong-audience tokens.
- audit completeness test enumerating all registered routes.
- redaction test: JSON scan with forbidden field/value patterns on every read route.
- integration: revoke-tokens then refresh fails; flag set then `GET /v1/flags` reflects it.
- failure-path: dependency service (flags/status) down -> 502-class problem+json, audit event with outcome `error`.
- negative: attempts to call any route with a user-supplied `workspace` header or impersonation parameter are rejected.

## Guardrails (MUST / MUST NOT)
- MUST NOT implement impersonation, user-token minting, or any way to read session content, history, snapshots, keys, or message text.
- MUST require a reason on every call and MUST audit reads as well as writes (support access to PII is itself sensitive).
- MUST be unreachable from the public listener and the public load balancer; never mounted on the same port as `/v1`.
- MUST NOT return secrets (API keys, webhook secrets, refresh tokens, Stripe ids beyond a masked tail) in any response.
- MUST NOT allow staff to modify their own role or to act on their own staff record.
- MUST fail closed when the audit write fails: the action is rolled back and 503 returned.

## Failure modes
- Audit store unavailable -> all admin calls fail with 503; no un-audited access.
- Staff user removed mid-session -> next request denied (staff table checked each request, cache <= 5 s).
- Target not found -> 404 with audit outcome `error`.
