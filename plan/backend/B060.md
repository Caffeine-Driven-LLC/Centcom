## Goal
Route approval requests and decisions between the right approvers, enforce delegation and expiry, and notify the notification dispatcher, using only the cleartext routing metadata.

## In scope
- Handler for approval.request and approval.decision hybrid frames using p fields approval_id, agent_id, risk, expires_at, approver (host|owner|any_editor), decision (approve|deny), scope (once|session|always).
- Authorisation of deciders: host always; delegated approvers only for requests whose p.approver allows them (owner = workspace owner/admin member in the session, any_editor = any editor).
- Pending-approval store with expiry: at expires_at the relay sequences an approval.decision {decision:'deny', scope:'once'} from the server (timeout), once.
- First decision wins; later decisions for the same approval_id are ignored with sys.error `forbidden` or a no-op for exact duplicates.
- Mute and kick of a requester cancel their pending approvals; agent.exit cancels pending approvals for that agent.
- Event to the notification dispatcher (category approval_needed, params agent/session/risk) through a NotifyPort, and sys.notice-free (no display text).

## Out of scope
- Notification delivery: B063+.
- The permission engine that decides what needs approval (client).
- Agent registry: B057; control commands such as delegating the host: B051.
- Storing summary/command/cwd (inside ct, never seen).

## Interfaces (the only surface other lanes may use)
- ApprovalRouter.onRequest(ctx, frame): Promise<Result>; onDecision(ctx, frame): Promise<Result>; sweep(now: Date): Promise<number>
- PendingApproval = {approvalId:'apr_…', agentId, requester:'mem_…', risk:'low'|'medium'|'high', approver:'host'|'owner'|'any_editor', expiresAt:string, requestSeq:number}
- NotifyPort.approvalNeeded(sid, a: {approvalId, agentId, risk}): void
- Redis hash approval:{sid}:{apr} with TTL = expires_at + 60 s
- Metric: relay_approvals_pending, relay_approval_timeouts_total, relay_approval_decision_latency_ms

## Acceptance criteria
1. approval.request from the host/owner of the agent is sequenced and stored; NotifyPort.approvalNeeded is called exactly once per approval_id even if the frame is retried.
2. Decision by an editor when approver='host' is rejected `forbidden` and audited; with approver='any_editor' an editor decision is accepted; with 'owner' only owner/admin members of the workspace are accepted.
3. Viewers never decide; a requester cannot approve their own request unless they are the host.
4. Two decisions race (approve and deny) -> the one with the lower seq wins, the other gets a no-op error and no second state change.
5. expires_at in the past on a request is rejected `invalid_frame`; a request with expires_at more than 24 h ahead is clamped by rejecting `invalid_frame`; at expires_at (fake clock) one server deny decision is sequenced exactly once even with two sweepers.
6. agent.exit or kick of the requester removes pending approvals without emitting a timeout deny.
7. Decision scope 'always' or 'session' is forwarded as-is; the relay stores no memory of scopes and does not auto-answer future requests.
8. Pending approvals survive relay restart (Redis restore) and are re-armed with their original expires_at.

## Guardrails (MUST / MUST NOT)
- MUST NOT auto-approve anything; the only server-originated decision is deny on expiry.
- MUST authorise deciders from live membership; the request's `approver` field narrows who may decide but never widens beyond role rules in CT-RBAC.
- MUST NOT read summary, command or cwd from ct, and MUST NOT include them in notifications.
- Expiry deny MUST be sequenced exactly once (guard with SET NX on the approval key).
- Notification params MUST contain ids and enums only (agent, session, risk).

## Failure modes
- Sweeper lag -> a late decision after expires_at but before the sweep is rejected as expired; sweeper emits deny afterwards only if no decision exists.
- NotifyPort failure -> approval still routed; notification retried by dispatcher outbox; failure counted.
- Host disconnected when request arrives -> request is kept; notification is sent; on expiry the deny is still emitted.
