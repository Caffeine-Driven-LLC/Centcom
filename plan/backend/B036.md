## Goal
Provide the audit event emitter library every state-changing path uses, writing append-only, privacy-minimal audit rows that the audit API (CT-API-AUDIT) serves.

## In scope
- `AuditEmitter` with transactional `emit(trx, event)` and best-effort `emitDetached(event)` (bounded queue) for paths with no DB transaction such as the relay.
- Migration for `audit_events` (append-only: update/delete blocked by trigger, retention purge only through a SECURITY DEFINER function).
- Typed action vocabulary and a metadata allowlist/size limit; redaction of secret-looking values.
- Fastify helper `request.audit(actionInput)` that fills actor, request id and workspace from the request context.
- Metrics `audit_events_written_total`, `audit_events_dropped_total`, `audit_emit_latency_ms`.

## Out of scope
- The read/export API for audit events (CT-API-AUDIT endpoints, later lane).
- Retention job (B090).
- Webhook delivery (later lane).

## Build against (no counterpart needed)
Postgres via the B010 harness; the structured logger from B005 for capture; no HTTP layer needed - unit and integration tests call the emitter directly and via a tiny Fastify instance.

## Deliverables
- `packages/core/src/audit/`
- `packages/db/migrations/0036_audit_events.sql`

## Interfaces (the only surface other lanes may use)
- TS: `interface AuditEvent { workspaceId: string | null; actor: { type: 'user' | 'api_key' | 'system' | 'device'; id: string }; action: AuditAction; target?: { type: string; id: string }; outcome: 'success' | 'denied' | 'failed'; requestId?: string; meta?: Record<string, string | number | boolean | null> }`
- TS: `interface AuditEmitter { emit(trx: Trx, e: AuditEvent): Promise<string>; emitDetached(e: AuditEvent): void; flush(timeoutMs: number): Promise<void> }` (returns the `aud_` id).
- TS: `AUDIT_ACTIONS` const list, e.g. `workspace.created`, `workspace.deleted`, `member.role_changed`, `member.removed`, `ownership.transferred`, `invite.created`, `invite.accepted`, `invite.revoked`, `project.created`, `settings.updated`, `account.deletion_requested`, `account.export_requested`, `control.kick`, `control.denied`; extendable via `defineAuditActions`.
- DB: `audit_events(id aud_, workspace_id null, actor_type, actor_id, action, target_type, target_id, outcome, request_id, meta jsonb, created_at)` with index `(workspace_id, created_at desc, id)`.
- Fastify decorator `request.audit`.

## Acceptance criteria
1. `emit` inside a transaction that rolls back leaves no audit row; inside one that commits leaves exactly one row with a unique `aud_` ULID.
2. UPDATE or DELETE on `audit_events` by the application DB role fails with a permission or trigger error.
3. `meta` is limited to 2 KiB serialised; larger meta throws before the write; keys outside a per-action allowlist are dropped; string values longer than 200 chars are rejected; values matching `cen_(live|test)_`, `eyJ` JWT shape or `sha256:` secrets are replaced with `[redacted]`.
4. `emitDetached` never throws, queues at most 1 000 events, writes in batches of up to 100 every 250 ms, and on overflow drops the oldest and increments `audit_events_dropped_total`.
5. `flush(5000)` on shutdown persists all queued events when the DB is up.
6. `emit` p95 < 5 ms on the Postgres test container; a listing query by `(workspace_id, created_at desc)` for 100 000 rows uses the index (EXPLAIN test).

## Tests required
- audit.emit.test.ts: commit/rollback, ids, ordering.
- audit.immutability.test.ts: UPDATE/DELETE blocked, purge function works.
- audit.meta-redaction.test.ts: allowlist, size, secret patterns (property test).
- audit.detached.test.ts: batching, overflow, flush.
- audit.request-helper.test.ts: actor, request id, workspace filled from context.

## Guardrails (MUST / MUST NOT)
- Audit rows MUST NOT contain message text, paths, branch names, tokens, keys, ciphertext, IP addresses or email addresses; `meta` holds ids and enums only.
- Writes MUST be append-only; no code path may UPDATE or DELETE audit rows except the retention function.
- State-changing REST handlers MUST use `emit(trx, ...)` in the same transaction as the change so audit and state cannot diverge (CT-API-AUDIT cross-cutting rule).
- Denied privileged actions MUST also be audited with outcome `denied` (CT-RBAC rule 6).
- `emitDetached` loss MUST be visible as a metric and an error log; never silent.

## Failure modes
- DB down during `emitDetached` flush -> retry with backoff + jitter, keep events in the bounded queue, drop oldest on overflow with metric.
- Unknown action string -> TypeScript error at compile time; at runtime (untyped caller) throws `InvalidAuditActionError`.
- Duplicate emit due to retry -> allowed; consumers dedupe on `id`; callers needing exactly-once pass through `emit` in a transaction.
