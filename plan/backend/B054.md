## Goal
The REST surface for sessions: list, create, get, patch, end, join-token, claim-host and members, authorised by scope and role and wired to the lifecycle service and relay tickets.

## In scope
- Routes GET/POST /v1/sessions, GET/PATCH /v1/sessions/{id}, POST /v1/sessions/{id}/end, POST /v1/sessions/{id}/join-token, POST /v1/sessions/{id}/claim-host, GET /v1/sessions/{id}/members.
- Scope and role checks per CT-API-SESSIONS table through the B021 RBAC engine (sessions:read, sessions:write, sessions:host; host, participant, workspace admin+).
- Join-token: mint a 60 s single-use JWT (aud centcom-relay, claims sid, mid, role, dev, caps, jti) via the B017 token service and return the region hint.
- Member records with slot assignment hand-off (slot from B031), role, device public keys (X25519, Ed25519) and join order.
- Idempotency-Key acceptance on POST create, ETag/If-Match on PATCH, pagination via B025, audit events for every state-changing call.
- claim-host: workspace admin+ may take host when the host is absent; calls SessionService and emits control.host_changed through the relay notifier.

## Out of scope
- Lifecycle state machine and expiry: B053.
- History, snapshot and share-link routes: B055, B056, B068.
- Relay-side ticket verification and handshake: B038.
- Slot assignment algorithm: B031.
- Entitlement computation: B069/B080 (consumed through a port).

## Acceptance criteria
1. POST /v1/sessions without a sessions:host scope returns 403 `forbidden`; with an API key (machine principal) join-token returns 403 and create is allowed only if the key has the scope and a member exists (keys never become members).
2. Create on a workspace whose entitlements have relay_access=false returns a 403 or 429 problem+json whose code is from the entitlement_* family and no row exists afterwards.
3. Sending the same Idempotency-Key and body twice returns identical 201 bodies and header Idempotency-Replayed: true on the second; a different body with the same key returns 409 `idempotency_conflict`.
4. join-token returns a JWT that verifies with the JWKS key, has aud centcom-relay, exp - iat = 60 s, a fresh jti each call, and claims sid/mid/role/dev/caps; the same user on an ended session gets 404/410 with no ticket.
5. A viewer or non-participant calling join-token for a session they may not join gets 403; a guest workspace role gets role 'viewer' in the ticket.
6. PATCH with a stale If-Match returns 412 `precondition_failed`; PATCH by an editor returns 403; name of 81 chars returns 422 with errors[0].pointer '/name'.
7. claim-host by a workspace member (non-admin) returns 403; by an admin when the host is connected returns 409; when the host is absent it returns 200, new host's role is host, old host becomes editor, and one audit event is written.
8. GET /v1/sessions/{id}/members lists device public keys only for the caller's own session, sorted by join order, and a non-participant gets 404 (not 403) to avoid leaking existence.
9. List responses honour limit 1..200 (default 50) and reject limit 201 with 422; each response carries RateLimit-* headers and X-Request-Id.

## Guardrails (MUST / MUST NOT)
- MUST store the ticket jti with a 60 s TTL so the relay can reject reuse; MUST NOT log the ticket or put it in a URL.
- MUST NOT mint tickets for API-key principals, revoked devices, removed members or ended/expired sessions.
- MUST return 404 for sessions the caller cannot see; existence is not disclosed to non-members.
- MUST authorise from live membership and workspace role in the DB, never from JWT claims alone.
- Device public keys in members responses MUST be exactly the registered keys; never include private or sealed material.
- claim-host MUST NOT succeed while the host holds a live relay connection.

## Failure modes
- Lifecycle service error SessionStateError -> 409 problem+json with a stable code, no partial change.
- Token signing key unavailable -> 503 with retry_after_s, no ticket issued, alert metric incremented.
- Relay notifier down during claim-host -> change committed, notification queued via outbox, response still 200.
