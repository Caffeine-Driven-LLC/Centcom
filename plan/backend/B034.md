## Goal
Implement workspace settings and policies: read and update the workspace-level defaults (auto-approve level, history sharing, retention override) with ETag concurrency, plus the PATCH /workspaces extension that accepts a `settings` object.

## In scope
- GET /v1/workspaces/{id}/settings (member+, ETag) and PATCH /v1/workspaces/{id}/settings (admin+, `If-Match` required).
- Validation and defaults: `auto_approve` in {`ask`,`trusted`,`everyone`} (default `ask`), `share_history` boolean (default true), retention override integer days bounded by the plan's `history_days`.
- Registration of a PATCH extension on /v1/workspaces/{id} (hook from B027) so a `settings` object there uses the same code path.
- Publishing `workspace.settings_changed` on Redis channel `centcom:workspace-events` for the relay and retention job.
- Audit events for every change.

## Out of scope
- Applying policy inside sessions (`control.policy` handling is B051; queue auto-approval is B052).
- The retention purge job (B090).
- Entitlement computation (B069); only the cap is read through its reader interface.

## Build against (no counterpart needed)
Fastify app built with the B006 error handler and the B010 test harness (Postgres/Redis containers, factories); routes are called with app.inject() and a test access token; authorisation goes through the B021 RBAC engine; no client is involved. The entitlements reader is a stub returning history_days 7 or 30 from contracts/fixtures/entitlements/.

## Interfaces (the only surface other lanes may use)
- HTTP: GET and PATCH /v1/workspaces/{id}/settings.
- TS: `interface WorkspaceSettings { auto_approve: 'ask' | 'trusted' | 'everyone'; share_history: boolean; retention_days: number | null }`
- TS: `interface WorkspaceSettingsService { get(wspId: string): Promise<{ settings: WorkspaceSettings; etag: string }>; update(wspId: string, patch: Partial<WorkspaceSettings>, ifMatch: string, actor: Actor): Promise<{ settings: WorkspaceSettings; etag: string }>; }`
- Redis channel `centcom:workspace-events` payload `{type: 'workspace.settings_changed', wsp, changed: string[], at}`.
- DB: `workspace_settings(workspace_id pk, auto_approve text, share_history bool, retention_days int null, version int, updated_at)`.

## Acceptance criteria
1. A workspace with no row returns the defaults (`ask`, true, null) from GET with an ETag; the first PATCH creates the row.
2. PATCH by `member` returns 403, by `admin` or `owner` returns 200; without `If-Match` returns a 400-class error; stale `If-Match` returns 412 `precondition_failed`.
3. `auto_approve: 'always'` returns 422 with `errors[0].pointer == '/auto_approve'`; unknown extra fields are ignored and not stored.
4. A `retention_days` larger than the workspace's `history_days` entitlement returns 422; `null` clears the override.
5. A successful PATCH publishes exactly one `workspace.settings_changed` message listing only the changed keys; the audit event contains the key names and old/new enum values but no free text.
6. PATCH /v1/workspaces/{id} with `{settings:{share_history:false}}` yields the same stored result as PATCH on /settings, with a single ETag update.
7. Two concurrent PATCHes with the same ETag: one 200, one 412.

## Guardrails (MUST / MUST NOT)
- The enum values for `auto_approve` MUST be exactly those in CT-WS-QUEUE rule 3 / `control.policy`; do not add values.
- Settings are workspace defaults only; the server MUST NOT push them into a live session by itself - the host client applies them via `control.policy`.
- Retention override MUST NOT exceed the plan's `history_days`; the retention job must never be able to keep data longer than the entitlement.
- Non-members MUST get 404; the PATCH MUST be atomic with the version bump.

## Failure modes
- Entitlements reader unavailable -> PATCH of `retention_days` returns 503 retryable; other fields still work.
- Pub/sub publish failure -> logged and retried 3 times; the stored value is authoritative.
- Row missing on PATCH race -> upsert inside the transaction.
