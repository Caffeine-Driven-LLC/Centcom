## Goal
Ship the account commands users type first: `centcom login`, `logout`, `whoami` and `devices`, with clear output and correct exit codes, on top of the auth client.

## In scope
- `centcom login [--no-browser] [--device-name <name>] [--api-key-stdin] [--json]`: starts the device flow, prints `user_code` as ABCD-EFGH and the verification URL, tries to open `verification_uri_complete` in the default browser (spawn without a shell), waits, then prints the signed-in user and plan.
- `centcom logout [--revoke-device]`: revokes the refresh token and clears the keychain; with `--revoke-device` also calls DELETE /v1/devices/{current dev}.
- `centcom whoami [--json]`: GET /v1/me; prints user, display name, plan, active workspace and entitlement revision.
- `centcom devices list [--json]` (GET /v1/devices) and `centcom devices revoke <dev_id> [--yes]` (DELETE /v1/devices/{id}); revoking the current device is treated as logout and warned about.
- Message table entries for all user-facing text and exit codes: 0 ok, 1 failure, 2 not logged in / auth required.

## Out of scope
- Device flow, keychain and refresh logic: lane C052. HTTP retry/pagination: lane C051.
- Workspace, invite and billing commands: other lanes (C064, C087).
- TUI login screens and onboarding: lane C048.
- Registering commands in the CLI router beyond exporting `registerAccountCommands(program)`: lane owning apps/cli entry.

## Build against (no counterpart needed)
the mock backend (lane C007): REST from OpenAPI plus the WebSocket relay simulator, started in-process with `startMockBackend()` from @centcom/testkit; no real backend is needed. Commands are run in-process with an injected mock HTTP base URL, in-memory TokenStore and a fake browser opener; the pty harness (lane C008) covers the interactive output.

- `--json` output shapes: whoami `{user:{id,display_name,email},plan,workspace:{id,name}|null,entitlement_rev}`; devices `{devices:[{id,name,platform,last_seen,fingerprint,current}]}`

## Acceptance criteria
1. `centcom login --no-browser` against the mock prints the code in the form `ABCD-EFGH`, the verification URL, never calls openBrowser, and exits 0 after approval; the printed user_code matches `^[A-HJ-KM-NP-Z2-9]{4}-[A-HJ-KM-NP-Z2-9]{4}$`.
2. Without `--no-browser` openBrowser is called once with `verification_uri_complete`; if it returns false the command still succeeds and prints the URL.
3. Login denied -> exit 1 with the message-table text for access_denied; expired -> exit 1 with a rerun hint; Ctrl-C (SIGINT) during polling aborts within 1 s, exits 130-style 1, and leaves the keychain unchanged.
4. `whoami` when not logged in exits 2 with a `centcom login` hint and makes no network call; when logged in prints the plan from GET /v1/me, and `--json` output validates against the shape above.
5. `devices list` marks the current device (matching the `dev` claim) and prints fingerprint, platform and last seen; empty list prints a friendly line and exits 0.
6. `devices revoke dev_X` without `--yes` on a TTY asks for confirmation; non-TTY without `--yes` exits 1 without calling DELETE; revoking the current device clears local tokens and exits 0 with a logged-out message.
7. `logout` while the mock is down clears the keychain, prints that server-side revocation was skipped, and exits 0.
8. No command prints a token, device_code, refresh token or API key in any mode, including `--json` and error output.
9. `login --api-key-stdin` reads one line from stdin, validates the `cen_(live|test)_[A-Za-z0-9]{32}` format locally, stores it in the keychain and then whoami works; a malformed key exits 1 before any network call.

## Tests required
- account/login.test.ts: device-flow timelines (approve, deny, expire, abort) with fake clock and opener.
- account/whoami.test.ts: logged in, logged out, plan variants free/pro/team, --json schema.
- account/devices.test.ts: list, revoke other, revoke current, confirmation prompt matrix (TTY/non-TTY, --yes).
- account/logout.test.ts: online and offline paths, --revoke-device.
- account/pty.test.ts: end-to-end rendering in the pty harness including NO_COLOR.
- account/redaction.test.ts: snapshot of all stdout/stderr never contains token-shaped strings.

## Guardrails (MUST / MUST NOT)
- MUST spawn the browser opener with an argument array (xdg-open / open / `cmd /c start`), never through a shell string; the URL comes from the server response and MUST be checked to be https (or the configured dev base URL) before opening.
- MUST NOT print or log secrets; the only credential-like value ever shown is the short `user_code`.
- MUST ask for confirmation before revoking a device unless `--yes`; MUST NOT prompt when stdin is not a TTY (fail instead).
- MUST keep all user-facing strings in messages.ts (one table), not inline.
- MUST work with no network for `logout` and for the not-logged-in branch of `whoami`.

## Failure modes
- Keychain unavailable at login -> command completes in memory only, prints the C052 remediation text and exits 0 with a warning that the login will not persist.
- GET /v1/me returns 401 device_revoked -> local tokens cleared, exit 2 with a re-login hint.
- Server unreachable on whoami/devices -> exit 1 with the offline message and request_id absent; no stack trace in non-debug mode.
