## Goal
A small typed in-process event bus, plus the catalogue of internal agent-runtime events, that decouples the runner, state machine, permissions, locks and the session layer without global state.

## In scope
- Generic `EventBus<M>` where `M` maps event names to payload types: `on`, `once`, `off`, `emit`, `stream` (async iterator), `listenerCount`; synchronous in-order dispatch to listeners registered at emit time.
- Re-entrancy rule: an `emit` made from inside a handler is queued and dispatched after the current dispatch finishes (FIFO), so handlers never observe nested delivery; max queue depth 10 000 then `BusOverflow` is reported to `onError` and the event dropped.
- Error isolation: a throwing or rejecting handler never stops other handlers; errors go to the injected `onError(err, eventName)`; async handlers are not awaited by `emit` (use `stream` for backpressure-aware consumers).
- `stream(names, { buffer = 1000, overflow = 'drop-oldest' })` returns an `AsyncIterable` with a bounded buffer and `return()` that unsubscribes.
- `AgentEventMap`: the catalogue of internal events (names use `domain:verb`, deliberately different from wire kinds): `agent:started`, `agent:prompt`, `agent:message_delta`, `agent:message_done`, `agent:tool_requested`, `agent:tool_result`, `agent:approval_needed`, `agent:approval_resolved`, `agent:state_changed`, `agent:context`, `agent:compaction`, `agent:exited`, `worktree:created`, `worktree:removed`, `lock:changed`, `lock:conflict`, `subagent:spawned`, `subagent:finished`; each payload typed with `agent_id` (`agt_`) and ids from `@centcom/protocol`.
- `createBus<M>(opts: { onError; maxListeners = 100 })` factory; no module-level singleton.

## Out of scope
- Emitting these events: runner (C013), state machine (C014), permissions (C015), locks (C018), sub-agents (C024).
- Converting internal events to wire frames: session layer lanes.
- Cross-process delivery (IPC): runner daemon in C013.

## Interfaces (the only surface other lanes may use)
- `interface EventBus<M extends Record<string, unknown>> { on<K extends keyof M>(k: K, h: (p: M[K]) => void | Promise<void>): Unsubscribe; once<K extends keyof M>(k: K, h: (p: M[K]) => void): Unsubscribe; emit<K extends keyof M>(k: K, p: M[K]): void; stream<K extends keyof M>(ks: readonly K[], o?: { buffer?: number; overflow?: 'drop-oldest' | 'drop-newest' }): AsyncIterable<{ k: K; p: M[K] }>; listenerCount(k?: keyof M): number }`
- `createBus<M>(o: { onError: (e: unknown, k: string) => void; maxListeners?: number }): EventBus<M>`
- `AgentEventMap` and `type AgentBus = EventBus<AgentEventMap>` exported from `@centcom/agent/events`.
- Payload example: `'agent:state_changed': { agent_id: AgentId; state: StateName; since: string }`; `'agent:approval_needed': { agent_id: AgentId; approval_id: ApprovalId; risk: 'low'|'medium'|'high'; expires_at: string }`.

## Acceptance criteria
1. Handlers run in registration order; a handler registered during dispatch of event X is not called for that same X emit.
2. Emitting `b` from inside the handler of `a` delivers `b` only after all handlers of `a` have returned (ordering asserted with a log array).
3. A handler that throws leaves later handlers running and calls `onError` exactly once with the event name; an async handler rejection does the same without unhandled-rejection warnings.
4. `stream` with buffer 3 and drop-oldest, fed 10 events with a stalled consumer, yields the last 3 events; memory stays bounded (no buffer above 3 entries).
5. Unsubscribe is idempotent; after `return()` on a stream `listenerCount` is 0; adding the 101st listener to one event calls `onError` with `MaxListeners` but still registers it.
6. Dispatch cost: 1,000,000 emits to 3 handlers complete in < 1 s on CI.
7. Type test (tsd/`expectTypeOf`): `emit('agent:exited', {})` fails to compile when the payload type requires `agent_id`.

## Guardrails (MUST / MUST NOT)
- MUST NOT use module-level state or a default global bus; each runner owns its bus instance.
- MUST keep every queue and buffer bounded (10 000 emit queue, 1000 stream buffer by default).
- MUST NOT put message text, file contents, paths or branch names into events meant for the wire path; internal events may carry them for local UI but the wire-bound ones (`agent:state_changed`, `agent:approval_needed`) carry ids and enums only, and a lint comment in the catalogue marks which payload fields are wire-safe.
- Handler errors MUST NOT be swallowed silently: always reach `onError`.

## Failure modes
- Queue overflow -> event dropped, `onError(BusOverflow)` once per 1000 drops, bus continues.
- Listener leak -> `MaxListeners` warning via `onError`; no automatic removal.
- Emit after all listeners removed -> no-op.
## Notes
Event names are internal and not part of any contract. If the catalogue grows beyond ~25 events consider splitting per area; keep names stable because C013/C014/C015/C018/C024 depend on them.
