## Goal
Stopping an agent works the same way for every engine: one normalised interrupt that ends the current turn promptly, cancels pending approvals, cleans up the engine's process tree, emits the state transitions and leaves the agent idle with partial output kept.

## In scope
- `interrupt(agentId, opts)` calls `AgentEngine.interrupt(agentId)` (lane C101) and tracks the result; engines declare how through capability `interrupt`.
- Claude Code path: SIGINT to the `claude` process (ends the current turn; when `system/init.capabilities` advertises an interrupt receipt such as `interrupt_receipt_v1` wait for it), grace 3 s, then SIGTERM, then SIGKILL at 8 s, escalating to the whole process group.
- Codex path: protocol cancel (app-server `turn/interrupt` for the active turn); if the app-server does not acknowledge within 3 s, or in `exec --json` fallback mode, use the same signal ladder.
- Pending approvals for the agent resolve as `deny` with reason `interrupted` through the permission engine (lane C015) and the prompt UI (lane C038) receives a close event; any approval request arriving after the interrupt for the old turn is auto-denied by turn id.
- State transitions: emit `agent.interrupted` then drive the agent to `idle` through lane C014; partial assistant output is kept and flagged `interrupted: true`; the next prompt continues the same engine session.
- Process-tree cleanup: kill the engine's whole process group (including tool children and MCP servers it started and Centcom's own approval-bridge helper), never any pid not registered by the runner; Windows uses `taskkill /T`.
- Double-Ctrl behaviour: first `ctrl+c` during a turn = soft interrupt; second within 1 s = hard (SIGKILL ladder immediately) and exit 130; idle `ctrl+c` prints `Press ctrl+c again to exit`, second within 2 s exits. Timeouts: per-turn `--timeout`/`agent.turnTimeoutS` calls `interrupt(reason:'timeout')`.

## Out of scope
- Key binding registration (lane C045); this lane exposes action ids `agent.interrupt` and `app.interrupt_or_quit`.
- Engine adapter internals and the wire framing of the interrupt (lanes C102, C103); this lane calls the interface and owns the fallback ladder.
- Rendering of the interrupted state (lanes C036, C046) and cancelling command-post queue items (session lanes).
- Persisting the interrupted turn (lane C026 records normalised events already).

## Interfaces (the only surface other lanes may use)
- `interface InterruptController { interrupt(agentId: string, opts?: {mode?: 'soft'|'hard'; reason?: 'user'|'signal'|'timeout'|'shutdown'}): Promise<InterruptResult>; onSignal(proc: NodeJS.Process): () => void }`
- `type InterruptResult = {agentId: string; method: 'protocol'|'sigint'|'none'; stoppedStream: boolean; cancelledApprovals: number; terminated: {pid: number; signal: 'SIGINT'|'SIGTERM'|'SIGKILL'}[]; durationMs: number}`
- `createInterruptController(deps: {engines: EngineRegistry; procs: ProcessRegistry; permissions: PermissionEngine; states: AgentStateMachine; bus: EventBus; clock: Clock; log: Logger}): InterruptController`
- Bus event `agent.interrupted` ({agent_id, reason, hard, method}); action ids `agent.interrupt` (default `esc`), `app.interrupt_or_quit` (default `ctrl+c`); config `agent.turnTimeoutS`, `interrupt.graceMs` (3000).

## Acceptance criteria
1. After `interrupt()` no further normalised `text.delta` events for that agent are delivered after 500 ms (fake clock); a Claude Code fake CLI that exits on SIGINT receives exactly one SIGINT and no further signal.
2. A fake CLI that ignores SIGINT gets SIGTERM at 3 s and SIGKILL at 8 s (+/-100 ms fake clock); `hard` mode skips the grace and sends SIGKILL immediately.
3. A grandchild spawned by the fake CLI does not survive the interrupt (checked with `ps` in the Linux CI job); only pids registered by the runner are ever signalled (test asserts the kill list).
4. With the Codex stub acknowledging `turn/interrupt` within 3 s, no signal is sent and `method:'protocol'`; when unacknowledged the ladder runs and `method:'sigint'`.
5. With 2 pending approvals both resolve as `deny` reason `interrupted`, the prompt UI gets 2 close events, and an `approval.requested` for the cancelled turn arriving 100 ms later is auto-denied.
6. After interrupt the state machine is at `idle` (state name from CT-STATE-MAP), `agent.interrupted` fired once, the partial message is flagged `interrupted: true`, and the next prompt starts a normal turn in the same engine session (resume option unchanged).
7. Second `ctrl+c` within 1 s runs the hard ladder and exits with code 130 after restoring the terminal; idle `ctrl+c` twice 3 s apart does not exit.
8. Concurrent interrupts for one agent coalesce into one ladder; interrupting an idle agent returns `stoppedStream:false` without error.

## Guardrails (MUST / MUST NOT)
- MUST kill the whole process group, never signal a pid the runner did not register, never kill by name.
- MUST NOT leave an approval open after an interrupt; a late keypress must not approve an action of a cancelled turn.
- MUST be idempotent and re-entrant; MUST NOT call `process.exit` in the library (entrypoint maps exit 130 per lane C050's table).
- MUST restore the terminal before exit on hard interrupt, and MUST NOT depend on a capability the engine did not advertise (feature-detect `interrupt`, else signals only).

## Failure modes
- SIGKILL fails -> warn with the pid, detach, set the agent `idle` locally, discard later events of that turn by turn id.
- Engine adapter ignores `interrupt()` for more than 8 s -> same as above and log at warn; the engine's own error text is shown verbatim.
- Interrupt during a git operation of the worktree manager -> let it finish if within 2 s else kill and remove a stale `index.lock` owned by the killed pid.
## Notes
The 3 s/8 s ladder replaces the earlier 2 s/5 s tool-process ladder because the target is now the CLI process itself. Normalised event and method names (`interrupt`, `turn.done`) must match lane C101.
