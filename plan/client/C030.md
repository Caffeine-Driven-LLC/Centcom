## Goal
Pressing esc (or sending SIGINT) stops the running turn promptly and predictably: streaming ends, running tools are terminated in escalating steps, pending approvals are cancelled, and the session is left in a clean `idle` state with the partial output kept.

## In scope
- `interrupt(agentId, opts)` on top of the lane C013 runner's AbortController: soft interrupt aborts the SDK query and stops streaming within 500 ms.
- Child process escalation for tool processes: SIGINT to the process group, SIGTERM after 2 s, SIGKILL after 5 s; Windows uses taskkill /T.
- Pending permission requests for the agent resolve as denied-by-cancel (tool result status `canceled`), without leaving an approval prompt open.
- Cascade to sub-agents spawned by the agent (lane C024) and to background tasks started in the turn, each with the same ladder.
- Terminal-level semantics: first `ctrl+c` while a turn runs = soft interrupt; second `ctrl+c` within 1 s = hard (skip straight to SIGKILL ladder) and then exit; `ctrl+c` while idle asks `Press ctrl+c again to exit` once, a second press within 2 s exits.
- The partial assistant message is kept in the transcript, flagged `interrupted: true`, and the next prompt may continue from it.

## Out of scope
- Key binding registration and remapping (lane C045); this lane exposes the action id `agent.interrupt` and handlers only.
- Rendering of the interrupted state in the transcript (lane C036) and mascot reaction (lane C046).
- Cancelling queue items in a command post (session/queue lanes); this lane emits a bus event they can map to `queue.done` outcome.
- Persisting the interrupted turn (lane C026 records bus events already).

## Interfaces (the only surface other lanes may use)
- `interface InterruptController { interrupt(agentId: string, opts?: {mode?: 'soft'|'hard'; reason?: 'user'|'signal'|'timeout'|'shutdown'}): Promise<InterruptResult>; onSignal(proc: NodeJS.Process): () => void }`
- `type InterruptResult = {agentId: string; stoppedStream: boolean; cancelledApprovals: number; terminated: {pid: number; signal: 'SIGINT'|'SIGTERM'|'SIGKILL'}[]; durationMs: number}`
- `createInterruptController(deps: {runner: AgentRunner; procs: ProcessRegistry; permissions: PermissionEngine; bus: EventBus; clock: Clock; log: Logger}): InterruptController`
- Bus events: `agent.interrupted` ({agent_id, reason, hard}); action id `agent.interrupt` (default `esc`), `app.interrupt_or_quit` (default `ctrl+c`).

## Acceptance criteria
1. After `interrupt()`, no further `message.assistant.delta`-class bus events for that agent are emitted after 500 ms, measured with the fake clock.
2. A tool process that ignores SIGINT receives SIGTERM at 2 s and SIGKILL at 5 s (+/-100 ms with the fake clock); one that exits on SIGINT is not signalled again.
3. Process-group kill: a child that spawned a grandchild leaves no surviving grandchild (checked with `ps` in the Linux CI job).
4. With 2 pending approvals, both resolve with status `canceled` and the approval UI receives close events; no approval remains registered.
5. Hard interrupt (second ctrl+c within 1 s) skips the 2 s wait and runs SIGKILL immediately, then the process exits with code 130.
6. After interrupt the agent state machine (lane C014) is back at `idle` and the next user prompt starts a normal turn in the same session.
7. Idle `ctrl+c` prints the exit hint once; two idle presses 3 s apart do not exit.
8. Interrupting an already-idle agent returns `stoppedStream: false` without error.

- interrupt/cascade.test.ts: sub-agent and background-task cancellation.

## Guardrails (MUST / MUST NOT)
- MUST kill the whole process group, not only the direct child, and MUST NOT signal any pid that was not registered by the agent runner (never kill by name or pid guess).
- MUST NOT leave an approval open after an interrupt; an orphaned approval prompt would let a later keypress approve an action from a cancelled turn.
- MUST be idempotent and re-entrant: concurrent interrupts for the same agent coalesce into one ladder.
- MUST NOT call `process.exit` from the library; only the entrypoint handler (apps/cli) exits, using the exit code from lane C050's table (130 for SIGINT).
- MUST restore the terminal (cursor visible, raw mode off, alt screen left) before exiting on hard interrupt.

## Failure modes
- SIGKILL fails (process not killable) -> report the pid in a warning toast, mark the tool result `canceled`, detach and continue; do not block the UI.
- Runner ignores abort for more than 5 s -> force the agent state to `idle` locally, discard further events from that turn by turn-id, and log at warn.
- Interrupt during a git operation started by the worktree manager -> let the git command finish its current step if it is within 2 s, else kill; never leave `index.lock` behind (remove it if owned by the killed pid).
## Notes
Interrupt of a command-post queue item run, when the host cancels, must surface as `queue.done` with an outcome; the mapping lives in the queue client lane. State after interrupt uses the contract state name `idle`.

## Definition of done
Everything in [GUIDELINES §8](../GUIDELINES.md) plus every acceptance item above covered by a test.
