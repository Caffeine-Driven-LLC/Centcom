## Goal
One-command local development: start the mock backend with realistic seed data, point a dev build of the client at it, and create throwaway git repos for agent/worktree tests, all offline.

## In scope
- `tools/dev/mock.mjs` launching the mock backend (lane C007) with default seed and scenario `happy`, printing the HTTP/WS URLs and the env exports (`CENTCOM_API_URL`, `CENTCOM_RELAY_URL`, `CENTCOM_CONFIG_DIR=.dev/config`, `CENTCOM_STATE_DIR=.dev/state`) the client needs; flags `--scenario`, `--port`, `--seed`.
- Seed data in `dev/seed/`: users `ada` (workspace owner, Pro), `ben` (member), `cy` (guest/viewer), `dee` (billing); workspaces `Acme Pro` (plan pro) and `Acme Team` (plan team); entitlement sets for free/pro/team using the CT-ENTITLEMENTS keys (relay_access, max_seats, max_session_members, max_concurrent_sessions, max_parallel_agents, history_days, agent_minutes_month, ...); three sessions in states created/active/ended; 12 notifications covering every CT-NOTIF-PAYLOAD category.
- `tools/dev/make-fixture-repo.mjs <dir> [--branches n] [--dirty]` creating a deterministic tiny git repo (fixed author/date env, 3 commits, optional extra branches and an uncommitted change) for worktree, lock and agent tests.
- `.devcontainer/devcontainer.json` (Node 22, pnpm) and `docs/dev-setup.md` with the 5-minute path from clone to a running mock + CLI.
- `dev/example-config/config.json` and `dev/example-config/project/.centcom/config.json` samples that pass the config schema (C004) and `dev/README.md` describing each seed user and token minting via the mock's `mintToken`.

## Out of scope
- The mock itself and its loader format: lane C007.
- Test harness helpers: lane C008.
- Any production code or real credentials: this lane ships dev data only.

## Interfaces (the only surface other lanes may use)
- `pnpm dev:mock [-- --scenario x --port n --seed n]` (root script defined in C001) prints a JSON line of URLs then a human block with `export ...` lines.
- `node tools/dev/make-fixture-repo.mjs <dir> [--branches n] [--dirty]` exit 0 and prints the repo path; deterministic commit hashes for identical flags.
- Seed file contract: `dev/seed/{users,workspaces,sessions,entitlements,notifications}.json`, arrays of objects valid against the generated protocol types; all ids are CT-IDS-valid fixed ULIDs.

## Acceptance criteria
1. From a clean clone, `pnpm install && pnpm dev:mock` prints reachable URLs within 5 s and `GET /v1/status` on the printed URL returns 200.
2. All seed files validate against the generated types (test), every id is a valid prefixed ULID, and entitlement objects for free, pro and team differ in `relay_access` (false/true/true) and `max_parallel_agents`.
3. Seeded notifications cover all 14 categories listed in CT-NOTIF-PAYLOAD, each with keys not display text.
4. `make-fixture-repo.mjs` run twice in different temp dirs yields identical `git rev-parse HEAD`; `--dirty` leaves exactly 1 modified tracked file; `--branches 3` creates 3 extra local branches.
5. The example configs load through `loadConfig` (C004) with zero warnings.
6. No file in dev/ contains a string matching the secret patterns from tools/ci/scan-secrets.mjs (C002).

## Tests required
- dev.test.ts: runs both scripts in a temp dir, validates seed files.
- checks fixture repo determinism and flags, Seed round-trip: start mock with `--data dev/seed`.
- fetch `/v1/me` with a minted token for `ada`, assert plan and entitlement rev.

## Guardrails (MUST / MUST NOT)
- MUST use obviously fake data (example.test e-mails, fixed ULIDs); MUST NOT include real names, keys, tokens or e-mail addresses.
- MUST NOT write outside the target directory or `.dev/`; `.dev/` is git-ignored.
- Fixture repo script MUST disable global git hooks/config influence (`GIT_CONFIG_GLOBAL=/dev/null`, `GIT_CONFIG_NOSYSTEM=1`) and call git by argv, never through a shell string.
- MUST work fully offline and MUST NOT require the real backend.

## Failure modes
- Port busy -> mock.mjs retries with `--port 0` and says which port it chose.
- git not installed -> make-fixture-repo exits 3 with an install hint.
- Seed file invalid -> mock refuses to start and lists JSON pointers.
## Notes
C001 gitignores `.dev/`. On Windows the script paths use `node` explicitly so no shebang is needed.
