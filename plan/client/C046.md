## Goal
Drive the mascot from real product state: map CT-STATE-MAP state names to animations with priority, dwell, burst collapsing, idle timers, one-shot caps and visibility rules, so the mascot is a faithful, quiet view of what the agent is doing.

## In scope
- `MascotDriver` state machine (pure, clock-injected) taking inputs `{type:'state', agentId, state}`, `{type:'tool-call'}`, `{type:'milestone', kind:'first-commit'|'pr-merged'|'release'}`, `{type:'failure'}`, `{type:'activity'}` and emitting `{animation, loop, color, visible}` for one mascot per agent id.
- State to animation lookup from the client copy of the state map in packages/theme (lane C009, same keys as contracts/state-map.json, e.g. `awaiting-approval` -> `permission_prompt`, `editing-file` -> `editing_file`); unknown state names behave as `thinking` and are logged once at debug.
- Priority resolution of simultaneous states per DESIGN §11.2 (8 tiers); lower tiers remain available to the status line through `driver.chips()`.
- Timing rules: minimum dwell 600 ms before switching; more than 3 tool calls within 2 s collapse into a single `tool_running`; transitions are hard cuts, with at most one 200 ms `prompt_received` beat when entering work from idle.
- Idle behaviour: `idle_breathe` -> after 20 s `idle_blink` -> after 3 min `look_around` -> after 10 min `status_away`/`sleeping`; night rule: local 23:00-06:00 after 30 min inactivity shows `sleeping` instead of idle (no sound ever).
- One-shot rules: `success` plays `thumbs_up` once then settles to the actual state; `celebrate` only on `milestone` inputs, max one celebratory animation per 10 minutes; `error` plays once per failure, retries do not replay it, a second consecutive failure shows `worried` (state `warning`).
- Visibility policy per DESIGN §10.1.9: visible only in first-run, empty states, waits >= 8 s beside the spinner line, success/failure moments and `/mascot`; never when `mascotAllowed` is false (lane C031), when `CENTO_MASCOT=off`, or when a mascot-free surface flag is set (permission prompts, security, billing, destructive confirmations, DESIGN §11.5).

## Out of scope
- Rendering frames (lane C033) and the static-frame/reduced-motion substitution rules (lane C049 feeds `motion` into this driver).
- Deriving connectivity and limit states (`offline`, `reconnecting`, `rate-limited`, `quota-reached`, `cost-alert`, `context-full`) from net/usage signals; those lanes emit the state names, the driver only maps them.
- Easter eggs such as `/dance` (not in v1).
- Multi-mascot crowd scenes (web).

## Acceptance criteria
1. Feeding `thinking`, then `reading-file` 400 ms later keeps `thinking` until 600 ms have passed, then switches (dwell); reading 10 files in 3 s results in a single `reading_file` view.
2. 5 tool-call inputs within 2 s produce exactly one `tool_running` view and no per-call switching; 3 calls in 2 s do not collapse.
3. With `error` and `editing-file` both active the view is `error` (tier 1 beats tier 4) and `chips()` lists `editing-file`.
4. `error` input plays `error` once (loop false) and returns to the actual state; a retry failure within the same turn does not replay it and a second consecutive failure yields animation `worried`.
5. `celebrate` plays only for a `milestone` input and only if 10 minutes have passed since the last celebratory animation; otherwise the driver plays `thumbs_up`.
6. Idle timeline with fake clock: t=0 `idle_breathe`, t=20 s `idle_blink`, t=3 min `look_around`, t=10 min `status_away`; at local 23:30 after 30 min inactivity `sleeping`.
7. `visible` is false at 80x24 (needs 30 rows), at 100x40 with `CENTO_MASCOT=off`, while `setSuppressed('permission', true)` is active, and for tool-result contexts; true at 100x40 for a wait >= 8 s.
8. Unknown state `future-state` yields animation `thinking` and one debug log line; every one of the 60 keys of contracts/state-map.json resolves to an animation that exists in animations.json (test loads both).
9. Reduced motion: `crash`, `glitch` and `panic` animations are never returned; the driver returns `error` with `loop:false` instead.

## Guardrails (MUST / MUST NOT)
- State drives the mascot; the mascot never drives state (DESIGN §11.4.1). The driver exposes no API that changes agent state.
- MUST NOT show the mascot in mascot-free surfaces: permission prompts, security warnings, billing, destructive confirmations (DESIGN §11.5); lane C038 and C048 call `setSuppressed`.
- MUST NOT imply blame or play joke animations in error, billing or security contexts (DESIGN §11.4.8-9).
- MUST enforce the frequency caps in code, not by convention: one celebration per 10 min, one error animation per failure.
- MUST treat the state map values as client-owned; only the keys are the contract (CT-STATE-MAP), so a missing animation falls back to `thinking` without throwing.
- MUST NOT use wall-clock `Date.now()` directly; time and timezone are injected.

## Failure modes
- State map JSON missing a key present in the contract -> use `thinking`, log once, and fail the coverage test in CI.
- Clock jumps (sleep/resume) -> reset idle timers rather than fast-forwarding through the idle timeline.
- Many agents (> 6 visible) -> only the focused agent's slot animates; the rest return the first-frame view (`loop:false`), matching the 6-animation budget.
