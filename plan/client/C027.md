## Goal
Before each user turn Centcom snapshots the agent's worktree as a git commit on a shadow ref, so the user can rewind files (and optionally the conversation) to an earlier turn without touching their branches, independent of which engine runs the agent.

## In scope
- Automatic checkpoint at the start of every turn (on the normalised `turn.started` event, before the first tool runs), labelled with the first 60 chars of the prompt; cap 100 per agent, oldest evicted.
- Snapshot strategy: inside the agent's worktree (lane C017) use a temporary index (`GIT_INDEX_FILE`), `git add -A` respecting .gitignore, `git write-tree`, `git commit-tree` with the previous checkpoint as parent, and update `refs/centcom/checkpoints/<agent_id>` (one ref per agent; each checkpoint is a commit on that chain, plus a tag-like ref `refs/centcom/checkpoints/<agent_id>@<n>` to protect it from gc). HEAD, the real index, stash and user branches are never touched.
- `rewind(checkpointId, mode)` with modes `files`, `conversation`, `both`; `preview` returns exact files to restore/delete and files modified outside the agent since.
- Conversation rewind: records `markRewind(toSeq)` in the Centcom transcript (lane C026) and then, if the engine reports capability `resume` AND the checkpoint stored an engine resume point (`engineSessionId` plus `engineTurnRef` when the engine reports one), asks the engine to resume from it; otherwise starts a fresh engine session whose first prompt carries a summary of the transcript up to that checkpoint (<= 8 KiB). Claude Code's own rewind feature is never driven or required.
- Slash `/rewind [n]` and action `checkpoints.rewind` (`esc esc` while idle) through the lane C034 action registry; basic Ink list picker showing age, label and file counts.
- Safety checkpoint: every file rewind first creates an automatic checkpoint so the rewind is undoable; recovery ref `refs/centcom/rewind-undo/<agent_id>`.
- Non-git directories: no code checkpoint; `files` mode reports `unavailable` and conversation mode still works.

## Out of scope
- Worktree creation and branch management (lane C017).
- Undoing side effects outside the worktree (shell commands, installs, network, databases); the confirmation text says so.
- Persisting transcripts (lane C026) and starting engine processes (lanes C013, C102, C103).
- Remote/shared sessions: rewind is a local action and sends no wire frame in this lane.
- Merging, pushing or rewriting any user branch.

## Build against (no counterpart needed)
Real git in temp repos built by the lane C008 fixtures, an in-memory C026 store stub and a stub `AgentEngine` (golden transcript replay) that reports capability `resume` on or off. No CLI or network.

## Interfaces (the only surface other lanes may use)
- `interface CheckpointManager { create(label: string, ctx: {promptSeq: number; engineSession?: EngineSessionRef}): Promise<Checkpoint>; list(): Checkpoint[]; preview(id: string, mode: RewindMode): Promise<RewindPlan>; rewind(id: string, mode: RewindMode, opts?: {confirmedPaths?: string[]}): Promise<RewindResult>; dispose(): Promise<void> }`
- `type RewindMode = 'files' | 'conversation' | 'both'`; `type Checkpoint = {id: string; n: number; at: string; label: string; promptSeq: number; commit: string | null; engineSession?: EngineSessionRef; files: {changed: number; added: number; removed: number}}`
- `type RewindPlan = {restore: string[]; delete: string[]; skippedModifiedOutside: string[]; needsConfirm: boolean; conversation: 'engine-resume'|'fresh-with-summary'|'none'}`
- `createCheckpointManager(deps: {worktree: string; agentId: string; store: SessionHandle; engine: Pick<AgentEngine,'capabilities'|'start'>; git: GitRunner; clock: Clock}): CheckpointManager`
- Slash `/rewind [n]`; action id `checkpoints.rewind` default `esc esc` (two presses within 600 ms while idle).

## Acceptance criteria
1. Creating a checkpoint in a worktree with 2,000 tracked files and 5 changed files takes under 500 ms and leaves `git status --porcelain`, HEAD, `.git/index` and `git stash list` byte-identical.
2. The shadow ref `refs/centcom/checkpoints/<agent_id>` exists after the first turn and `git branch --list` and `git for-each-ref refs/heads` are unchanged after 10 turns and a rewind.
3. `rewind(id,'files')` restores every file changed since the checkpoint and deletes files created since, verified by tree-hash equality with the checkpoint tree.
4. Files edited outside the agent after the checkpoint appear in `skippedModifiedOutside`, `needsConfirm` is true, and they are untouched unless listed in `confirmedPaths`; untracked pre-existing and ignored files are never deleted.
5. `rewind(id,'conversation')` with the stub engine reporting `resume` starts the engine with the checkpoint's `engineSessionId`; with `resume` absent it starts a fresh session whose first prompt contains the summary (<= 8 KiB) and the plan says `fresh-with-summary`.
6. The 101st checkpoint evicts the first and deletes its protecting ref; object growth after 100 checkpoints of 1 MiB changes stays under 150 MiB.
7. In a non-git directory `create` returns `commit: null`, `rewind(...,'files')` fails with `checkpoint_unavailable`, and `conversation` mode still works.
8. During a merge or rebase in the worktree files rewind is refused with a clear message; the confirmation text states that effects of shell commands outside tracked files are not undone.

## Tests required
- checkpoints/git-shadow-ref.test.ts: real git; HEAD/index/stash/branches untouched; ignored and untracked files preserved.
- checkpoints/rewind-modes.test.ts: files, conversation, both; modified-outside detection; confirmedPaths.
- checkpoints/engine-resume.test.ts: capability on/off paths with the stub engine.
- checkpoints/eviction.test.ts: cap 100, ref cleanup, rewind to n then latest is a no-op (property test).
- checkpoints/binary-and-large.test.ts: binary, 10 MiB files, symlinks, mode changes.

## Guardrails (MUST / MUST NOT)
- MUST NEVER modify the user's HEAD, branches, real index, stash, reflog or `.gitignore`; all plumbing uses a temporary index and refs under `refs/centcom/` only.
- MUST NEVER delete a file the agent did not create after the checkpoint, nor overwrite a file changed outside the agent without `confirmedPaths`.
- MUST run git with an argument array (no shell), `GIT_TERMINAL_PROMPT=0`, 30 s timeout per command; MUST refuse paths resolving outside the worktree and MUST NOT follow symlinks on restore.
- MUST work identically for every engine and MUST NOT call or depend on Claude Code's own rewind feature; engine resume is used only when capability `resume` is present.
- MUST delete the agent's `refs/centcom/checkpoints/*` when the session is removed (lane C026 `remove`).

## Failure modes
- `git add -A` fails or times out -> checkpoint marked unavailable, warning toast, the turn still runs.
- A restore fails midway -> stop, report restored/unrestored paths, leave `refs/centcom/rewind-undo/<agent_id>` for retry.
- Engine refuses to resume from the stored point -> fall back to fresh-with-summary and say so, showing the tool's own error verbatim.
## Notes
Checkpoints are keyed by agent (one worktree per agent, lane C017/C024), not by session as in the earlier design. `engineTurnRef` depends on what lane C101 normalises; if no engine exposes a turn pointer the conversation rewind is always fresh-with-summary. SPLIT? if the picker grows.
