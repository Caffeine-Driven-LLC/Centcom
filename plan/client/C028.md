## Goal
Users choose a model per agent through whichever engine runs it: the model list comes from what the engines report, the choice is passed through each CLI's documented model option, and no price table or direct model call exists in Centcom.

## In scope
- Model list sources, in order: the model reported by the engine's init event (Claude Code `system/init` model; Codex session/turn info) via the normalised `session.started` event, models the engine reports through `AgentEngine.listModels()` when capability `models.list` is present (documented model commands of the CLI), and a user-editable list of known aliases in config `models.aliases` (aliases only, no prices).
- Per-agent choice, resolution order: `--model <name>` flag, session override (`/model <name>`), project config `model`, user config `model`, else the engine's own default (nothing is passed).
- Passing the choice: Claude Code `--model <name>` at spawn, and for a change on a live session the documented `/model <name>` prompt command (or a restart with `--resume` + `--model` when the engine lacks it); Codex `-m/--model` or the app-server thread/turn model parameter. All mapping lives in engine adapters; this lane calls `AgentEngine.setModel(agentId, name)` and reads `capabilities`.
- `/model [name]`: no arg prints the engine, the model the engine last reported and the cached list (max 80 cols); with arg switches at the next turn boundary. Emits bus event `model.changed` ({agent_id, from, to, reason}) and a `message.system` notice.
- Cache of reported models per engine at `<data>/models-cache.json` (TTL 24 h, refreshed on engine start and on `/model`), flagged with the engine version it came from.
- Unknown names pass through to the CLI unchanged; the CLI's own rejection is shown verbatim. Capability notes: if `models.list` is absent the UI says `This engine did not report a model list.`

## Out of scope
- Any price, context-window or token table: cost is whatever the CLI reports (lane C029); context size display is lane C019.
- Direct calls to any model API, listing models over HTTP, or reading provider config/credential files.
- Engine adapters themselves (lanes C102, C103) and the picker overlay (lane C041 may reuse `list()`).
- Sending model names on the wire; model names are secret payload of `agent.spawn` handled by the session lanes.

## Build against (no counterpart needed)
A stub `AgentEngine` driven by golden transcripts (init events with a model name, a canned model list, and variants without `models.list`); config from lane C004 with an in-memory source. No CLI, no network.

## Deliverables
- `packages/agent/src/models/`
- `packages/agent/src/models/README.md`

## Interfaces (the only surface other lanes may use)
- `interface ModelRegistry { list(engine: EngineId): Promise<ReportedModel[]>; current(agentId: string): {engine: EngineId; model: string | null; source: 'engine-reported'|'flag'|'override'|'config'}; resolve(agentId: string, input?: string): ModelChoice; switchTo(agentId: string, name: string, reason: 'user'|'config'): Promise<ModelChoice> }`
- `type ReportedModel = {id: string; label?: string; reportedBy: 'init-event'|'model-command'|'alias'; engineVersion?: string}`; `type ModelChoice = {engine: EngineId; model: string | null; passAs: 'flag'|'command'|'protocol'}`
- `createModelRegistry(deps: {config: ConfigReader; bus: EventBus; engines: EngineRegistry; cachePath: string; clock: Clock; log: Logger}): ModelRegistry`
- Flag `--model <name>`; slash `/model [name]`; config keys `model`, `models.aliases`, `models.cacheTtlHours` (24).

## Acceptance criteria
1. Precedence table test: flag beats session override beats project config beats user config beats engine default; with nothing set the registry returns `model: null` and the spawn args contain no model option.
2. For `claude-code` the stub engine receives `--model <name>` exactly once at spawn; for `codex` it receives `-m <name>`; both asserted from the recorded argv of the fake CLI.
3. `switchTo` during a streaming turn returns immediately, the engine receives the change only after `turn.done`, and exactly one `model.changed` event is emitted; switching to the current model is a no-op with `Already using <name>.`.
4. With the stub engine lacking `models.list`, `list()` returns only the init-reported model plus configured aliases and `/model` prints the capability note.
5. The cache survives restart, is ignored after 24 h, and is invalidated when the reported engine version changes.
6. `/model` with no argument prints one line per model, max 80 columns, the current one marked `*`.
7. An engine rejection (`provider_protocol_error`-class event with the CLI's text) keeps the previous model, shows a toast `Couldn't switch to <name>. Still using <previous>.` and the CLI's text verbatim in the detail view.
8. A repo-wide grep test fails the build if `packages/agent/src/models/` contains the strings `price`, `per_mtok`, `fetch(` or `@anthropic-ai`/`openai` imports.

## Tests required
- models/resolve.test.ts: precedence and null default.
- models/pass-through.test.ts: argv per engine via recorded fake CLI.
- models/switch.test.ts: turn-boundary application, no-op, rejection.
- models/cache.test.ts: TTL, version invalidation, corrupt cache ignored.
- models/no-prices.test.ts: source scan for forbidden strings and imports.

## Guardrails (MUST / MUST NOT)
- MUST NOT hard-code prices, context windows or full model catalogues; only user aliases and what the engines report.
- MUST NOT call any model API or read provider config/credential files; ask the CLI through documented commands/events only.
- MUST apply a switch only at a turn boundary, so usage reports in lane C029 stay attributable to one model.
- MUST log model names only at debug and never prompts or argv containing user text.

## Failure modes
- Engine model command times out (10 s) -> use cache or init-reported model, mark the list `stale`, no retry loop.
- Config `model` is not a string -> ignore, log the key name at warn, use the engine default.
- Reported list contains duplicates or empty ids -> drop them silently, keep order.
## Notes
Replaces the catalog.json design; a model's context window and cost come from the engine's own usage reports (lane C029/C019). Model names are looked up per engine, so the same alias can map to different names per engine.

## Definition of done
Everything in [GUIDELINES §8](../GUIDELINES.md) plus every acceptance item above covered by a test.
