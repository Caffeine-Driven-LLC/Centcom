## Goal
Create the client pnpm monorepo so every later lane has a package to live in, one set of scripts to run, and lint/type rules that enforce the package dependency direction. After this lane `pnpm install && pnpm typecheck && pnpm lint && pnpm test` pass on an empty-but-wired workspace.

## In scope
- Root workspace: package.json (private, `packageManager` pinned pnpm, `engines.node` >=22 <23), pnpm-workspace.yaml (`apps/*`, `packages/*`), committed pnpm-lock.yaml, .node-version `22`.
- Package shells (package.json + tsconfig.json only) for apps/cli and packages/{protocol,theme,mascot,agent,tui,net,lan,session,testkit}, all named `@centcom/<dir>` (`@centcom/cli` for the app). The apps/web shell is owned by the web scaffold lane (C081); the workspace glob `apps/*` already covers it.
- tsconfig.base.json: `strict`, `noUncheckedIndexedAccess`, `exactOptionalPropertyTypes`, `module/moduleResolution: NodeNext`, ESM only, `verbatimModuleSyntax`; per-package tsconfig extends it with project references.
- ESLint flat config (eslint.config.js) with typescript-eslint strict: ban `any`, `@ts-ignore` without issue link, `console.*` in packages/*/src, `process.exit` outside apps/*/src/main.ts, `eval`, `child_process` with `shell: true`; plus `no-restricted-imports` enforcing dependency direction (see interfaces).
- Prettier (.prettierrc.json: 100 cols, single quotes, trailing commas all), .editorconfig, .gitignore, .npmrc (`ignore-scripts=true`, `save-exact=true`, `engine-strict=true`; listed as `./.npmrc` in deliverables because deliverable paths need 8+ characters), .env.example (names only).
- Root scripts: `typecheck`, `lint`, `format`, `format:check`, `test`, `test:watch`, `build`, `clean`, `dev:mock`, `fixtures:repo`; per-package scripts `build`, `typecheck`, `test`. testkit gets script `mock-backend` (tsx src/mock-backend/cli.ts).
- Root vitest.workspace.ts that discovers `packages/*/vitest.config.ts` and `apps/*/vitest.config.ts` (a package with none gets a default node project).
- Wildcard subpath exports in each package.json (`"./*": "./src/*/index.ts"`, protocol additionally `"."`) so later lanes add subfolders without editing package.json.

## Out of scope
- CI workflows, lock check, licence/secret scans: lane C002.
- Generated protocol code and the shared test preset: lanes C003 and C008.
- Any real source code under packages/*/src or apps/*/src (each owning lane adds its own folder).
- Bundling / Node SEA packaging and release tooling: lane C012 and later packaging lanes.

## Interfaces (the only surface other lanes may use)
- Root scripts: `pnpm typecheck` (tsc -b), `pnpm lint` (eslint . --max-warnings 0), `pnpm test` (vitest run), `pnpm build`, `pnpm format:check`.
- Dependency direction enforced by lint (a package may import only packages on its right): protocol <- {theme,mascot,net,testkit}; net <- {lan,session,agent}; theme+mascot <- tui; {protocol,net,lan,session,agent,tui,theme,mascot} <- apps/*; testkit may import anything but nothing outside testkit and test files may import testkit.
- Naming: workspace deps use `workspace:*`; internal imports use package names (`@centcom/net/errors`), never relative paths across packages.
- Scripts that point at files owned by later lanes: `dev:mock` -> `node tools/dev/mock.mjs` (C011), `fixtures:repo` -> `node tools/dev/make-fixture-repo.mjs` (C011), `@centcom/protocol` `gen` -> `tsx scripts/gen.ts` (C003), `@centcom/theme` and `@centcom/mascot` `sync` -> `tsx scripts/sync-assets.ts` (C009), `@centcom/testkit` `mock-backend` -> `tsx src/mock-backend/cli.ts` (C007).

## Acceptance criteria
1. On a clean clone with Node 22: `pnpm install --frozen-lockfile` exits 0 and runs no dependency install scripts (`.npmrc ignore-scripts=true`).
2. `pnpm typecheck`, `pnpm lint` and `pnpm test` all exit 0 on the empty workspace, and `pnpm lint` fails with a non-zero code when a file in packages/net imports from `@centcom/agent` (dependency-direction test fixture).
3. ESLint reports an error for each of: an `any` type, `console.log` in packages/*/src, `process.exit` in packages/net/src, `spawn(..., {shell:true})`, `// @ts-ignore` with no URL.
4. Every package.json has `"type":"module"`, `"private":true`, `"license":"UNLICENSED"` placeholder replaced only by an ADR, and exact (no `^`/`~`) dependency versions: a script check `node -e` over all package.json files finds zero ranges.
5. `pnpm -r build` produces no output files outside each package's `dist/`; `pnpm clean` removes them.
6. `pnpm --filter @centcom/testkit run mock-backend --help` resolves the script name (the entry file may print 'not implemented' until C007 lands).
7. Running `pnpm install` on Windows, macOS and Linux yields an identical pnpm-lock.yaml (no platform-specific diffs).

## Tests required
- tools/meta/workspace.test.ts (root Vitest project `meta`) asserting all package.json fields (name scope, type, exact versions, wildcard exports).
- tools/meta/lint-fixtures/: ESLint cases run through the Node API for each banned construct and for the dependency-direction rule.
- CI-less smoke: `pnpm -r typecheck` over all shells on Node 22.

## Guardrails (MUST / MUST NOT)
- MUST pin every dependency to an exact version and keep `ignore-scripts=true`; MUST NOT add a package with a postinstall script or a non-MIT/Apache-2.0/BSD/ISC licence.
- MUST keep `.env.example` to variable NAMES with empty values; MUST NOT commit any real key, token or `.env`.
- MUST NOT add runtime dependencies to the root package.json (dev tooling only).
- MUST make the dependency-direction rule fail the build rather than warn, so protocol/net never depend on UI packages.
- MUST NOT introduce a `core`/`shared` package; shared runtime code goes where the owning lane's deliverables say (e.g. config/log under packages/net/src).

## Failure modes
- Node version below 22 -> `pnpm install` fails with the `engine-strict` message; the scripts never fall back to an older runtime.
- Lockfile out of date -> CI `--frozen-lockfile` fails; the fix is regenerating the lockfile in the same PR, never ignoring the failure.
- A later lane adds a cross-package relative import -> lint error names the offending file and the allowed alternative.
## Notes
Placement decision: the layout in plan/LANE_CARD_SPEC.md has no shared core package, so config, logging, error model and telemetry live in packages/net/src/{config,log,errors,telemetry}/ and the event bus in packages/agent/src/events/. Propose an ADR for a `packages/core` if import cycles appear. License value is a placeholder pending a human decision.
