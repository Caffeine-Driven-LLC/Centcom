## Goal
Configure, start, supervise and stop MCP servers for agents, with explicit trust for project-defined servers, a minimal environment for child processes, and bounded timeouts and output sizes.

## In scope
- Config sources: user `<config dir>/mcp.json` and project `.centcom/mcp.json`: `{ servers: { <name>: { type: 'stdio', command: string, args?: string[], env?: Record<string,string>, cwd?: string } | { type: 'http'|'sse', url: string, headers?: Record<string,string> } } }`; server names `^[a-z][a-z0-9_-]{0,31}$`.
- Trust gate: a project-defined server (or any server whose definition hash changed) is not started until `TrustStore.isTrusted('mcp', sha256(canonical JSON of definition))` (store from lane C013); a `needsTrust` list is exposed for the UI to prompt; user-config servers are trusted implicitly.
- Lifecycle: lazy start on first use, handshake timeout 15 s, health ping every 30 s, restart with backoff 1 s, 2 s, 4 s ... cap 30 s, max 5 consecutive failures then `failed` until manual `restart`; stop with SIGTERM then SIGKILL after 3 s on agent/runner exit.
- Child environment is an allow-list (PATH, HOME, LANG, TERM, TMPDIR) plus declared `env` after `${VAR}` expansion restricted to an allow-list of variable names the user config names in `env_passthrough`; `secret:<name>` values resolved by an injected `SecretResolver` (keychain), never stored in config files.
- Tool exposure: tools named `mcp__<server>__<tool>` handed to the runner; call timeout default 60 000 ms, result size cap 256 KiB (truncated with a marker), concurrency cap 4 per server.
- URL servers: https only except loopback; no redirects to other origins; headers never logged.
- Status API for UI: `{ name, state: 'stopped'|'starting'|'ready'|'failed'|'untrusted', tools: number, lastError?: code }`.

## Out of scope
- Implementing the MCP protocol transport itself beyond using the SDK/official client library (justify the dependency).
- Permission decisions for MCP tool calls: lane C015 (this lane only names the tools and marks read-only hints).
- Keychain access: injected `SecretResolver` (net/auth lanes).

## Acceptance criteria
1. A project `.centcom/mcp.json` server is reported `untrusted` and never spawned (spawn mock call count 0) until `trust(name)`; editing its `args` changes the hash and reverts it to `untrusted`.
2. Child env for a stdio server contains only the allow-listed variables + declared env: a poisoned parent env with `CENTCOM_REFRESH_TOKEN`, `AWS_SECRET_ACCESS_KEY`, `GITHUB_TOKEN` shows none of them in the spawned env.
3. Handshake that does not complete in 15 000 ms (fake clock) marks the server `failed` and kills the child; the crash-on-call fixture is restarted with delays 1 s, 2 s, 4 s and after 5 consecutive failures stays `failed`.
4. A tool returning 1 MiB is truncated to 256 KiB with a trailing marker, and the call result flags `truncated:true`; a slow tool call is aborted at 60 000 ms with `McpTimeout`.
5. `stopAll` terminates children: SIGTERM, then SIGKILL at 3 s if still alive, resolving in <= 4 s; no zombie child in the process list (test via pid check).
6. Tool names follow `mcp__<server>__<tool>`; a server named `a__b` or a tool name containing control characters is rejected.
7. An `http` URL server with scheme `http://example.com` is rejected; `https://` and `http://127.0.0.1:PORT` accepted; a 302 to another origin is not followed.

## Guardrails (MUST / MUST NOT)
- MUST NOT start a project-defined MCP server (it runs an arbitrary command) without explicit local trust bound to the definition hash.
- MUST NOT pass the parent environment, tokens or keychain data to servers; secrets only via `secret:` references resolved at spawn.
- MUST NOT log commands, args, env, headers, URLs with credentials or tool inputs/outputs.
- MUST bound everything: startup 15 s, call 60 s, output 256 KiB, 4 concurrent calls per server, 20 servers total.
- MUST NOT shell-interpolate: `command` + `args` are spawned as argv without a shell.

## Failure modes
- Server binary missing -> status `failed` with `lastError:'spawn_failed'`; other servers unaffected; agent continues without those tools.
- Server writes non-protocol noise on stdout -> ignored up to 1 MiB then killed as `protocol_error`.
- Trust store corrupted -> treated as empty (everything untrusted).
