## Goal
Make the TUI usable with reduced motion, NO_COLOR and a screen reader: a shared motion context, a linear (append-only) rendering mode, text equivalents for every state, and a conformance test that every TUI component passes.

## In scope
- `MotionProvider` / `useMotion()` combining `CENTO_REDUCE_MOTION=1`, `/motion reduced` (lane C047) and screen-reader mode into `'full'|'reduced'`; consumed by C033 (static frame), C040 (static `…`), C043 (static bar), C046 (no crash/glitch/panic).
- Screen-reader mode switch: flag `--screen-reader`, env `CENTO_SCREEN_READER=1`, config `a11y.screenReader`; implies reduced motion, no mascot, no alt screen, no box-drawing borders, no cursor-movement redraw.
- `LinearRenderer`: subscribes to the bus and prints transcript items, tool calls/results, approvals, toasts and state changes as plain appended lines (`Assistant: ...`, `Tool: Read src/a.ts`, `Result: 120 lines`), with a `> ` readline prompt and line-based permission prompts (`Allow Cento to run: <command> in <dir>? [y/n/a]`).
- State text equivalents `describeState(state, ctx)` for all 60 CT-STATE-MAP names, in full sentences (`Cento is editing 3 files`, `Waiting for your approval`), plus `announce(text, 'polite'|'assertive')` which writes a distinct line (assertive for blocking errors).
- Colour-independence and no-colour audit helpers used by tests: `assertNoColorCodes(output)`, `assertGlyphAndWord(output, states)`.
- A conformance suite in packages/tui/test/a11y/ that mounts every TUI component fixture (prompt, transcript, diff, permission, status, spinner, palette, fleet, tasks, toast, help, first-run) under `NO_COLOR=1`, `CENTO_REDUCE_MOTION=1` and screen-reader mode.

## Out of scope
- Theme token logic (lane C032) and the high-contrast palette itself.
- Per-component rendering changes beyond reading the motion context; each lane implements its own reduced variant.
- Web accessibility (web lanes).
- Sound cues.

## Build against (no counterpart needed)
All other TUI lanes' components with prop fixtures through the lane C008 harness; the bus from lane C025 driven by recorded event scripts. No backend.

## Acceptance criteria
1. With `CENTO_REDUCE_MOTION=1` a 10 s run of the full app emits no animated redraws: the mascot area changes 0 times, the spinner line shows `…` with elapsed seconds updating once per second, indeterminate progress is static (frame-diff count from the pty harness).
2. In reduced motion `crash`, `glitch` and `panic` animations are never selected, and nothing in the UI changes more than 3 times per second (flash budget test on recorded frames).
3. `describeState` returns a non-empty sentence for each of the 60 state keys and `describeState('future')` returns `Cento is working`.
4. Screen-reader mode output for a scripted session contains no ESC sequences at all (no colour, no cursor movement, no `?1049h`), every line ends with `\n`, and states appear as sentences (e.g. `Cento is editing 3 files.`).
5. In screen-reader mode a permission request prints one line with the exact command and directory and accepts `y`, `n` or `a` + Enter; invalid input re-asks; the prompt never auto-approves on timeout.
6. A blocking error (e.g. `auth-required`) is announced with prefix `Error:` on a separate line; a non-blocking state change is prefixed `Status:`.
7. The conformance suite fails if any component's `NO_COLOR` output contains `ESC[3` `ESC[4` colour parameters or if a status (success, warning, danger, info) is rendered without its glyph and word; run in CI on 12 components.
8. The mascot never appears in screen-reader mode and `<Cento>` renders nothing there.

## Tests required
- a11y/motion.test.ts: provider resolution and consumer contract.
- a11y/linear.test.ts: scripted bus session to expected plain text; no ESC bytes.
- a11y/describe-state.test.ts: all 60 keys.
- a11y/conformance.test.ts: every component fixture under three modes.
- a11y/flash.test.ts: frame-rate rule on recorded frames.
- a11y/permission-linear.test.ts: line-based approval, invalid input, no auto-approve.

## Guardrails (MUST / MUST NOT)
- MUST NOT convey information by colour, animation or position alone; every state has text (DESIGN §16.2-16.3).
- MUST NOT auto-approve, auto-deny or time out a permission request because of slow screen-reader input.
- MUST NOT emit cursor-movement or screen-clearing sequences in screen-reader mode.
- MUST honour `NO_COLOR` and reduced motion regardless of other settings, and MUST NOT allow `/theme` or `/mascot on` to override screen-reader mode.
- MUST keep announcements free of secrets: command lines are shown only for permission prompts, as in the visual UI.

## Failure modes
- Stdin is not a TTY in screen-reader mode -> read lines from stdin without prompts and exit on EOF with code 0.
- A component fixture throws in the conformance run -> the suite reports the component name and fails; no component is skipped silently.
