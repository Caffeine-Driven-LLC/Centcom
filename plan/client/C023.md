## Goal
Edit project and user memory files for the engines (`CLAUDE.md` for Claude Code, `AGENTS.md` for Codex) with an optional shared source that keeps both in sync, a quick-add flow (`#` in the TUI), conflict handling, and no overwrite without diff and confirmation.

## In scope
- Files: project `<repo>/CLAUDE.md`, `<repo>/AGENTS.md`; user `~/.claude/CLAUDE.md` and the user-level Codex AGENTS.md path (paths supplied by the engine adapters; Centcom never reads other files in those directories).
- Plain edit flow: `read(file)` returns text + sha256; `plan(edit)` returns a unified diff; `apply(plan, confirm)` writes atomically (temp + rename) only if the on-disk sha256 still equals the one the plan was built on (else `Conflict` with the new text for a 3-way merge view).
- Quick add (`#` in the TUI composer or `centcom memory add "text" [--to claude|codex|both] [--scope project|user]`): appends one bullet under a `## Notes (added with Centcom)` heading, creating the heading if missing; shown as a one-line diff and confirmed with Enter.
- Optional sync: shared source `.centcom/memory.md` plus generated sections; `sync` rewrites only the region between `<!-- centcom:memory:begin sha256=<hex> -->` and `<!-- centcom:memory:end -->` in both CLAUDE.md and AGENTS.md; content outside markers is never modified; sync is off by default and enabled per repo in `.centcom/config.json` `memory.sync: true`.
- Drift detection: `status()` reports `in_sync|source_changed|target_edited|conflict` by comparing marker checksums; `target_edited` offers 'pull into source' (diff and confirm) or 'overwrite from source' (diff and confirm).
- Secret guard: refuses content where `looksLikeSecret` (C005) matches or that contains a PEM block, returning `SecretRejected` without echoing content. Size caps: file <= 256 KiB for edits, quick-add text <= 2 KiB.
- Import hint: if a repo has only one of the two files, offer (never auto-create) to create the other as a pointer or a synced copy.

## Out of scope
- Loading memory into the model: the engines read CLAUDE.md and AGENTS.md natively; Centcom injects nothing.
- Automatic memory extraction by the model. Syncing memory to the backend or teammates (local files only; git is the user's own).
- The full-screen editor widget: TUI lanes; this lane provides the model and the flows.
- Skills, hooks, MCP: C020, C022, C021.

## Interfaces (the only surface other lanes may use)
- `createMemoryFiles(deps: { fs: MemFs; engines: { memoryPaths(engine: EngineId, scope: 'project'|'user', root?: string): string | undefined }; log: Logger; config: { sync: boolean } }): MemoryFiles`
- `interface MemoryFiles { read(engine: EngineId, scope, root?): Promise<{ text: string; sha256: string; exists: boolean }>; plan(edit: { engine: EngineId; scope: 'project'|'user'; newText?: string; quickAdd?: string; root?: string }): Promise<MemoryPlan>; apply(plan: MemoryPlan, confirm: { accepted: true; planHash: string }): Promise<ApplyReport>; status(root?: string): Promise<SyncStatus>; sync(op: { direction: 'source_to_targets'|'target_to_source'; from?: EngineId; root?: string }): Promise<MemoryPlan> }`
- `SyncStatus = { state: 'in_sync'|'source_changed'|'target_edited'|'conflict'|'disabled'; files: { engine: EngineId; state: string }[] }`; local errors `SecretRejected`, `TooLarge`, `Conflict`, `PlanChanged`.
- CLI: `centcom memory show|edit|add|status|sync [--scope project|user]`; TUI: a line starting with `#` is routed to `plan({quickAdd})` instead of the prompt.

## Acceptance criteria
1. Quick add of `Use pnpm, not npm` to a repo with CLAUDE.md creates a plan whose diff is exactly the new `## Notes (added with Centcom)` heading plus one bullet; `apply` writes it and every other byte is unchanged (CRLF preserved).
2. If the file changes on disk between `plan` and `apply`, `apply` throws `Conflict` carrying the new text and writes nothing; an `apply` without `accepted: true` writes nothing (fs write count 0).
3. With `sync: true`, `sync({direction:'source_to_targets'})` updates only the marked region in both CLAUDE.md and AGENTS.md; 100 lines outside the markers stay byte-identical; running it again yields an empty diff.
4. After a manual edit inside the CLAUDE.md marked region, `status` returns `target_edited`; if the source also changed it returns `conflict` and `apply` refuses until the user chooses a direction.
5. Content containing `-----BEGIN PRIVATE KEY-----` or a string from `secret-patterns.json` is refused with `SecretRejected`; the error text contains no part of it.
6. Writes are atomic: a simulated crash between temp write and rename leaves the old file intact; file mode of an existing file is preserved.
7. A `#`-prefixed TUI line `# remember tabs` produces a quick-add plan and is not sent to the engine (engine `send` mock count 0); a line `#hashtag` without the space is sent as a normal prompt.
8. A 300 KiB edit is refused with `TooLarge`; quick-add text of 2 049 bytes is refused.

## Guardrails (MUST / MUST NOT)
- MUST NOT overwrite any memory file without a shown diff and a confirmation bound to the plan hash and the on-disk sha256.
- MUST NOT modify bytes outside Centcom's marker region during sync; user-authored text is never regenerated.
- MUST NOT transmit memory text anywhere (wire, telemetry, snapshots, logs); log only counts and states.
- MUST NOT persist secret-looking content; MUST NOT read any file in `~/.claude` or `~/.codex` except the memory file path given by the adapter.
- Paths are fixed by the adapters; no user-supplied path may leave the repo root or the user memory file.

## Failure modes
- File missing -> `exists:false`; a plan creates it (0644) after confirmation.
- Non-UTF-8 or binary file -> `unreadable`, not editable here.
- Disk full or EACCES -> typed error, original file untouched, temp file removed.
## Notes
This replaces the earlier private CENTCOM.md store; Centcom has no memory format of its own, only the vendors' files. Whether Codex also reads a user-level AGENTS.md must be confirmed with the installed version (the adapter returns undefined when not).
