## Goal
A deterministic, in-process mock of the whole backend contract (REST from the OpenAPI document plus a WebSocket relay simulator with scriptable scenarios) so every network-facing client lane can be built and tested with no real server.

## In scope
- REST server (node:http, no framework) whose routes, methods, status codes and schemas are driven by `operations` generated from contracts/openapi.yaml (lane C003 output). Hand-written behaviour for core flows: device auth (`POST /v1/auth/device/code`, `POST /v1/auth/token` incl. `authorization_pending`, `slow_down`, `access_denied`, `expired_token`, refresh rotation with `refresh_reuse_detected`), `GET /v1/me`, workspaces/members/invites, sessions (`POST /v1/sessions`, `join-token`, `members`, `history`, `snapshot` + commit), entitlements, usage ingest, notifications, flags, status, releases, telemetry. Every other operation answers from schema examples/seeded generated data.
- Cross-cutting REST behaviour: Bearer auth with Ed25519-signed JWT access tokens (15 min) and JWKS at `/.well-known/jwks.json`; problem+json errors with `request_id` and `X-Request-Id`; `RateLimit-*` headers and a scriptable 429 with `Retry-After`; cursor pagination (`limit` 1..200, `next_cursor`, `has_more`); `Idempotency-Key` store (24 h virtual time, `Idempotency-Replayed: true`, 409 `idempotency_conflict`, `idempotency_key_required` on required routes); `ETag`/`If-Match` -> 412 `precondition_failed`; body limits (256 KiB, usage 1 MiB).
- WS relay simulator at `/v1/ws` (subprotocol `centcom.v1`): hello timeout 5 s -> close 4408; ticket check (JWT `aud=centcom-relay`, 60 s `exp`, single-use `jti`) -> `sys.error` + 4401; `sys.welcome` with `heartbeat {ping_ms:20000, dead_ms:50000}` (overridable), `member`, `limits`, `resume`; server-assigned `seq` from 1 on every sequenced frame, echo to sender with `seq`, de-dup by `(sid, from, id)`, ack tracking, replay buffer (>= 5000 frames), `sys.resumed {from_seq,to_seq,count}` or `{snapshot_required:true,snapshot_seq}`.
- Relay semantics for queue (states queued/approved/running/done, caps 5 per member and `queue_limit` default 20 -> `sys.error queue_full`, `queue.state` after every change, `queue_item_gone`), control (host-only kick/mute/role/transfer/end/policy, server-only frames ignored from clients, kick -> close 4403 + `control.rotate_key` with consecutive seq), presence coalescing (<= 1 fan-out per 500 ms per member, never replayed), and `sys.notice` injection (codes from CT-WS-SESSION-EVENTS).
- Scripted behaviours: forced disconnect with any close code (1001, 4401, 4403, 4404, 4409, 4426, 4429, 4503), `sys.slow_down` then 4429 when the client's outbound buffer exceeds 2 MiB, bad-frame injection (`invalid_frame`, >10/min -> 4400), duplicate delivery, out-of-order delivery (to test client reorder), delayed acks, host loss/return, and virtual peers (host/editor/viewer members that send scripted frames; ciphertext is opaque, the mock never decrypts).
- Control plane on 127.0.0.1 only: `POST /__mock/scenario`, `/__mock/disconnect {code, retry_after_s?}`, `/__mock/notice`, `/__mock/advance {ms}`, `/__mock/reset`, `GET /__mock/frames?sid=` (frame log of kinds/ids only). Same operations as methods on the programmatic handle.
- CLI `pnpm --filter @centcom/testkit mock-backend --port <n|0> --scenario <name|file.json> [--seed <int>] [--data <dir>] [--clock real|virtual] [--ping-ms n --dead-ms n]`; with `--port 0` prints one JSON line `{"http":"http://127.0.0.1:P","ws":"ws://127.0.0.1:P/v1/ws"}` on stdout and logs to stderr.
- Bundled scenarios in packages/testkit/scenarios/: `happy`, `resume-hot`, `resume-snapshot`, `forced-disconnect`, `ticket-expired`, `superseded`, `kicked`, `host-loss`, `slow-consumer`, `bad-frames`, `quota-warning`, `maintenance`, `client-too-old`, `overload-4503`, `errors` (every registry code once), `rate-limited`.

## Out of scope
- Any production code path: the mock lives in testkit and nothing outside tests/dev tooling may import it.
- Real cryptography of session content (the mock treats `ct` as opaque) and the client crypto itself.
- Default seed data and the dev-launch wrapper `tools/dev/mock.mjs`: lane C011 (this lane only defines the `--data` loader format).
- Billing provider behaviour: checkout/portal return canned `{url}` values only.

## Build against (no counterpart needed)
Self-contained: depends only on generated validators and operation tables from lane C003 and the fixtures under contracts/fixtures/. Conformance of the mock itself is checked by replaying those fixtures through it and by contract-shape validation of every response against the OpenAPI response schema.

## Acceptance criteria
1. With a fixed `--seed 7 --clock virtual`, two runs of scenario `happy` driven by the same client script produce byte-identical frame logs (kinds, ids, seqs, timestamps) -- asserted by a golden file.
2. Every operation in openapi.yaml answers with a status and body that validate against its response schema (generated sweep test, one request per operation, count asserted equals operation count).
3. Handshake: no `sys.hello` within 5 s of virtual time -> close 4408; hello with an expired ticket -> `sys.error` then close 4401; reusing a ticket `jti` -> 4401; second connection for the same member+device -> first gets `sys.bye reason=superseded`, close 4409.
4. Sequencing: 3 clients send interleaved frames; each receives all frames in identical `seq` order starting at 1 with no gaps; a resent frame with the same `id` yields no new `seq`.
5. Resume: client reconnects with `last_seq` inside the 5000-frame buffer -> receives exactly the missing frames then `sys.resumed {from_seq,to_seq,count}`; with `last_seq` older than the buffer -> `sys.resumed {snapshot_required:true}`.
6. Queue: 6th live item from one member -> `sys.error` `queue_full` to that member only; non-host `queue.approve` -> `forbidden`; `approve` for a finished item -> `queue_item_gone` to sender only; every change emits `queue.state` with an increasing `version`.
7. Control: `control.kick` from the host closes the target with 4403 and the next two sequenced frames are `control.member_left` and `control.rotate_key`; `control.kick` from an editor is rejected; a server-only kind sent by a client is dropped.
8. Slow consumer: a client that does not read until > 2 MiB is buffered receives `sys.slow_down` and is then closed with 4429.
9. Bad frames: 11 invalid frames within 60 virtual seconds -> 10 `sys.error invalid_frame` then close 4400; an unknown `k` is sequenced and forwarded without error.
10. REST: a replayed POST with the same `Idempotency-Key` and body returns the stored response with `Idempotency-Replayed: true`; different body -> 409 `idempotency_conflict`; list endpoints honour `limit` and return stable `next_cursor` pages.
11. `--port 0` prints exactly one valid JSON line on stdout within 2 s; the process exits 0 within 1 s of SIGINT.
12. The mock binds only to 127.0.0.1 and `/__mock/*` returns 404 on any non-loopback source address.

## Guardrails (MUST / MUST NOT)
- MUST NOT decrypt, parse or log `ct` payloads; the frame log stores kind, ids, sizes and seq only (mirrors the relay privacy budget).
- MUST be deterministic: all time via the injected virtual clock, randomness via a seeded PRNG, ids via the CT-IDS generator; MUST NOT call `Date.now()`, `Math.random()` or `setTimeout` directly.
- MUST bind to 127.0.0.1 only and MUST NOT make outbound network calls; the control plane MUST refuse non-loopback peers.
- MUST validate every inbound REST body and WS frame with the generated validators and reject unknown frame types/closed shapes the way the contract says; MUST NOT accept fields the real service would reject just to be convenient.
- MUST NOT import from or be imported by production packages; the lint dependency rule (C001) enforces this. Test-signing keys are generated at start and never written to disk.
- MUST implement authorisation per CT-RBAC from live mock membership, never from client-supplied role claims.

## Failure modes
- Port already in use -> CLI exits 1 with `EADDRINUSE` message naming the port; programmatic call rejects with the same error.
- Malformed scenario file -> exit 2 listing JSON pointers of every violation; nothing starts.
- OpenAPI operation with no hand-written handler and no example -> the mock generates a deterministic response from the response schema; if generation is impossible the sweep test fails (the mock never invents an error code).
