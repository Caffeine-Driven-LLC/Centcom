## Goal
Make every shortcut a named, remappable action with a single keymap, support chords and contexts, validate conflicts at load, and provide a `?` help screen listing the live bindings.

## In scope
- Key-string grammar and parser: modifiers `ctrl+ alt+ shift+ meta+`, names `enter esc tab space backspace delete up down left right home end pageup pagedown f1..f12`, single characters, and chords of up to 2 steps separated by a space (`ctrl+x ctrl+s`) with a 1,000 ms chord timeout; normaliser from Ink `useInput` events and raw sequences to `KeyEvent`.
- Default keymap table `defaultKeymap` implementing DESIGN §22.2: `enter` send, `shift+enter` newline, `esc` interrupt/close overlays, `ctrl+k` palette, `ctrl+t` tasks, `ctrl+b` fleet rail, `shift+tab` cycle mode (ask -> accept edits -> plan), `y/n/a` in permission prompts, `?` help.
- User overrides from `keybindings.json` in the user config dir (path from lane C004): `{"bindings": [{"key": "ctrl+o", "action": "palette.open", "context": "global"}], "unbind": ["ctrl+k"]}`, validated with a JSON schema; invalid entries are skipped with warnings listed in the help screen.
- Contexts (`global`, `prompt`, `overlay`, `transcript`, `permission`, `palette`, `toast`) and resolution: innermost focus context first, then `global`; conflict detection per context at load.
- Dispatcher that replaces the simple per-action `defaultKey` handling of lane C034 with the resolved keymap, via the same `registerAction` registry.
- Help screen `<HelpScreen>` opened by `?` when the prompt is empty (and by `/help`): actions grouped by `group`, key names bold (DESIGN §5.4), two columns at >= 100 cols and one at 80, live filter typed in a search line, `esc` closes; plus `centcom keys` CLI printing the table (plain text, `--json` for scripts).

## Out of scope
- The actions themselves (each lane registers its own through `registerAction`).
- Prompt-level text editing keys (lane C035 owns the editing keys inside the text buffer).
- Permission prompt decisions (lane C038 registers `y/n/a/e` in context `permission`; this lane only lets them be remapped).
- Mouse bindings and OS-level shortcuts.

## Build against (no counterpart needed)
Pure parser tests plus the pty harness from lane C008 sending raw byte sequences; a stub registry with 12 actions for rendering tests. No backend.

## Interfaces (the only surface other lanes may use)
- `parseKey(s: string): KeyChord | KeyParseError`; `formatKey(k: KeyChord): string`; `type KeyChord = KeyStep[]`; `type KeyStep = {ctrl: boolean; alt: boolean; shift: boolean; meta: boolean; key: string}`
- `loadKeymap(deps: {defaults: Keymap; userFile?: string; actions: ActionDef[]}): {keymap: Keymap; warnings: KeymapWarning[]}`
- `createDispatcher(deps: {keymap: Keymap; focus: FocusStack; clock: Clock}): { handle(ev: KeyEvent): boolean }`
- `<HelpScreen actions: ActionDef[]; keymap: Keymap; warnings: KeymapWarning[]; onClose: () => void />`
- CLI: `centcom keys [--json]`; slash `/help`; action ids `help.open` (`?`), `app.quit`.

## Acceptance criteria
1. `parseKey('ctrl+shift+p')` yields ctrl+shift+`p`; `parseKey('ctrl+x ctrl+s')` yields two steps; `parseKey('banana+x')` returns a typed `KeyParseError`; `formatKey(parseKey(k))` round-trips for 100 generated keys.
2. A chord's first step followed by silence for 1,000 ms (+/-50 ms) cancels the chord and the first key is not replayed as a standalone command if it was swallowed; a non-matching second key cancels the chord and is processed normally.
3. With the default keymap, `ctrl+k` in context `prompt` triggers `palette.open`; with a user file `{unbind:["ctrl+k"], bindings:[{key:"ctrl+o",action:"palette.open"}]}`, `ctrl+k` does nothing and `ctrl+o` opens the palette.
4. Two actions bound to the same key in the same context produce a `KeymapWarning` naming both and the later binding is ignored; the same key in different contexts is allowed.
5. If the user unbinds the last binding of `app.quit` or `help.open`, the loader restores the default and warns, so the app can always be quit and help can always be opened.
6. `?` opens help only when the prompt buffer is empty; otherwise it types `?`.
7. Help screen at 80x24 fits without scrolling for 30 actions in the 2-column/1-column rule, shows key names bold and groups headed in `text.secondary`; typing `pal` filters to `palette.open`.
8. `centcom keys --json` prints a stable JSON array `[{id, group, description, keys:[...], context}]` and exits 0; invalid user file prints warnings to stderr and still exits 0.

## Tests required
- keys/parse.test.ts: grammar, round-trip property test, bad input.
- keys/decode.test.ts: raw byte sequences (CSI u, legacy ctrl, alt-prefix ESC) to KeyEvent.
- keys/chords.test.ts: timeout and cancellation with fake clock.
- keys/keymap.test.ts: overrides, unbind, conflicts, protected actions, schema errors.
- keys/help.test.ts: snapshots 80x24, 120x40, NO_COLOR; filter.
- keys/cli.test.ts: `centcom keys --json`.

## Guardrails (MUST / MUST NOT)
- MUST keep every action remappable (DESIGN §16.2) except that `app.quit` and `help.open` always keep at least one binding.
- MUST NOT bind or swallow `ctrl+c` outside the explicit `app.interrupt_or_quit` action; terminals send it as a signal-like byte and lane C030 owns its semantics.
- MUST NOT execute actions from pasted text: bracketed-paste content bypasses the dispatcher entirely.
- MUST validate the user keybindings file against a schema and never evaluate any value from it as code.
- MUST dispatch exactly one action per key event; actions in `overlay` and `permission` contexts take precedence over `global`.
- MUST NOT change action ids once released; they are part of the user-facing config surface.

## Failure modes
- keybindings.json unreadable or invalid JSON -> use defaults, show `※ keybindings.json was ignored (line 3).` once at startup and in the help screen.
- Terminal cannot report a modifier (shift+enter) -> the action is still reachable through its documented fallback key listed in help.
- Unknown action id in user file -> skip the entry and warn with the id.
## Notes
Ambiguities of terminals (esc vs alt-prefixed keys: treat ESC followed within 20 ms by a byte as alt+byte; lone ESC after 50 ms is `esc`) are documented in the README. `shift+tab` mode cycling's state is owned by the permission engine (lane C015).
