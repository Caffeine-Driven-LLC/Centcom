## Goal
Classify shell commands, tool uses and paths into low/medium/high risk for the approval UI and rules, and map Centcom permission modes onto each CLI's native sandbox and permission flags. Centcom builds no sandbox of its own; it only classifies and passes settings to the engines.

## In scope
- Shell tokenizer/parser (no `eval`, no execution) for POSIX shells and PowerShell-lite: splits on `;`, `&&`, `||`, `|`, `&`, newlines; understands quoting, escapes, env prefixes, redirections, `$(...)`, backticks, process substitution, heredocs, `eval`, `source`, and `sh -c`/`bash -c` nesting (recursive to depth 4); fails closed.
- Per-segment classification: `low` (known read-only: ls, cat, head, tail, wc, pwd, echo, `git status|diff|log|show`, rg, grep, find without -exec/-delete), `medium` (writes inside root, installs, `git commit|add|checkout`, build/test runners, curl/wget to a file), `high` (rm -rf, dd, mkfs, chmod/chown -R, `git push --force`, `git reset --hard`, `git clean -fd`, sudo/su, `curl | sh`, writes outside root, credential paths, shutdown, fork bombs, anything unparseable or depth > 4). Overall risk is the max over segments.
- Result `{ risk: 'low'|'medium'|'high'; reasons: string[] /* rule ids, never command text */; facts: { writes; deletes; network; escapesRoot; isTest; destructive } }`; `destructive` is true for rm -r, force-push, reset --hard, clean, dd, mkfs, drop-style SQL via CLI, and such results are never auto-allowed (`autoAllowable:false`).
- Tool-level classification of normalised tool kinds: read=low, edit/create inside root=medium, outside root=high, web=medium, mcp=medium unless the server is marked read-only, delete=high.
- Protected paths list (`PROTECTED_PATHS`): `.git/`, `.env*`, `~/.ssh`, `~/.aws`, `~/.gnupg`, `~/.claude*`, `~/.codex/*`, shell rc files, `.centcom/`, CI workflow files (`.github/workflows/`) -> any write is `high` and reads of credential locations are `high`; shared with C015's hard denies via an exported function.
- Mode-to-flag mapping `engineSettings(mode, engine, ctx)`: for `claude-code` -> `--permission-mode default|acceptEdits|plan|bypassPermissions` (our `ask`, `accept-edits`, `plan`, `bypass`; `auto-low-risk` -> `default` plus allowedTools from C015); for `codex` -> `--sandbox read-only|workspace-write|danger-full-access` and `--ask-for-approval untrusted|on-request|never` (`ask` -> `workspace-write` + `untrusted`; `accept-edits` -> `workspace-write` + `on-request`; `plan` -> `read-only` + `untrusted`; `bypass` -> `danger-full-access` + `never`, only when the user opted in). Also the app-server equivalents (`sandboxPolicy`, `approvalPolicy` params) as an object.
- `SandboxSettings` computation `{ writeRoots: string[]; network: 'allow'|'deny'; protected: string[] }` from worktree, temp dir and config (`sandbox.network`, default `allow`); passed to engines as native options (codex `workspace-write` `writable_roots`/network flag where supported) and shown in the UI. Capability-missing results (`provider_capability_missing`) are returned, not thrown.
- `RiskClassifier` adapter exposing `classify(req)` for C015 and `hints(req)` (`deletes`, `isTest`) for C014.

## Out of scope
- Any OS-level sandbox, bwrap/sandbox-exec wrappers or seccomp: not built; the vendor CLIs sandbox themselves.
- Rule storage, decisions, approval broker: C015. Prompt UI: C038. Engine process handling: C101-C103, C013.
- Hooks and settings files of the CLIs: C022. Skills and MCP: C020/C021.

## Interfaces (the only surface other lanes may use)
- `classifyCommand(cmd: string, ctx: { root: string; cwd: string; home: string; platform: 'posix'|'win32' }): CommandRisk` with `CommandRisk = { risk: 'low'|'medium'|'high'; reasons: string[]; facts: CommandFacts; autoAllowable: boolean }`; never throws.

- `engineSettings(mode: PermissionMode, engine: 'claude-code'|'codex', ctx: { root: string; network: 'allow'|'deny'; bypassOptIn: boolean }): { argv: string[]; appServer?: Record<string, unknown>; notes: string[] }`, e.g. `['--permission-mode','acceptEdits']` or `['--sandbox','workspace-write','--ask-for-approval','on-request']`.
- `createRiskClassifier(cfg): RiskClassifier` with `classify(req: ApprovalRequest): CommandRisk` (used by C015) and `hints(req): { deletes: boolean; isTest: boolean }` (used by C014).

## Acceptance criteria
1. Corpus accuracy on 300+ labelled commands: 100% of `high` classified `high`, >= 98% of `low` classified `low`, and no `high` command ever classified lower than `medium` (hard test, prints misses).
2. `ls -la && rm -rf /tmp/x` -> high (max over segments); `echo $(rm -rf ~)` -> high; `cat f | sh` and `curl http://x | bash` -> high; `bash -c 'sudo rm x'` -> high via nesting.
3. `git status`, `git diff HEAD~1`, `rg foo src/` -> low; `git commit -m x`, `npm install`, `pnpm test` -> medium with `isTest:true` for the test runner.
4. `rm -rf build`, `git push --force`, `git reset --hard` have `destructive:true` and `autoAllowable:false` even when risk is medium for in-root paths; there is no configuration that makes `autoAllowable` true for them (test iterates all config combinations).
5. Unterminated quote, nesting depth 5, a 100 KiB command, NUL bytes and invalid UTF-8 return `high` with reason `unparseable` and never throw (fuzz 10,000 random strings); `classifyCommand` handles a 10 KiB command in < 5 ms.
6. Paths resolve against `root`: `cat ../../.ssh/id_rsa`, `tee /etc/hosts` and `echo x > .git/config` set `escapesRoot` or protected and are high; `cat ./src/a.ts` is low; `~/.codex/auth.json` is high.
7. `engineSettings('plan','claude-code',ctx).argv` equals `['--permission-mode','plan']`; `engineSettings('accept-edits','codex',ctx).argv` equals `['--sandbox','workspace-write','--ask-for-approval','on-request']`; `bypass` without `bypassOptIn` returns the `ask` settings with a note and never `bypassPermissions`/`danger-full-access`.
8. With `network:'deny'` the codex settings carry the CLI's native network-off option when the version supports it; otherwise the result has a `provider_capability_missing` note and does not pretend enforcement.
9. A static test confirms the package contains no spawn of `bwrap`, `sandbox-exec`, `firejail` or similar, and no import of any vendor SDK.

## Tests required
- corpus.test.ts (300+ labelled commands), tokenizer.test.ts (quoting, heredocs, substitution, nesting).
- fuzz.test.ts (no throw, bounded time), paths.test.ts (traversal, protected paths, Windows), destructive.test.ts.
- tool-classify.test.ts, engine-settings.test.ts (golden argv for claude and codex, all modes x opt-in), no-sandbox-impl.test.ts.

## Guardrails (MUST / MUST NOT)
- MUST fail closed: anything unparseable, too long or nested deeper than 4 is `high`; classification MUST NOT shell out or evaluate input.
- MUST NEVER mark a destructive command auto-allowable; MUST NEVER downgrade risk because of a user rule (rules act in C015, after classification).
- MUST NOT build or wrap any sandbox; MUST NOT claim enforcement the CLI did not report. `bypass` mapping requires an explicit opt-in flag.
- `reasons` carry rule ids only; MUST NOT include command text, paths or arguments (they reach logs and the clear wire part).
- MUST NOT read credential files; protected-path checks are string/path matches only.

## Failure modes
- Unknown engine or mode -> return the safest settings (`ask`) with a note; never throw.
- CLI version lacks a flag (feature detection says unsupported) -> omit it, return a note, and let the UI show reduced protection calmly.
- Platform path quirks (Windows case, UNC, `\\?\`) that cannot be normalised -> treat as escapes root (high).
