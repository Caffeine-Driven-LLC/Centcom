## Goal
One typed, validated configuration object built from five layers (defaults, user file, project file, environment, CLI flags) with a defined precedence, safe handling of project-supplied config, and a way to explain where each value came from.

## In scope
- Precedence low to high: built-in defaults < user file < project file < environment < flags. Later layers override per key (deep merge for objects, replace for arrays).
- User file `config.json` in `$CENTCOM_CONFIG_DIR`, else `$XDG_CONFIG_HOME/centcom/` (Linux), `~/Library/Application Support/centcom/` (macOS), `%APPDATA%\centcom\` (Windows). Project file `.centcom/config.json` found by walking up from cwd to the git toplevel (max 25 levels).
- Key set with defaults: `api.base_url`=`https://api.centcom.dev`, `relay.url`=`wss://relay.centcom.dev/v1/ws`, `net.timeout_ms`=15000, `net.max_attempts`=5, `telemetry.enabled`=false, `log.level`=`info`, `log.max_file_bytes`=5242880, `log.max_files`=3, `ui.theme`=`auto`, `ui.mascot`=true, `ui.reduced_motion`=false, `lan.enabled`=true, `agent.max_parallel`=4, `agent.approval_timeout_ms`=600000.
- Environment mapping: `CENTCOM_API_URL`, `CENTCOM_RELAY_URL`, `CENTCOM_LOG_LEVEL`, `CENTCOM_TELEMETRY` (`on`|`off`), `DO_NOT_TRACK`, `CENTCOM_CONFIG_DIR`, `CENTCOM_STATE_DIR`, `NO_COLOR`, `CENTCOM_REDUCED_MOTION`.
- Schema validation with a JSON Schema compiled by Ajv standalone (own schema, not a wire contract); unknown keys warn and are ignored (forward compatible); wrong types are errors.
- Project-file allow-list: a project file may set only `ui.*`, `agent.max_parallel`, `agent.approval_timeout_ms`, `log.level`. Keys `api.*`, `relay.*`, `telemetry.*`, `net.*`, `lan.*` from a project file are ignored with a warning (a cloned repo must not redirect traffic or enable telemetry).
- `explain(cfg, key)` returning the winning layer and file path; `writeUserConfig(patch)` doing an atomic write (temp file + rename) with mode 0600 and creating the directory with 0700.

## Out of scope
- Secrets and tokens (keychain access): later auth lane; this lane must refuse them in files.
- CLI flag parsing and the `centcom config` subcommand: CLI lanes (this lane takes an already-parsed flag object).
- Logging: lane C005. Telemetry opt-in behaviour beyond reading the key: lane C010.

## Build against (no counterpart needed)
Pure filesystem + env input: tests use an in-memory fs adapter and fake env/platform passed through `LoadDeps`. No network.

## Deliverables
- `packages/net/src/config/`
- `docs/configuration.md`

## Interfaces (the only surface other lanes may use)
- `export interface LoadDeps { cwd: string; env: Record<string,string|undefined>; platform: NodeJS.Platform; homedir: string; fs: ConfigFs; warn: (code: string, key?: string) => void }`
- `loadConfig(deps: LoadDeps, flags?: Partial<FlatFlags>): Promise<ResolvedConfig>` where `ResolvedConfig` is a deeply readonly typed object (`cfg.api.base_url`).
- `explain(cfg: ResolvedConfig, key: string): { layer: 'default'|'user'|'project'|'env'|'flag'; source?: string }`.
- `writeUserConfig(deps, patch: DeepPartial<UserConfig>): Promise<void>`; `userConfigPath(deps): string`; `stateDir(deps): string`.
- `class ConfigError extends Error { kind: 'invalid_value'|'secret_in_file'|'unreadable'|'parse'; key?: string }` (client-local, never on the wire).

## Acceptance criteria
1. With all five layers setting `log.level`, the flag wins; removing the flag the env wins; then project; then user; then the default `info` (5 tests).
2. A project file containing `{"api":{"base_url":"https://evil.example"},"ui":{"mascot":false}}` yields `api.base_url` unchanged, `ui.mascot=false`, and exactly one warning with code `project_key_ignored` and key `api.base_url`.
3. `DO_NOT_TRACK=1` or `CENTCOM_TELEMETRY=off` forces `telemetry.enabled=false` even if user file and flags say true.
4. A file containing any key whose name matches `/token|secret|password|api_?key|private/i` makes `loadConfig` throw `ConfigError{kind:'secret_in_file'}` naming the key but not its value.
5. Invalid JSON in the user file throws `ConfigError{kind:'parse'}` with file path and line/column; an unreadable (EACCES) file throws `kind:'unreadable'`; neither crashes with a raw stack.
6. `writeUserConfig` leaves the original file intact if the process is killed between temp write and rename (simulated with a failing rename) and creates files with mode 0600 (POSIX).
7. `loadConfig` completes in < 20 ms with all layers present on CI (no network, no synchronous scan beyond 25 parents).
8. Walking up never leaves the git toplevel: a `.centcom/config.json` in the parent of the repo is not read.

## Tests required
- precedence.test.ts (all pairwise layer orders), project-allowlist.test.ts, env-mapping.test.ts, secret-guard.test.ts.
- atomic-write.test.ts with an injected failing `rename`, file-mode test on POSIX only.
- explain.test.ts and a property test that merge never mutates its inputs.

## Guardrails (MUST / MUST NOT)
- MUST NOT read credentials from config; MUST reject secret-named keys in any file (refresh tokens live only in the OS keychain).
- MUST ignore network/telemetry/endpoint keys in project config; MUST NOT trust a repo-supplied value for anything that changes where data is sent.
- MUST honour `DO_NOT_TRACK=1` and `CENTCOM_TELEMETRY=off` over every other source.
- MUST NOT block startup on an unreachable backend: loading config never touches the network.
- MUST inject `fs`, `env`, `platform`, `cwd`; MUST NOT read `process.env` or call `os.homedir()` outside the entry adapter.
- Error messages MUST NOT include config values for secret-like keys or full home paths in logs.

## Failure modes
- Config dir not writable -> `writeUserConfig` throws `ConfigError{kind:'unreadable'}`; reads still work and the app runs on defaults.
- Unknown key or future version of the file -> warning `unknown_key`, value ignored, app continues.
- Two processes write at once -> last rename wins, file never partially written.
## Notes
Local-only error identifiers (`ConfigError.kind`) are not in errors.json and never go on the wire. Defaults for `agent.*` are product choices, not contract values. Placement under packages/net is a layout workaround (see C001 notes).

## Definition of done
