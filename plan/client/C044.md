## Goal
Show short, non-blocking toasts above the prompt and turn server `sys.notice` frames into local-copy notices, with queueing, de-duplication and persistence rules that never hide something the user must act on.

## In scope
- `<ToastLine>` one row above the prompt: prefix glyph `✓` success, `!` warning, `✗` error, `i` info (ASCII same), text from the message table, optional action hint (`[u] upgrade`), dismissible with `esc` when focus rules allow.
- `ToastController`: `show({level, text, key?, actions?, ttlMs?})`, one visible at a time, FIFO queue capped at 20 (oldest `info` dropped first), default ttl 4,000 ms, severity preemption (an `error` replaces a visible `info` or `success`, which is requeued).
- Persistence rule: toasts carrying actions, and notices with level `error`, never auto-dismiss (DESIGN §16.2); they stay until dismissed or resolved.
- De-duplication: same `key` within 60 s increments a counter `(x3)` instead of stacking.
- Notice mapping `noticeToToast(p: {code, level, params})` for the `sys.notice` codes `usage_warning`, `quota_reached`, `plan_changed`, `member_limit_near`, `maintenance_soon`, `client_update_available`, `history_retention_changed`, using a local message table (DESIGN §13.3 style); unknown codes show the generic message `i Notice received.` and are logged at debug.
- Message table `packages/tui/src/toast/messages.ts` with parameter formatting (`pct`, `resets_at` as local time, `minutes`, `version`).

## Out of scope
- Receiving `sys.notice` frames (net lane) and emitting OS or push notifications (notification lanes).
- Billing flows behind action hints (the hint only emits `onAction`).
- Sound cues (DESIGN §15 sound is off by default and out of scope here).
- Mascot reactions to notices (lane C046).

## Interfaces (the only surface other lanes may use)
- `interface ToastController { show(t: ToastInput): string; dismiss(id?: string): void; subscribe(fn: (t: Toast | null) => void): () => void }`; `type ToastInput = {level: 'info'|'success'|'warn'|'error'; text: string; key?: string; actions?: {key: string; label: string; id: string}[]; ttlMs?: number}`

## Acceptance criteria
1. A success toast stays 4,000 ms (+/-50 ms fake clock) then disappears; two toasts queued within 100 ms display sequentially, the second after the first clears.
2. An `error` toast arriving while an `info` toast is visible replaces it immediately and the info toast is shown afterwards if still within its remaining ttl.
3. A toast with an action never auto-dismisses; `esc` dismisses it and emits `toast.dismissed` on the bus.
4. Posting the same `key` 3 times in 10 s shows one toast with `(x3)`.
5. `noticeToToast({code:'usage_warning', level:'warn', params:{pct:82, resets_at:'2026-11-01T00:00:00.000Z'}})` produces text `Usage is at 82% of this month's quota. Agents pause at 100%.` and level warn; `quota_reached` produces an error-level persistent toast with `resets_at` rendered in local time.
6. All 7 notice codes in the contract table map to a non-generic message; an unknown code maps to the generic message and does not throw; the server never supplies display text.
7. Queue cap: after 25 rapid `info` toasts, 20 are retained (newest) and no `warn`/`error` toast is ever dropped.
8. Under `NO_COLOR` the glyph prefix (`✓ ! ✗ i`) carries the level; text contains no ANSI colour codes.
9. A toast longer than the width is truncated with `…`, never wrapped.

## Tests required
- toast/controller.test.ts: ttl, queue, preemption, dedupe, cap with fake clock.
- toast/notices.test.ts: every sys.notice code and unknown code; locale time formatting.
- toast/render.test.ts: snapshots per level at 80x24, NO_COLOR.
- toast/keys.test.ts: esc dismissal and focus-context rules.

## Guardrails (MUST / MUST NOT)
- MUST render notices only from the local message table keyed by `code`; never display server-provided strings (CT-WS-SESSION-EVENTS Notices).
- MUST NOT auto-dismiss anything that requires user action (DESIGN §16.2).
- MUST NOT steal `esc` from the interrupt action: while an agent is running, `esc` interrupts (lane C030) and toasts dismiss on timeout or with `ctrl+x`; the focus-context rule is tested.
- MUST sanitise any interpolated parameter (versions, names) before display.
- MUST NOT show more than one toast at a time (DESIGN §10.1.8).
- MUST call the screen-reader hook `onShow` for every toast so lane C049 can announce it.

## Failure modes
- Invalid `resets_at` -> omit the time phrase and keep the rest of the message.
- Controller disposed while a toast is visible -> timers cleared, no late callbacks.
## Notes
Conflict flagged: DESIGN says toasts are dismissible with `esc`, and esc also interrupts the agent (DESIGN §22.2). This card gives interrupt priority while an agent runs and adds `ctrl+x` as the dismiss key in that case; design should confirm. `usage_warning` and `quota_reached` mirror CT-ENTITLEMENTS warnings/limits.
