## Goal
Centcom keeps its own append-only transcript of every agent session, built from normalised engine events, so the UI can render history and LAN/relay snapshots can be built even if a CLI's private session store changes; `centcom --resume` maps a Centcom session to the engine's session id and continues it by passing the engine's own resume option.

## In scope
- Append-only JSONL log per session under the data dir from lane C004 (`<data>/sessions/<ses_id>/log.jsonl`), fed by subscribing to normalised engine events on the bus (lane C025, event names from lane C101); dirs 0700, files 0600.
- Every record passes the redaction helper of lane C005 using `contracts/fixtures/providers/secret-patterns.json` before it is written; tool inputs/outputs are stored as the normalised display summary (cap 8 KiB per field), never raw environment or credential material.
- Session index `<data>/sessions/index.json` (id, cwd, branch, title = first user message cut to 80 chars, created_at, updated_at, message_count, engines used, last model) rewritten atomically and rebuildable by scanning logs.
- Engine session map: `engineSessions: {engine: 'claude-code'|'codex', engineSessionId: string, since: seq}[]` recorded from the `session.started` normalised event (Claude Code: the `session_id` from `system/init` and the final `result`; Codex: the thread id). A Centcom session may hold several engine sessions (after a fresh start or an engine switch).
- Resume: `resumeSession(id)` loads the log, then asks the engine through `AgentEngine.start({resume: {engineSessionId}})` (lane C101; Claude Code `--resume <session_id>`, Codex `codex exec resume SESSION_ID` / app-server thread resume). The transcript UI always renders from Centcom's log, not from the CLI's store.
- CLI: `centcom --resume [id]` (no id = picker of last 20 sessions), `centcom --continue`/`-c` (newest session whose cwd matches; maps to the engine's `--continue` only when the engine reports capability `resume`), slash `/resume [id]` via the lane C035 registry.
- Corruption recovery, size limits and retention: torn-last-line recovery, 64 MiB segment roll, 1 MiB line cap, single-writer lock file, retention pruning (`session.retentionDays`, default 30).
- Versioned header `{"fmt":"centcom.localsession","v":2}`; unknown fmt/v refused with a one-line message. Snapshot export helper `toSnapshotEvents(id, {fromSeq})` yields normalised events for the LAN/relay session lanes.

## Out of scope
- Running or resuming the engine process itself (lanes C013, C102, C103); this lane only supplies the engine session id and reads the `resume` capability.
- Reading or copying the CLIs' own stores (`~/.claude/projects/*`, `~/.codex/sessions/*`): forbidden by CT-PROVIDER rule 1; only ids reported by the CLI's events are kept.
- Checkpoints and file rewind (lane C027); this lane exposes `markRewind`/`forkFrom` only.
- Hosted-session history, replay buffer and snapshot upload (net/session lanes); the local format is separate from `centcom.snapshot`.
- Rendering a resumed transcript (lane C036) and the picker beyond a plain list.

## Interfaces (the only surface other lanes may use)
- `interface SessionStore { create(init: {cwd: string; branch?: string}): Promise<SessionHandle>; open(id: string): Promise<LoadedSession>; list(q?: {cwd?: string; limit?: number}): Promise<SessionSummary[]>; remove(id: string): Promise<void>; prune(now: Date): Promise<{removed: number}> }`
- `interface SessionHandle { id: string /* ses_<ULID> */; append(ev: NormalisedEvent): void; recordEngineSession(m: EngineSessionRef): void; markRewind(toSeq: number): Promise<void>; flush(): Promise<void>; close(): Promise<void> }`
- `type EngineSessionRef = {engine: 'claude-code'|'codex'; engineSessionId: string; sinceSeq: number}`; `type LogRecord = {n: number; at: string; agent_id?: string; type: string; data: unknown}` (`n` per-log counter, not the relay `seq`).
- `resumeSession(deps: {store: SessionStore; engines: EngineRegistry; log: Logger}, id: string, opts?: {agentId?: string}): Promise<ResumeOutcome>` where `ResumeOutcome = {mode: 'engine-resumed'|'fresh-with-summary'|'read-only'; engineSessionId?: string; reason?: string}`
- `createSessionStore(deps: {dataDir: string; clock: Clock; bus: EventBus; redact: (s: string) => string; log: Logger}): SessionStore`
- CLI flags `--resume [id]`, `--continue`/`-c`; slash `/resume [id]`; config `session.retentionDays` (30), `session.persist` (true).

## Acceptance criteria
1. Records flush every 250 ms or 50 records; `kill -9` during a 1,000-record burst leaves a log whose valid prefix loads and loses at most the last 250 ms of records.
2. A log whose last line is truncated JSON loads, the torn line is dropped, a `{type:'recovered'}` record is appended and earlier bytes are not rewritten; truncating a valid log at every byte offset always loads the longest valid prefix.
3. Replaying the recorded Claude Code golden transcript stores `engineSessions[0] = {engine:'claude-code', engineSessionId:<id from the init event>}`; `resumeSession` starts the stub engine with exactly `resume.engineSessionId` equal to it.
4. When the engine lacks capability `resume`, or rejects the id (stub returns `provider_capability_missing` / session-not-found), `resumeSession` returns `mode:'fresh-with-summary'` (a new engine session whose first prompt carries a summary of the last 40 normalised messages, capped at 8 KiB) and the UI notice says so; the old transcript stays visible and a new `engineSessions` row is appended.
5. Feeding a record containing `sk-ant-api03-AAAAAAAAAAAAAAAAAAAAAAAA` and a `"refresh_token":"<20+ chars>"` JSON fragment in a tool output writes `[redacted:anthropic_api_key]`/`[redacted:codex_auth_json]` and none of the `must_match` strings of secret-patterns.json appear in any file of the session dir.
6. A second process opening a session with a live lock (pid alive) fails with typed error and hint `session in use`; a stale lock is taken over. Session ids match `^ses_[0-9A-HJKMNP-TV-Z]{26}$`.
7. A log over 64 MiB rolls to `log.1.jsonl`, `log.2.jsonl`; `open()` reads all segments in order; a single record over 1 MiB is stored truncated with `data.truncated=true`; the writer buffer never exceeds 1,000 records or 8 MiB.
8. `centcom --continue` with two stored sessions in the cwd picks the newest `updated_at`; with none it exits 1 with `No session to continue in this directory.`; an unknown header fmt/v throws `UnsupportedSessionFormat` and prints one line without a stack.
9. Deleting `index.json` and calling `list()` rebuilds it from 500 sessions of 1,000 records in under 2 s; `prune()` never removes a locked session.
10. `toSnapshotEvents(id, {fromSeq: 10})` returns only normalised events with n >= 10, in order, equal to the fixture golden output.

## Guardrails (MUST / MUST NOT)
- MUST NOT read or copy any file in `~/.claude*` or `~/.codex/*`; engine session ids come only from events the CLI emits (CT-PROVIDER rule 1).
- MUST NOT store credentials, tokens, environment dumps or raw tool secrets; redaction runs before the write and again over `toSnapshotEvents` output.
- MUST create dirs 0700 and files 0600 and refuse symlinked session directories; transcripts contain source code and prompts.
- MUST keep the log append-only: a rewind appends a `rewind` record, never edits earlier lines.
- MUST NOT put message bodies, paths or branch names in the structured application log (GUIDELINES 3.5).
- MUST NOT import `@anthropic-ai/*` or `openai` packages or anything from packages/net or packages/session; the store works offline and without any CLI installed.

## Failure modes
- Disk full or EACCES while flushing -> keep records in the buffer up to the cap, emit one bus event `session.persist_failed`, one warning toast, continue the live session without persistence.
- Engine rejects the resume id (CLI session expired or removed) -> load the transcript read-only or continue as `fresh-with-summary`, show the tool's own error text verbatim in a calm frame, never retry in a loop.
- Index and logs disagree -> drop the stale row on `list()` and log at debug.
- Engine session ids missing from the event stream (older CLI) -> session still persists and renders; resume offers fresh-with-summary only.
## Notes
Format v2 supersedes the earlier SDK-based design (no `sdk_session_id`). Event names (`session.started`, `usage.report`, ...) must match lane C101. Local ids reuse the `ses_` prefix but are never sent to a server.
