## Goal
Install, update and remove the bundled Centcom skills pack as plain files the engines load natively: SKILL.md folders under `.claude/skills/` for Claude Code and a delimited Centcom section in `AGENTS.md` for Codex, always with a diff preview and user confirmation. Centcom executes nothing from a skill.

## In scope
- Bundled pack under `packages/agent/skills/<name>/SKILL.md` (5 skills: `commit-message`, `code-review`, `test-writer`, `pr-description`, `handoff-notes`) with frontmatter `name`, `description`; each < 4 KiB, plain English, no scripts, no URLs that fetch code; plus `packages/agent/skills/manifest.json` `{ pack_version, skills: { <name>: { sha256, bytes } } }`.
- Targets: Claude Code project scope `<repo>/.claude/skills/<name>/SKILL.md`, user scope `~/.claude/skills/<name>/SKILL.md` (path supplied by the engine adapter, never discovered by reading credential files); Codex: a section in `<repo>/AGENTS.md` (project) or the user-level AGENTS.md path supplied by the adapter, delimited by `<!-- centcom:skills:begin v=<pack_version> sha256=<hex> -->` and `<!-- centcom:skills:end -->`; content outside the markers is never touched.
- Operations `plan(op)` -> `Plan { changes: FileChange[]; diff: string }` and `apply(plan, confirmation)`: install, update (pack_version or checksum differs), remove (only files whose sha256 still matches what Centcom installed; edited files are reported `modified` and left alone unless the user confirms), status (`not_installed|current|outdated|modified`).
- Install record `.centcom/skills-installed.json` (project) / `<config dir>/skills-installed.json` (user): `{ pack_version, installed: { <path>: sha256 } }`, used for checksums and clean removal.
- Scope choice `project|user` per engine; default project; user scope requires a second explicit confirmation line naming the directory class (not the path).
- Listing of skills the engine reports as loaded (from the engine status event, capability `skills`) next to what Centcom installed, so mismatches are visible.
- Atomic writes (temp + rename), directories 0755, files 0644; refuses to write through symlinks and any path escaping the target root (realpath check).

## Out of scope
- Loading, ranking or injecting skills into prompts: the engines do that natively (Claude Code `.claude/skills/`; Codex reads `AGENTS.md`).
- A skill marketplace or remote fetching (v1: bundled pack only). Executing scripts referenced by skills: engine plus permissions (C015).
- Editing memory files in general: C023. Writing hooks or MCP config: C022, C021.
- Reading or writing any credential or auth file of either CLI.

## Build against (no counterpart needed)
Temp-dir filesystem fixtures, the bundled pack, and FakeEngine (C101) emitting an engine status event that lists loaded skills; no real CLI, no network.

## Interfaces (the only surface other lanes may use)
- `createSkillsInstaller(deps: { fs: SkillFs; bundledDir: string; engines: { targetDirs(engine: EngineId, scope: 'project'|'user', root?: string): { skillsDir?: string; agentsMd?: string } }; log: Logger }): SkillsInstaller`
- `interface SkillsInstaller { status(scope, root?): Promise<SkillsStatus>; plan(op: { kind: 'install'|'update'|'remove'; engines: EngineId[]; scope: 'project'|'user'; skills?: string[]; root?: string }): Promise<SkillsPlan>; apply(plan: SkillsPlan, confirm: { accepted: true; planHash: string }): Promise<ApplyReport> }`
- `interface SkillsPlan { planHash: string; changes: { path: string; action: 'create'|'update'|'delete'|'skip_modified'; before?: string; after?: string }[]; diff: string }`; `SkillsStatus = { pack_version: string; per: { engine: EngineId; skill: string; state: 'not_installed'|'current'|'outdated'|'modified' }[] }`.
- CLI: `centcom skills status|install|update|remove [--scope project|user] [--engine claude|codex] [--yes]` (`--yes` still prints the diff).

## Acceptance criteria
1. `plan({kind:'install', engines:['claude-code'], scope:'project'})` on an empty repo lists 5 `create` changes under `.claude/skills/` and `apply` with the matching `planHash` writes exactly 5 files; a wrong `planHash` writes nothing and throws `PlanChanged`.
2. Codex install inserts one marker-delimited block into `AGENTS.md`; with 40 lines of user text before and after, those lines are byte-identical afterwards; a second install with an unchanged pack yields an empty change list.
3. After the user edits an installed `SKILL.md`, `status` reports `modified`, `update` and `remove` return `skip_modified` for that file and delete or overwrite nothing without an explicit per-file confirmation.
4. Updating from `pack_version` 1.0.0 to 1.1.0 changes only files whose manifest sha256 differs and records the new checksums in the install record.
5. A skills directory that is a symlink to outside the repo, or a skill name `../x`, is refused with `UnsafePath` and nothing is written.
6. `apply` without `confirm.accepted === true` writes nothing (fs mock write count 0); `--yes` prints the full diff before applying.
7. All 5 bundled skills pass validation (name `^[a-z0-9][a-z0-9-]{0,39}$` equals directory, description 1..300 chars, body <= 4 KiB) and total pack size < 20 KiB.
8. No code path spawns a process: the module's imports contain no `child_process` (lint test).

## Guardrails (MUST / MUST NOT)
- MUST NOT write, change or delete anything without a shown diff and an explicit confirmation bound to the plan hash.
- MUST NOT execute any content of a skill or spawn any process; Centcom only copies files.
- MUST NOT touch bytes outside the Centcom markers in `AGENTS.md` or files it did not install (checksum mismatch means hands off).
- MUST NOT read or write `~/.claude` or `~/.codex` internals other than the documented skills directory and AGENTS.md path given by the engine adapter; never read credential files.
- MUST NOT log file contents or absolute paths; log counts, skill names and reason codes.

## Failure modes
- Target directory unwritable (EACCES) -> that change fails with `unwritable`, other changes roll back (all-or-nothing per engine), message with next step.
- Install record missing or corrupt -> treat everything as `modified` (conservative), offer a re-baseline after diff review.
- Engine not installed or capability `skills` absent -> installation still allowed as plain files; status notes that the engine did not confirm loading.
## Notes
Skills format follows the verified Claude Code convention (SKILL.md in `.claude/skills/`). Codex has no skills directory in the facts we verified, so guidance goes into AGENTS.md. Marketplace stays out of v1 (ARCHITECTURE section 8).
