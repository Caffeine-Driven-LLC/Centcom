## Goal
Discover, validate and expose agent skills (Markdown instruction packs) from project, user and bundled locations, with progressive disclosure so only names and descriptions cost context until a skill is used. Ship a small bundled pack.

## In scope
- Skill format: directory `<name>/SKILL.md` with YAML-lite frontmatter (`name`, `description`, optional `allowed_tools`) and a Markdown body; optional `references/` text files.
- Search order and precedence: project `.centcom/skills/`, user `<config dir>/skills/`, bundled `packages/agent/skills/`; same name -> project beats user beats bundled; shadowing is reported in `list()` output.
- Validation: `name` `^[a-z0-9][a-z0-9-]{0,39}$` equal to the directory name; `description` 1..300 chars; SKILL.md <= 64 KiB; reference files <= 256 KiB each, max 20; no symlinks resolving outside the skill dir; UTF-8 only; invalid skills are skipped with a reported reason.
- `skillsPromptSection(maxChars = 2000)` rendering only name + description lines; `render(name)` returning the full body on demand (the agent loads it via a tool / prompt injection decided by the runner).
- Frontmatter `allowed_tools` is advisory metadata for the permission engine (it can only narrow, never grant).
- Bundled pack (5 skills): `commit-message`, `code-review`, `test-writer`, `pr-description`, `handoff-notes` -- plain instructions, no scripts, written in English, each < 4 KiB.
- Project skills are data, not code: nothing in a skill is executed by this lane.

## Out of scope
- A marketplace / install command / remote fetching of skills (non-goal for v1).
- Executing scripts referenced by skills: any execution goes through the permission engine (C015).
- Wiring skills into the SDK request: runner (C013) calls this lane's API.

## Build against (no counterpart needed)
Filesystem fixtures in a temp dir and the bundled pack; no network.

## Deliverables
- `packages/agent/src/skills/`
- `packages/agent/skills/`
- `docs/skills.md`

## Interfaces (the only surface other lanes may use)
- `createSkillRegistry(deps: { fs: SkillFs; dirs: { project?: string; user?: string; bundled: string }; log: Logger }): SkillRegistry`
- `interface SkillRegistry { reload(): Promise<LoadReport>; list(): SkillMeta[]; get(name: string): Promise<Skill | undefined>; promptSection(maxChars?: number): string }`
- `interface SkillMeta { name: string; description: string; source: 'project'|'user'|'bundled'; shadows?: ('user'|'bundled')[]; allowedTools?: string[] }`; `interface Skill extends SkillMeta { body: string; references: string[] }`.
- `LoadReport = { loaded: number; skipped: { dir: string; reason: string }[] }` (reasons are enums, not paths with content).

## Acceptance criteria
1. A project skill named `code-review` shadows the bundled one; `list()` shows `source:'project'` and `shadows:['bundled']`.
2. Skills violating any rule (bad name, 301-char description, 65 KiB body, symlink to `/etc/passwd`, invalid UTF-8) are skipped and appear in `LoadReport.skipped` with distinct reason codes; the other skills still load.
3. `promptSection(2000)` never exceeds 2000 characters and drops lowest-precedence skills first; with 5 bundled skills it lists all 5 name+description lines.
4. The body of a skill is not present in `promptSection` output (test greps for a body-only sentinel).
5. `reload()` completes in < 100 ms for 50 skills on CI and is safe to call concurrently (second call awaits first).
6. Frontmatter `allowed_tools: [Bash]` never expands permissions: `get(name).allowedTools` equals the list but no function in this lane returns an 'allow' decision.
7. All 5 bundled skills pass validation and total size < 20 KiB.

## Tests required
- load.test.ts, precedence.test.ts.
- validation.test.ts (each rule), symlink-escape.test.ts.
- prompt-section.test.ts, bundled-pack.test.ts.
- reload-concurrency.test.ts.

## Guardrails (MUST / MUST NOT)
- MUST NOT execute anything from a skill, and MUST NOT interpret frontmatter beyond the documented keys.
- MUST reject symlinks and `..` path segments that escape the skill directory (realpath check).
- MUST NOT send skill content anywhere except the local agent request; skills may contain private project instructions.
- MUST NOT log skill bodies or absolute paths; log counts and reason codes.
- Bundled skills MUST contain no URLs that fetch/execute remote code and no secrets.

## Failure modes
- Skills dir missing -> empty list, no error.
- Unreadable file (EACCES) -> that skill skipped with reason `unreadable`.
- Huge directory (> 500 entries) -> stop after 500 and report `too_many` once.
## Notes
Format deliberately mirrors the common SKILL.md convention; no marketplace in v1 (ARCHITECTURE section 8).
