## Goal
Show file changes as a readable, collapsible unified diff in the terminal, with word-level highlights, line numbers and safe handling of hostile or huge input.

## In scope
- Unified-diff parser (`parseUnifiedDiff(text)`) and a two-string differ (`diffStrings(old, new, {context: 3})`) producing `DiffFile[]` with hunks and line records (`add|del|ctx`, old/new line numbers).
- `<DiffView files expanded onToggle width />` rendering per DESIGN §10.1.3: added lines `status.success` on `status.success.subtle` prefixed `+`, removed `status.danger` on `status.danger.subtle` prefixed `-`, context `text.secondary` with 3 lines either side, line numbers `text.muted` right-aligned in 5 columns.
- Word-level highlights for paired changed lines (tokenise on word/punctuation boundaries, LCS diff): changed spans rendered bold on a brighter background; skip pairing for lines over 2,000 chars.
- Collapse of long unchanged gaps to a row `⋯ 42 unchanged lines` (gap > 6 lines), expandable with `⏎` when focused; file header row `path  +12 −3`; binary files show `Binary file changed`; renamed files `old → new`.
- Caps: 2,000 rendered lines per file and 200 files per view with `⋯ N more lines` / `⋯ N more files` rows.
- Adapter from the `diff.share` secret payload (`files`, optional `blob`) and from local edit tool results to `DiffFile[]`.

## Out of scope
- Computing git diffs from the repository (runner/worktree lanes supply patch text).
- Interactive hunk staging, apply or revert actions, and side-by-side layout (not in v1).
- Fetching a `blb_` blob referenced by `diff.share` (net lanes); this lane receives text.
- Syntax highlighting.

## Interfaces (the only surface other lanes may use)
- `parseUnifiedDiff(text: string, limits?: {maxFiles?: number; maxLinesPerFile?: number}): DiffFile[]`
- `diffStrings(oldText: string, newText: string, opts?: {context?: number}): DiffFile`
- `type DiffFile = {oldPath?: string; newPath: string; status: 'added'|'deleted'|'modified'|'renamed'|'binary'; hunks: Hunk[]; adds: number; dels: number}`; `type DiffLine = {kind: 'add'|'del'|'ctx'; oldNo?: number; newNo?: number; text: string}`
- `<DiffView files: DiffFile[]; width: number; maxRows?: number; focusable?: boolean />`
- `fromDiffShare(files: unknown[]): DiffFile[]` (tolerates unknown shapes, returns what it can)

## Acceptance criteria
1. A 3-file golden diff renders at 80 columns with `+`/`-` prefixes, 5-column right-aligned line numbers, and no line longer than 80 columns (long lines wrap with a continuation indent of 7 columns).
2. Under `NO_COLOR` added/removed lines are distinguishable by the `+`/`-` prefix and word-level changes by reverse video; no colour SGR codes are emitted.
3. A hunk with 60 unchanged lines between changes shows `⋯ 54 unchanged lines` (3 context lines each side kept) and `⏎` on the focused row expands it in place.
4. Word-level highlight: changing `retryCount` to `retryLimit` on one line highlights only the differing span `Count`/`Limit` (assert on style ranges).
5. A 50,000-line diff parses in under 300 ms and renders 2,000 lines + `⋯ 48,000 more lines`; memory stays under 50 MiB (benchmark guard).
6. Binary patch (`Binary files a/x and b/x differ`) renders `Binary file changed`; a pure rename with 100 % similarity renders `old → new` with no hunks.
7. Terminal escape bytes inside diff content (`\x1b[2J`, `\x1b]0;title\x07`) never reach stdout raw; they appear as visible `␛` placeholders.
8. CRLF files and files without trailing newline render the marker `\ No newline at end of file` as a muted row.

## Tests required
- diff/parse.test.ts: golden diffs, renames, binary, no-newline, CRLF; fuzz test that arbitrary text never throws.
- diff/words.test.ts: LCS word diff cases and the 2,000-char cutoff.
- diff/render.test.ts: snapshots 80x24, 120x40, NO_COLOR, light theme.
- diff/collapse.test.ts: gap collapse and expansion.
- diff/limits.test.ts: size caps and benchmark.
- diff/diff-share.test.ts: `fromDiffShare` with the contract fixture and with unknown shapes.

## Guardrails (MUST / MUST NOT)
- MUST replace control characters and escape sequences in diff text with visible placeholders before rendering; diff content comes from untrusted repos and remote members.
- MUST NOT execute, apply or write anything; the component is display-only.
- MUST bound work: parsing and word-diffing are capped by the limits above so a hostile diff cannot hang the UI (word diff aborts after 5 ms per line pair).
- MUST NOT rely on colour alone: `+`/`-` prefixes are always present.
- MUST show paths as given but sanitised; do not resolve or open them.

## Failure modes
- Malformed diff text -> show the raw text in a muted block with the header `※ Couldn't parse this diff.` instead of throwing.
- `diff.share` file entries of unknown shape -> skip those entries, show `⋯ N files couldn't be shown`.
- Width below 40 -> render file headers and counts only, with `⋯ widen the terminal to see changes`.
## Notes
CONTRACT GAP: `diff.share` secret payload defines `files` as an array of unspecified objects (and an optional `blob`). This lane assumes entries like `{path, patch}` and degrades if the shape differs; the session lane that produces them must document the shape in a contract clarification.
