## Goal
A pure state machine that derives the contract's product state names from the normalised engine events (never from any SDK or CLI internals) and produces `agent.state` payloads that obey the contract's rate and dedupe rules. The same machine serves claude and codex.

## In scope
- Reducer `nextState(current, ev: NormalisedEvent | RunnerSignal, ctx): { state: AgentWireState; effects: Effect[] }` driven by the bus (C025) `agent:event` stream plus runner signals (`agent:exited`, interrupt, idle timers).
- Mapping table normalised event -> state (documented in docs/agent-states.md and encoded as data in `mapping.ts`): `turn.started` -> `prompt-received`; `thinking.delta` -> `thinking`; `text.delta` -> `streaming`; `tool.requested{kind:'read'}` -> `reading-file`; `{kind:'search'|'web'}` -> `searching`; `{kind:'edit'}` -> `editing-file`; `{kind:'create'}` -> `creating-file`; `{kind:'delete'}` or a command flagged `deletes` by C016 -> `deleting-file`; `{kind:'command'}` -> `running-command`; `{kind:'subagent'}` -> `sub-agent`; `{kind:'background'}` -> `background-task`; `{kind:'mcp'|'other'}` -> `tool-running`; `approval.requested` -> `awaiting-approval`; `approval.resolved{approve}` -> `approved`, `{deny}` -> `denied`; `question.asked` -> `asking-question`; `compaction.started` -> `compacting`; `turn.done{ok}` -> `success`; `turn.done{error}` -> `error`; `engine.warning` -> `warning`; plan-mode turn -> `planning`; `agent:exited{crash}` -> `crash`.
- Transient and timed states with an injected clock: `prompt-received` 600 ms, `approved`/`denied` 800 ms, `success` 2000 ms, then the last work state or `idle`; `awaiting-approval` and `asking-question` persist until resolved; `thinking` becomes `thinking-hard` after 15 s with no engine output; `idle` becomes `sleeping` after 15 min.
- Outcome refinements: a command event whose `isTest` hint (from C016 facts) finishes ok/fail -> `tests-pass`/`tests-fail`; worktree merge conflict signal -> `merge-conflict`; snapshot save signal -> `saving`.
- Parallel tool calls: when several `tool.requested` are open, the state is that of the most recently started open tool; closing it falls back to the previous open tool, then `thinking`.
- `StateEmitter`: never re-emits an identical consecutive state; at most 2 emissions per agent per second with trailing-edge coalescing; output is the clear payload `{agent_id, state, since}` only (`since` RFC 3339 ms UTC).
- Provider-aware client-local states (`provider-auth-required`, `provider-cap-reached`, `provider-policy-blocked`, connectivity, account, limits, social) are typed as `LocalUiState` and are NOT produced here, except that `provider_cap_reached`/`provider_rate_limited` engine errors are exposed as a `localHint` for the UI layer (C046) and the wire state stays `error` or `warning`.

## Out of scope
- Mascot animation selection and dwell rules: C046. Status line text: C039.
- Parsing CLI output into normalised events: engines C101-C103. This lane never sees raw CLI JSON.
- Approval brokering: C015. Command classification: C016 (only consumed as optional hints).
- Connectivity, account and social states, who-pays banners: other lanes (C105 and the session lanes).

## Interfaces (the only surface other lanes may use)
- `nextState(current: StateCtx, input: NormalisedEvent | RunnerSignal, now: number): { state: AgentWireState; effects: Effect[] }`
- `type AgentWireState` = the agent-level subset of CT-STATE-MAP keys; `const AGENT_WIRE_STATES: readonly AgentWireState[]`; `type LocalUiState` for client-local states.
- `createStateEmitter(deps: { clock: Clock; send: (p: { agent_id: AgentId; state: AgentWireState; since: string }) => void; onLocal?: (s: LocalUiState) => void }): { push(agentId: AgentId, s: AgentWireState): void; dispose(): void }`
- `attachStateMachine(bus: AgentBus, emitter: StateEmitter, opts?: { hints?: HintSource }): Disposable` subscribing to `agent:event` and `agent:exited`.
- `mapping.ts` exports `EVENT_STATE_TABLE` (data) so tests and docs read the same table.

## Acceptance criteria
1. Every value the machine can output is a member of `AGENT_WIRE_STATES` and a key of contracts/state-map.json (exhaustive test over all event kinds x tool kinds x current states: 0 violations).
2. Golden transcript `claude-edit-with-approval`: events turn.started, thinking.delta, tool.requested{read}, tool.requested{edit}, approval.requested, approval.resolved{approve}, turn.done{ok} yield exactly: prompt-received, thinking, reading-file, editing-file, awaiting-approval, approved, (800 ms) editing-file, success, (2000 ms) idle with the fake clock.
3. The same logical sequence replayed from a `codex` golden transcript yields the identical state list (engine-independence test, both transcripts in CI).
4. Emitter dedupe: 5 consecutive `thinking` pushes produce 1 send; 10 distinct states pushed inside 1 s produce at most 2 sends that second and the last send carries the latest state.
5. Every send payload validates against the generated `agent.state` clear-payload schema and has exactly the fields `agent_id`, `state`, `since`.
6. `thinking` with no engine output for 15 s becomes `thinking-hard`; 15 min idle becomes `sleeping`; a new `turn.started` wakes it (fake clock).
7. `agent:exited{outcome:'crash'}` from any state yields `crash` and the machine ignores later events until `dispose`; interrupt returns to `idle` within one tick.
8. Two overlapping `tool.requested` (read then command) show `running-command`; after the command closes the state is `reading-file` until that closes, then `thinking`.
9. A static test shows the module never outputs `offline`, `reconnecting`, `rate-limited`, `quota-reached`, `teammate-joins`, `provider-*`; an unknown `NormalisedEvent.type` or unknown tool kind maps to `tool-running`/no change without throwing.

## Tests required
- transitions.test.ts (table-driven from EVENT_STATE_TABLE), emitter.test.ts (dedupe, rate, coalescing).
- timers.test.ts, contract-parity.test.ts (state sets vs state-map.json).
- golden-transcripts.test.ts (claude and codex transcripts to identical state lists).
- property.test.ts: random event streams never emit an invalid state or exceed 2 sends per second per agent.

## Guardrails (MUST / MUST NOT)
- MUST derive states only from normalised events and runner signals; MUST NOT import from any engine package or inspect raw CLI JSON.
- MUST emit only keys from CT-STATE-MAP agent-level list; state names are not user copy.
- MUST NOT put tool names, paths, commands or model names in the `agent.state` payload (clear part carries only id, state, since).
- Unknown events and unknown enum values MUST be tolerated (debug log, no state change), never thrown.

## Failure modes
- Engine stream ends without `turn.done` -> treat as `error` after the runner's exit signal; never stay in `thinking` forever.
- Event arrives for a disposed agent -> ignored.
- Clock jumps backwards -> timers use monotonic ticks; no negative dwell, no duplicate emission.
## Notes
Table of event names is assumed from C101 (`turn.started`, `thinking.delta`, `text.delta`, `tool.requested{kind}`, `approval.requested/resolved`, `question.asked`, `compaction.started/ended`, `turn.done`, `engine.warning`); align to the final C101 names. CONTRACT GAP: none; provider-* states stay client-local per CT-STATE-MAP.
