## Goal
A runner that starts, drives, interrupts and stops Claude agents through the Claude Agent SDK, streams their output onto the internal bus, enforces concurrency and time limits, and can run as a local daemon so the TUI and CLI share agents. It also hosts the trust store used by MCP and hooks lanes.

## In scope
- `SdkAdapter` interface isolating `@anthropic-ai/claude-agent-sdk` (`query()` streaming input/output, `interrupt`, session resume id); `RealSdkAdapter` and a scriptable `FakeSdkAdapter` (emits canned assistant deltas, tool calls, permission requests, results, errors, crashes).
- `AgentRunner` with `start`, `get`, `list`, `stopAll`: one `AgentHandle` per agent (`agt_` id from the CT-IDS generator), prompt queue per agent (max 20 pending prompts), `send`, `interrupt` (SDK interrupt, then kill after 5 s), `stop`, and an async event stream. Emits `agent:*` events on the bus (C025): started, prompt, message_delta, message_done, tool_requested, tool_result, approval_needed, context, exited.
- Permission hook: the SDK `canUseTool` callback delegates to an injected `PermissionGate.check(req): Promise<GateDecision>` (implemented by lane C015); until provided the default gate denies everything except read-only tools.
- Limits: `agent.max_parallel` (config, default 4) enforced with a queue-or-reject policy (`start` rejects with `RunnerBusy` when full); startup timeout 30 s; overall per-turn watchdog 30 min (config); tool-approval waits bounded by `agent.approval_timeout_ms` (default 600 000) after which the tool is denied; event ring buffer 1000 per agent.
- Environment for the SDK subprocess is an allow-list (PATH, HOME, LANG, TERM, proxy vars, `ANTHROPIC_*` and Claude auth vars the SDK needs) -- Centcom tokens, `CENTCOM_*` secrets and the OS-keychain contents are never passed.
- Daemon mode `runnerd`: local-only IPC over a Unix domain socket (`$XDG_RUNTIME_DIR/centcom/runner.sock`, fallback `<state dir>/runner.sock`) or Windows named pipe `\\.\pipe\centcom-runner-<user>`, mode 0600, JSON-lines protocol with a version field and per-connection auth by file permissions plus a random 256-bit session secret in the runtime dir; commands `start|send|interrupt|stop|list|subscribe`. Single-instance lock; exits after 60 s with no agents and no clients.
- `TrustStore` (`<config dir>/trust.json`, atomic writes, 0600): `isTrusted(kind: 'mcp'|'hooks', sha256)`, `trust(kind, sha256, label)`, `revoke`; used by lanes C021 and C022 to gate project-supplied commands.

## Out of scope
- Permission policy and approval brokering: lane C015. Command classification: C016.
- State names for the UI/wire: C014. Worktrees: C017. Context compaction policy: C019.
- Skills, MCP, hooks, memory, sub-agents: lanes C020-C024.
- Anthropic credentials and login: delegated to the SDK; Centcom neither stores nor forwards them.

## Interfaces (the only surface other lanes may use)
- `createRunner(deps: { sdk: SdkAdapter; bus: AgentBus; gate: PermissionGate; ids: IdGenerator; clock: Clock; log: Logger; config: RunnerConfig }): AgentRunner`
- `interface AgentSpec { cwd: string; prompt: string; model?: string; permissionMode?: 'default'|'acceptEdits'|'plan'|'bypassPermissions'; mcpServers?: McpServerSpec[]; systemPromptAppend?: string; resume?: string; maxTurns?: number; parentAgentId?: AgentId }`
- `interface AgentHandle { id: AgentId; send(prompt: string): Promise<void>; interrupt(): Promise<void>; stop(): Promise<void>; events(): AsyncIterable<RunnerEvent>; status(): 'starting'|'running'|'waiting'|'exited' }`
- `interface PermissionGate { check(req: ToolUseRequest, ctx: { agentId: AgentId; signal: AbortSignal }): Promise<GateDecision> }` where `GateDecision = { behavior: 'allow'|'deny'; reason?: string; updatedInput?: unknown }`.
- `class RunnerBusy extends Error`; `interface TrustStore { isTrusted(kind, sha256): Promise<boolean>; trust(kind, sha256, label): Promise<void>; revoke(kind, sha256): Promise<void> }`.
- Daemon: `centcom-runnerd [--socket <path>] [--idle-exit-s 60]`; IPC frames `{ v: 1, id: string, cmd: string, args: object }` -> `{ v: 1, id, ok: boolean, result?: object, error?: { code: string } }`.

## Acceptance criteria
1. With the fake SDK, `start` then a scripted turn emits on the bus, in order: `agent:started`, `agent:prompt`, N x `agent:message_delta`, `agent:message_done`, `agent:exited{outcome:'ok'}`.
2. Starting a 5th agent with `agent.max_parallel=4` rejects with `RunnerBusy` immediately; after one agent exits the 5th can start.
3. `interrupt()` during a long scripted turn ends the turn within 1 s; if the fake ignores the interrupt the runner force-stops it after exactly 5 s (fake clock) and emits `agent:exited{outcome:'canceled'}`.
4. A tool request awaiting approval for `approval_timeout_ms` (600 000 ms, fake clock) is denied and the agent receives a tool-denied result; no leaked timers remain (`clock.pending() === 0` after stop).
5. The env passed to the SDK subprocess contains no variable starting `CENTCOM_` other than `CENTCOM_AGENT_ID`, and none matching `/TOKEN|SECRET|PASSWORD/i` (test with a poisoned parent env).
6. `runnerd`: second instance exits 1 with `already running`; the socket file has mode 0600 and dir 0700; a client lacking the session secret is rejected (`error.code = 'unauthorized'`) and disconnected; daemon exits within 61 s after the last agent stops with no clients.
7. Adapter crash (fake throws mid-stream) yields `agent:exited{outcome:'error'}` and the runner remains usable for other agents.
8. Trust store: `trust('mcp', h)` persists; a corrupted trust.json is treated as empty and a backup `trust.json.corrupt` is written; permissions 0600.

## Guardrails (MUST / MUST NOT)
- MUST route every tool use through `PermissionGate`; MUST fail closed (deny) if the gate throws, times out or is absent.
- MUST NOT pass Centcom tokens, keychain data or arbitrary parent env to the SDK subprocess (allow-list only).
- MUST NOT log prompts, assistant text, tool inputs or file paths; log ids, kinds, durations and counts.
- IPC MUST be local-only (Unix socket / named pipe, never a TCP port), permission-restricted, size-capped, and authenticated with the per-run secret.
- Agents run strictly inside the `cwd` given by the caller; the runner MUST NOT widen it or add parent directories.
- MUST work with no backend and no network except what the SDK itself needs: LAN and solo use never depend on the Centcom API.

## Failure modes
- SDK subprocess dies -> `agent:exited{outcome:'error'}` with a local error code, pending approvals are cancelled, other agents unaffected.
- Runner stopped with agents running -> `stopAll` interrupts all, waits 5 s, kills; resolves in <= 6 s.
- Daemon socket stale after crash -> new daemon checks liveness (connect with 500 ms timeout), removes the stale socket and starts.
## Notes
The 'agent runner daemon' is optional at runtime (the CLI may embed the runner in-process); the daemon exists so TUI and headless commands can share agents. Local IPC protocol is private to the client and is not a contract. Model names are never logged (they are secret fields on the wire). SPLIT? daemon/IPC could be a separate PR from runner core.
