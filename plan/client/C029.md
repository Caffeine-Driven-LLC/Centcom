## Goal
The client keeps an exact local ledger of tokens, estimated cost and active agent minutes per agent and session, raises cost alerts, and produces usage events in the shape CT-API-USAGE accepts for the later usage client to upload.

## In scope
- Ledger fed from bus events carrying provider usage (input, output, cache read/write tokens per turn) and from agent state transitions to compute active agent minutes (time in working states, excluding `idle`, `ready`, `sleeping`, `away`, `awaiting-approval`, `asking-question`).
- Cost estimate in integer micro-USD per turn using catalog prices from lane C028; exposed as `{amount, currency:'USD'}` minor-unit objects (CT-IDS money rules) for display.
- Per-agent, per-session and rolling-day totals; `snapshot()` for the status line (lane C039) and `/cost` slash command (one-screen table).
- Soft budget: config `budget.sessionUsd` (default unset); at 80 % emit bus event `cost.alert` (level warn), at 100 % emit `cost.alert` (level error); the UI maps it to state name `cost-alert`.
- Usage outbox: batches of `{id, type, qty, at, session_id?, agent_id?}` with `type` in `agent_minutes | tokens_in | tokens_out` (the only CT-API-USAGE types this lane can measure), at most 500 per batch, persisted in `<data>/usage/outbox.jsonl`, cap 10,000 pending events.
- Local-only mode: accounting runs with no account and never calls the network.

## Out of scope
- Uploading the outbox, retries and `Idempotency-Key` handling (usage client in packages/net, a later lane).
- `queue_items` and `relay_bytes` usage types; they are measured by the session/net lanes.
- Quota/entitlement display from CT-ENTITLEMENTS (lane C039 renders it; the server is authoritative).
- Token counting of a prompt before it is sent and compaction triggers (lane C019).

## Build against (no counterpart needed)
Scripted bus events from lane C025's test helpers and the catalog from lane C028. The shape of produced batches is validated against the CT-API-USAGE request schema generated by lane C003; no server is needed.

## Interfaces (the only surface other lanes may use)
- `interface Ledger { snapshot(scope: {agentId?: string; sessionId?: string}): LedgerTotals; onTurnUsage(u: TurnUsage): void; onAgentState(agentId: string, state: string, at: Date): void; dequeueBatch(max?: number): UsageEvent[]; ack(ids: string[]): void; requeue(ids: string[]): void }`
- `type LedgerTotals = {tokensIn: number; tokensOut: number; cacheRead: number; cacheWrite: number; agentMs: number; cost: {amount: number; currency: 'USD'}; estimated: boolean}`
- `type UsageEvent = {id: string; type: 'agent_minutes'|'tokens_in'|'tokens_out'; qty: number; at: string; session_id?: string; agent_id?: string}`
- `createLedger(deps: {clock: Clock; ids: IdGen; models: ModelRegistry; bus: EventBus; outboxPath: string}): Ledger`
- Bus events emitted: `cost.alert` ({level:'warn'|'error', pct, session_id}); slash `/cost`; config `budget.sessionUsd`.

## Acceptance criteria
1. A scripted turn with 1,200 input and 340 output tokens at catalog prices yields `cost.amount` equal to the hand-computed micro-USD rounded half-up to the nearest cent for display, with the micro value retained internally.
2. Agent minutes: 90 s in `thinking`, 30 s in `awaiting-approval`, 60 s in `editing-file` accumulate 150 s, emitted as a `agent_minutes` event with `qty` 3 (whole minutes, remainder carried, never fractional per CT-IDS).
3. `dequeueBatch()` never returns more than 500 events, each `id` is unique and monotonic, and re-dequeuing without `ack` returns the same ids after `requeue` (dedupe key stable).
4. The outbox survives a process restart: 1,000 queued events written before kill are returned afterwards, in order, with no duplicates.
5. With the outbox at 10,000 events a further event drops the oldest `tokens_in`/`tokens_out` event first and increments a `dropped` counter exposed in `snapshot()`; `agent_minutes` events are dropped last.
6. `budget.sessionUsd=1.00` produces exactly one `cost.alert` warn at $0.80 and one error at $1.00 per session, not repeated on later turns.
7. Unknown model (no price) sets `estimated: true` and cost 0 rather than throwing.
8. No usage event contains text, paths, branch names or model names.

## Tests required
- accounting/cost.test.ts: rounding, cache pricing, unknown model.
- accounting/minutes.test.ts: state accumulation with injected clock, remainder carry, excluded states.
- accounting/outbox.test.ts: persistence, cap/drop policy, batch size 500, requeue, crash restart.
- accounting/contract-shape.test.ts: every produced batch validates against the generated CT-API-USAGE request schema (body <= 1 MiB).
- accounting/budget.test.ts: alert thresholds fire once.

## Guardrails (MUST / MUST NOT)
- MUST use integer arithmetic for money and quantities (micro-USD, whole minutes); never floats on the wire (CT-IDS).
- MUST NOT include any work content in usage events; only type, qty, timestamps and ids.
- MUST treat the local ledger as an estimate; the server is authoritative at enforcement time (CT-ENTITLEMENTS), so no feature may be locked by local numbers alone.
- MUST keep generating events when offline or logged out; the outbox is the only buffer and is bounded.
- MUST stay bounded: outbox file rewrite on ack must be atomic, and memory holds at most one batch.

## Failure modes
- Outbox file corrupt -> move it to `outbox.corrupt.<ts>`, start empty, log at warn once, keep counting in memory.
- Provider usage fields missing on a turn -> record the turn with zero tokens, set `estimated: true`, and never block the turn.
- Clock moves backwards -> clamp negative durations to zero.
## Notes
CONTRACT GAP: CT-API-USAGE does not state the format of the event `id` (only that it dedupes); this lane uses a monotonic ULID without prefix. Free LAN usage is also counted locally but never uploaded unless a later lane decides otherwise.
