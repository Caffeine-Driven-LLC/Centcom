## Goal
The client aggregates the `usage.report` events engines emit into per-agent, per-session and per-day views, labelled as estimates exactly as the CLI reported them, warns about budgets using those reported values, and queues informational usage events for the user's dashboard without ever enforcing a plan limit locally.

## In scope
- Ledger fed by normalised `usage.report` events (tokens in/out, cache tokens, cost estimate as reported by the CLI, per-model breakdown when present; Claude Code gets these from `result.total_cost_usd` and the per-model usage, Codex from usage in its events) and by `agent.state` transitions for active minutes.
- Resumed sessions: Claude Code reports the conversation total on resume, so the ledger stores the last reported cumulative per engine session and records only the delta; a cumulative that goes down is treated as a new baseline.
- Views: per agent, per session, per calendar day (local time) and a rolling 7 days; `snapshot()` for the status line (lane C039) and `/usage` slash command (one-screen table). Every cost figure is shown with the label `est.` and, when the engine gave no cost, `not reported` (never computed from a price table).
- Soft budget on reported values: config `budget.sessionUsd` (unset by default); at 80 % emit `cost.alert` level warn, at 100 % level error, once each per session; the UI maps it to state `cost-alert`. Budgets only warn; they never stop an engine.
- Informational usage outbox: batches of `{id, type, qty, at, session_id?, agent_id?}` with `type` in `agent_minutes | tokens_in | tokens_out` (CT-API-USAGE; informational only, never enforced or billed), `id` = `use_` + ULID, at most 500 per batch, persisted in `<data>/usage/outbox.jsonl`, cap 10,000 pending.
- Local-only mode: runs without an account and never touches the network.
- Engine limit messages (plan cap, rate limit) are passed through as the CLI's own text and counted as `limit_events` in the snapshot; no local limit logic.

## Out of scope
- Uploading the outbox, retries and `Idempotency-Key` handling (usage client in packages/net, a later lane).
- `queue_items` and `relay_bytes` usage types, measured server-side.
- Any plan, quota or entitlement enforcement or display (CT-ENTITLEMENTS is rendered by lane C039; the server decides).
- Price tables, token counting and compaction triggers (lane C019 shows context; engines count tokens).

## Acceptance criteria
1. Replaying the Claude Code golden transcript with `total_cost_usd: 0.0421` yields `costUsdReported = 0.0421` labelled `estimate`; the `/usage` output contains `est.` next to every cost and no figure that is not present in the transcript.
2. A transcript with no cost field yields `costLabel: 'not-reported'` and the table shows `not reported`; a source scan test fails the build on any price/per-million constant in `packages/agent/src/accounting/`.
3. Resuming: two `usage.report` events with cumulative totals 1,000 then 1,600 input tokens add 1,600 in total (not 2,600); a drop from 1,600 to 200 on a new engine session id starts a new baseline.
4. Agent minutes: 90 s `thinking`, 30 s `awaiting-approval`, 60 s `editing-file` accumulate 150 s and emit an `agent_minutes` event with `qty` 3 (whole minutes, remainder carried); `idle`, `ready`, `sleeping`, `away`, `awaiting-approval`, `asking-question` are excluded.
5. `dequeueBatch()` never returns more than 500 events; each `id` matches `^use_[0-9A-HJKMNP-TV-Z]{26}$` and is unique; every batch validates against the generated CT-API-USAGE request schema.
6. The outbox survives restart (1,000 queued events returned in order, no duplicates); at 10,000 pending the oldest token events drop first, `agent_minutes` last, and `dropped` increments.
7. `budget.sessionUsd=1.00` with reported costs 0.85 then 1.05 emits exactly one warn (at >= 0.80) and one error (at >= 1.00) per session; no alert fires when costs are `not-reported`.
8. No usage event contains text, paths, branch names, model names or engine ids; with no account and no network the ledger still updates and nothing opens a socket (test with a blocked `net` module).
9. A reported engine limit message increments `limitEvents` and nothing else changes: no engine is stopped and no feature is disabled.

## Guardrails (MUST / MUST NOT)
- MUST NOT hard-code or fetch prices; a cost is shown only if the CLI reported it and is always labelled an estimate.
- MUST NEVER enforce plan limits or lock a feature from local numbers; usage types here are informational only, the server decides entitlements.
- MUST use integers for tokens, minutes and the outbox; reported USD floats are kept for display only and never put on the wire.
- MUST NOT put work content, model names or engine session ids in usage events.
- MUST stay bounded: atomic outbox rewrite on ack, memory holds at most one batch.

## Failure modes
- Outbox file corrupt -> move to `outbox.corrupt.<ts>`, start empty, warn once, keep counting in memory.
- `usage.report` fields missing or non-numeric -> record zeros, mark the turn `not-reported`, never block the turn.
- Clock moves backwards -> clamp negative durations to zero.
