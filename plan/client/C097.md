## Goal
When something breaks, users can run `centcom doctor` to diagnose their environment in seconds and, only if they opt in, produce a redacted crash report; nothing leaves the machine automatically.

## In scope
- `centcom doctor [--json] [--bundle <path>] [--check <id>...] [--timeout-ms 8000]` in apps/cli/src/doctor/ running independent checks in parallel and printing a pass/warn/fail list.
- Checks: node version >= 22; OS/arch; terminal (colour tier, truecolor, size >= 80x24, unicode); keychain round-trip with a throwaway entry via @napi-rs/keyring; git present and >= 2.30; config files parse and have 0600 perms where they hold references; network `GET /healthz` and `GET /v1/status` (status, `min_client_version` vs own version, `contract_version` compat); clock skew vs server (warn > 30 s, fail > 60 s, the CT-AUTH tolerance); relay reachability (WS upgrade with subprotocol `centcom.v1` then close, no ticket); auth state (`GET /v1/me` or 'not logged in'); LAN multicast availability for mDNS; update channel and install method.
- Crash capture in apps/cli/src/crash/: top-level handlers for uncaughtException/unhandledRejection write a redacted JSON report to the state dir (`crashes/<ts>.json`, max 10 kept, 64 KiB each) containing version, contract version, platform, stack with file paths reduced to package-relative form, error `code` (CT-ERR) and last 50 redacted log lines.
- Opt-in sharing: `centcom crash list|show|delete` and `centcom doctor --bundle` writing a local `.tar.gz` the user can attach to an issue; if telemetry is enabled, also emits `error.shown {code}` (CT-TELEMETRY) with code only.
- Redaction pass reusing the logger redaction (C005) plus path scrubbing (home dir -> `~`, repo names, branch names removed) with a deny-list test corpus.

## Out of scope
- Telemetry client and batching (C010).
- Any automatic upload of crash reports (none in v1; see notes).
- Logging framework itself (C005).
- Fixing issues found; doctor only reports and gives one next step.

## Interfaces (the only surface other lanes may use)
- centcom doctor [--json] [--bundle <path>] [--check <id>] [--timeout-ms <n>]; exit 0 all pass, 1 warnings only, 2 any failure
- JSON: {schema_version: 1, version, contract, checks: [{id, status: 'pass'|'warn'|'fail'|'skip', summary, next_step?, duration_ms}]}
- export interface DoctorCheck { id: string; run(ctx: DoctorContext): Promise<CheckResult> }
- centcom crash list | show <id> | delete <id|--all>
- Env/flags: CENTCOM_TELEMETRY=off and DO_NOT_TRACK=1 disable the telemetry emit; crash files are always local.

## Acceptance criteria
1. `centcom doctor` completes in <= 8 s even when the network is blackholed (each network check has a 3 s timeout, run in parallel).
2. Each failure line has exactly one `next_step`; for clock skew 61 s the check is `fail`, for 31 s `warn`, for 5 s `pass` (fake clock test).
3. `--json` output validates against the embedded schema; with `--check keychain` only that check runs.
4. Crash report from a thrown error containing `/home/alice/secret-repo/src/x.ts`, a fake token `cen_live_...`, a branch name and a message body contains none of them (redaction corpus of 30 strings, 0 leaks).
5. Crash dir never exceeds 10 files/640 KiB; the 11th crash evicts the oldest.
6. With telemetry off (default) no network call is made by crash capture or by `doctor` other than the diagnostic checks it displays; verified by a no-egress test on the crash path.
7. With telemetry on, a crash emits at most one `error.shown {code}` event and its payload has only `code` (schema-validated).
8. Keychain check creates and deletes a test entry and leaves no residue; on headless Linux without a secret service it reports `fail` with the next step 'install a Secret Service provider'.

## Guardrails (MUST / MUST NOT)
- MUST NOT include keys, tokens, ciphertext, decrypted payloads, message bodies, file contents, paths, repo or branch names in crash reports or doctor output (CT-CRYPTO section 7, CT-TELEMETRY rule 1).
- MUST NOT upload anything automatically; sharing is a manual user action in v1.
- MUST honour `DO_NOT_TRACK=1` and `CENTCOM_TELEMETRY=off` unconditionally.
- Doctor MUST NOT mutate user state beyond a self-cleaning keychain test entry and MUST NOT print secrets even when diagnosing auth.
- Crash handler MUST NOT swallow the failure: exit non-zero after writing the report; MUST NOT run complex logic (no network, no async I/O beyond one sync file write).

## Failure modes
- Check throws -> reported as `fail` with the text 'check crashed' (no stack shown to the user) and the other checks continue.
- State dir unwritable -> print the redacted report to stderr only if `--print` is passed, else explain.
- Relay check cannot distinguish blocked WS from relay down -> status `warn` with both hypotheses in `next_step`.
