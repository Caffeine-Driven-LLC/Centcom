## Goal
Implement the end-to-end encryption module exactly as CT-CRYPTO specifies, so frames, key grants, rotation, fingerprints and path MACs interoperate bit-for-bit with every other implementation, proved by the shared known-answer vectors.

## In scope
- libsodium bootstrap (`libsodium-wrappers`, exact-pinned; use the `-sumo` build only if a needed primitive is missing) with a typed, awaited `initCrypto()`.
- Device identity: generate X25519 and Ed25519 keypairs, persist private halves in the OS keychain via `@napi-rs/keyring` (account `device-keys:<dev id or pending>`), expose public halves as base64url; implements the C052 `DeviceKeyProvider` shape.
- Frame encryption: RFC 8785 canonical JSON, 24-byte random nonce, AAD = canonical_json({v,t,id,sid,from_dev,k,kid}), XChaCha20-Poly1305-IETF, output `ct {alg:'xchacha20poly1305', kid, n, c}`; decrypt with AAD recomputation; payload > 192 KiB rejected, plus chunk split/join (`chunk {i,n,group}`) helpers.
- Signing: Ed25519 over canonical_json({v,t,id,sid,from_dev,k,kid,n,c,p?}) (`p` only for hybrid frames); `verifyFrame` against a registered sender device key; verify before decrypt.
- `KeyRing`: per-session epoch keys `K[e]` held in memory, optionally persisted encrypted under a 32-byte keychain-held wrapping key; `kid = 'k'+epoch`; creation of `k1`; rotation rules (new epoch on kick/leave/revoke; scheduled every 7 days or 100 000 frames).
- Key grants: `sealGrants(keys, recipientX25519)` using `crypto_box_seal` per kid and `openGrants`; share-history-off variant (current and future epochs only); invite key bundle seal/open for the `#k=` fragment key.
- Fingerprints `fp = base32(BLAKE2b-128(D_x||D_s))` shown as `ABCD-EFGH-IJKL`; `TrustStore` (TOFU) returning `new | match | changed`; `path_hmac` via BLAKE2b keyed hash with `K_p[e]`.

## Out of scope
- Sending/receiving frames, REST calls for device keys or bundles, the roster: lane C057 and the transport lanes.
- Token handling and auth: lane C052.
- LAN pairing PAKE (CPace) and confirmation MACs: lane C073 (uses the primitives here).
- UI for fingerprint verification or key-change warnings: TUI lanes; this lane only emits the structured result.
- Optional Argon2id passphrase wrapping and key backup (not in v1).

## Acceptance criteria
1. Every entry in contracts/fixtures/crypto/vectors.json passes: encrypt with the fixed key/nonce/AAD yields the exact expected `c`, signing yields the exact `sig`, `pathHmac` yields the exact `path_hmac`; sealed-box output has the structural properties checked by the vectors (length, decrypts).
2. Round trip: for each event fixture with a `secret_payload` in contracts/fixtures/events/, encrypt then decrypt returns a deeply equal object and the result validates against the kind's `$defs.s_*` schema.
3. Changing any one of v, t, id, sid, from_dev, k or kid after encryption makes decryption throw `aead_failed` (7 mutations tested); flipping one bit of `c`, `n` or `sig` fails decrypt/verify.
4. `verifyFrame` fails for hybrid frames when `p` is altered, and passes when `p` is absent for encrypted-only frames; verification of a frame signed by a different device key returns false.
5. A second encryption of the same plaintext with the same key produces a different `n` and `c`; across 100 000 encryptions in a test no nonce repeats (24-byte random).
6. Plaintext producing a `ct` over 192 KiB throws `too_large`; `splitChunks` on a 500 KiB payload yields parts each <= 192 KiB with consistent `group`/`n` and `joinChunks` restores the original.
7. Grant flow: a host KeyRing with epochs k1,k2 seals grants to device B; B opens exactly [k1,k2]; with share-history off only [k2] is sealed; device C (different key) opens nothing (returns empty / null).
8. Rotation: `rotate('member_removed')` yields `k3`; frames encrypted afterwards use k3 and a ring lacking k3 cannot decrypt them; `shouldRotate` returns 'scheduled' at 7 days or 100 000 frames and null just below.
9. Fingerprint of fixed test keys equals the vector value, formatted `XXXX-XXXX-XXXX`; TrustStore returns `new` then `match`, and `changed` (never silent accept) when the Ed25519 key differs for a known device id.
10. Private keys and session keys never appear in any file under the temp HOME/config dir (test greps for the key bytes in hex/base64url); the keychain fake holds the private halves.
11. `initCrypto()` can be called concurrently 10 times and loads libsodium once.

## Guardrails (MUST / MUST NOT)
- MUST use only the primitives named in CT-CRYPTO (X25519, Ed25519, XChaCha20-Poly1305-IETF, BLAKE2b, crypto_box_seal); MUST NOT add algorithms or negotiate `alg` values other than `xchacha20poly1305`.
- MUST generate every nonce and key from libsodium's CSPRNG (`randombytes_buf`); MUST NOT use Math.random, a counter or a derived nonce.
- MUST verify the Ed25519 signature BEFORE attempting decryption and MUST drop frames that fail either step; MUST NOT surface plaintext of an unverified frame.
- MUST NOT write private keys, session keys, plaintext payloads or ciphertext to logs, error messages, telemetry, crash reports or config files; errors carry codes only.
- MUST persist session keys only encrypted under a keychain-held key; MUST zero secret buffers (`sodium.memzero`) when dropped.
- MUST treat a changed key for a known device as a warning result (`changed`), never silently accept or overwrite it.
- MUST use constant-time comparison for MACs, signatures and fingerprints (sodium compare functions); MUST NOT use `===` on secret bytes.
- MUST hold the AAD `from_dev` as the sender DEVICE id (known to the sender), not the server-stamped member id.

## Failure modes
- Unknown `kid` on an incoming frame -> `CryptoError('unknown_kid')`; the caller keeps the frame ciphertext and shows 'waiting for key' until a grant arrives (CT-CRYPTO §4).
- AEAD or signature failure -> drop the frame, count it, raise a protocol warning, never throw out of the receive loop.
- Keychain unavailable -> device keys cannot persist: `initDeviceKeys` throws KeychainUnavailableError; an in-memory ephemeral identity may be used only for LAN sessions and is flagged `ephemeral:true`.
- libsodium fails to load (WASM blocked) -> fail fast at `initCrypto()` with a clear error; no fallback to another library.
