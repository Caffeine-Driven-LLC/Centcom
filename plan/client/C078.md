## Goal
When two agents want the same file or a merge conflicts, every participant sees who holds the lock, for how long, and gets clear resolution actions (wait, take turns, branch off, resolve with Cento) without ever being shown plaintext paths to the relay.

## In scope
- Conflict state store in packages/tui/src/conflicts/ fed by `file.lock` (acquire, release, deny, expire) and `conflict.detected` frames and by the local lock client (C018) and fleet sync (C062).
- Lock chip and inspector panel: holder name + colour, agent, remaining TTL from `ttl_ms`, resolved display path taken from the decrypted `ct.path` when present, else a short `path_hmac` prefix.
- Banner and actions: `Wait`, `Take turns`, `Branch off`, and `Resolve with Cento` for merge conflicts, per DESIGN.md 12.5; actions invoke callbacks supplied by fleet sync / agent runner, they do not talk to the network.
- Mascot hooks: owning agent card state `merge-conflict`, waiting agent shows animation `waiting`, locked card `file_locked` through the state driver (C046).
- Text equivalents for every conflict state (status line copy via the message table, not inline strings).

## Out of scope
- Lock arbitration and TTL enforcement (relay or LAN host); local lock acquisition logic (C018).
- Git merge execution and conflict resolution agent prompts (agent runner).
- Web conflict UI (part of the fleet board, C084).
- Fleet panel layout (C042).

## Build against (no counterpart needed)
Drive with fixtures contracts/fixtures/events/file.lock.json and conflict.detected.json plus scripted sequences via the mock backend (lane C007); TUI snapshot tester (C008).

## Interfaces (the only surface other lanes may use)
- export function useConflicts(source: ConflictSource): {locks: LockView[]; conflicts: ConflictView[]}

- export function ConflictBanner(props: {conflict: ConflictView; onResolve(action: 'wait'|'take-turns'|'branch-off'|'resolve-with-cento'): void}): JSX.Element
- export function LockInspector(props: {locks: LockView[]; now: number}): JSX.Element

## Acceptance criteria
1. file.lock {action: acquire} then {action: deny} for a second agent shows the second agent as waiting, the holder's name and a countdown from ttl_ms updated once per second.
2. On `expire` or `release` the chip disappears within one render and the waiting agent returns to its real state.
3. conflict.detected with two agent_ids and one path_hmac renders a banner listing both agent owners and offers exactly the 4 documented actions; keyboard hints shown (`w`, `t`, `b`, `r`).
4. Display path comes only from the decrypted `ct.path`; if absent the UI shows `file ab12…` (first 4 chars of path_hmac) and never an empty label.
5. Priority rule from DESIGN.md 11.2: merge-conflict outranks tool-running on the owning agent card, but never outranks awaiting-approval being shown.
6. Chosen action returns a promise; while pending the buttons are disabled with reason text; a rejected promise shows a danger toast with the CT-ERR message, not a crash.
7. Banner is persistent (not auto-dismissed) until the conflict resolves; at most 2 banners stacked, extras collapse into `+N more`.

## Tests required
- conflicts.store.test.ts: acquire/deny/release/expire state machine incl. out-of-order delivery and duplicate seq.
- conflicts.render.snap.test.tsx: banner, chip, inspector at 80x24 and 120x40, NO_COLOR.
- conflicts.actions.test.ts: each action calls the callback once; double-press ignored.
- conflicts.privacy.test.ts: path text never logged and never placed in `p` of outgoing frames.

## Guardrails (MUST / MUST NOT)
- MUST treat locks as advisory; MUST NOT block the user from editing locally because the UI shows a lock.
- MUST NOT display or log paths derived from anything but the decrypted `ct` of that frame; path_hmac is the only cleartext identifier.
- MUST NOT use colour alone: conflict states carry the glyph `!` plus the word (DESIGN.md 4.4, 16.2).
- MUST NOT show the mascot in destructive confirmations (DESIGN.md 11.5); the Resolve confirmation is plain text.

## Failure modes
- ttl_ms missing -> show 'held' without countdown and drop on release/expire only.
- conflict.detected references an unknown agent id -> show 'an agent' and keep the banner.
- Lock `ct` cannot be decrypted (waiting_for_key) -> fall back to hmac label, upgrade label when key arrives.
