## Goal
New users and contributors can find accurate, searchable documentation: a user docs site, man pages, a repository README flow and built-in help that all come from one source and are checked in CI.

## In scope
- Docs site in docs/site/ (VitePress, static output, no tracking scripts): Getting started, Install (npm, Homebrew, binary), Login, Sessions (LAN, relay), Command post and branch mode, Roles and permissions, Queue and approvals, Privacy and encryption (what the relay can and cannot see, per CT-CRYPTO section 6), Billing and plans, Webhooks and notifications, Troubleshooting (`centcom doctor`), Keyboard shortcuts, Environment variables.
- Generated CLI reference: `tools/docs/gen-cli-reference.ts` reads command metadata from apps/cli (name, flags, descriptions) and writes docs/site/reference/cli/*.md and docs/man/*.1 (roff), so docs cannot drift from flags.
- Built-in help: `centcom help [topic]`, `centcom <cmd> --help` formatting (80 columns, NO_COLOR safe) and a `/help` text source consumed by the TUI help screen (C045); topics share the docs content.
- Docs for env vars from DESIGN.md 22.4 (`NO_COLOR`, `COLORTERM`, `CENTO_MASCOT`, `CENTO_REDUCE_MOTION`, `CENTO_SPINNER`, `CENTO_THEME`) and telemetry opt-out vars (`DO_NOT_TRACK`, `CENTCOM_TELEMETRY`).
- Link/spell/accessibility checks: lychee-style link checker script, cspell config, Lighthouse accessibility >= 95 on docs home.
- Content voice per DESIGN.md section 13 (terminology cheat-sheet: mission, command post, host, fleet, relay, queue).

## Out of scope
- Marketing site and brand assets (DESIGN.md 18).
- API reference for the backend REST API (generated from OpenAPI elsewhere; this site only links to it).
- First-run onboarding UI (C048) and TUI help screen widget (C045); this lane supplies content.
- Translations (English only in v1).

## Build against (no counterpart needed)

## Interfaces (the only surface other lanes may use)
- pnpm docs:dev | docs:build | docs:check  // check = links + spelling + generated-reference drift
- centcom help [topic]; centcom man  // prints the path/installs man pages when asked
- export function renderHelp(cmd: CommandMeta, opts: {width: number; colour: boolean}): string
- Generated outputs: docs/man/centcom.1, docs/man/centcom-<subcommand>.1

## Acceptance criteria
1. `pnpm docs:check` fails when a CLI flag exists in apps/cli but not in docs/site/reference/cli (drift test adds a fake flag and expects failure).
2. Every internal link resolves; every external link is checked weekly (non-blocking) and internal anchors on every PR (blocking).
3. Man pages pass `mandoc -Tlint` with 0 warnings and render in `man ./docs/man/centcom.1`; page header contains the current version and contract version.
4. `centcom --help` output is <= 80 columns wide, contains no ANSI codes when NO_COLOR is set or stdout is not a TTY, and lists every top-level command.
5. Docs site build output <= 5 MB, first load JS <= 120 KB gzip on the home page, Lighthouse performance >= 90 and accessibility >= 95.
6. The Privacy page states exactly the 'visible to relay' items from CT-CRYPTO section 6 (checked by a snapshot test comparing to a maintained list) and says traffic analysis is not hidden in v1.
7. Install page commands are tested: a CI job extracts the shell blocks tagged `<!-- test -->` and runs them in a clean container.
8. All documented environment variables exist in `apps/cli` config (test greps code for each name).

## Tests required

- help.render.test.ts (width, NO_COLOR, unknown topic).
- docs.links.check.ts.

- docs.lighthouse (LHCI).

## Guardrails (MUST / MUST NOT)
- MUST NOT include real tokens, keys, ids or emails in examples; use placeholders like `ses_01JA…` and `cen_live_…` truncated forms.
- MUST NOT make claims beyond the contracts for privacy; copy from CT-CRYPTO by link, do not paraphrase guarantees (e.g. no 'zero knowledge').
- MUST NOT load third-party scripts, fonts or analytics on the docs site; fonts self-hosted.
- Docs examples MUST use the terminology cheat-sheet; 'session' is the UI word for chat-like threads, 'command post' for the shared mode.

## Failure modes
- Generated reference out of date -> CI blocks merge with the diff and the regeneration command.
- Man page generation unavailable on Windows -> skipped there; `centcom help` is the universal path.
- Broken external link -> weekly issue created, not a PR blocker.
