## Goal
Spawn sub-agents from a running agent with bounded depth, budget and permissions, optional worktree isolation, and clean cancellation, reporting each spawn as an `agent.spawn` payload and driving the parent's `sub-agent` state.

## In scope
- `SubagentSpawner.spawn(parentId, spec)` creating a child through the runner (C013) with `parentAgentId` set; child receives a task prompt and returns a final text result capped at 8 KiB (truncated with a marker).
- Limits (config `subagent.*`, defaults): max depth 2, max 4 concurrent children per parent, children count against `agent.max_parallel`, per-child wall clock 15 min, max turns 20.
- Isolation modes: `shared` (read-only tools only, parent cwd), `worktree` (own worktree via C017, full tool set subject to permissions); default `shared`.
- Permission inheritance: child tool set = intersection of requested tools and the parent's currently allowed tools; the child never gets `bypassPermissions` and never exceeds the parent's permission mode; all child approvals go through the same permission engine (C015) annotated with `origin: childId -> parentId`; a child cannot resolve its own or its parent's approvals.
- Cancellation cascade: parent stop/interrupt stops all descendants within 5 s; child failure returns an error result to the parent without killing it.
- Payload builders: `agent.spawn` clear part `{ agent_id, owner, mode: 'command_post'|'branch' }` and secret `{ label?, branch?, worktree?, model? }`; `agent.exit` clear `{ agent_id, outcome: 'ok'|'error'|'canceled', error_code? }` for each child.
- Bus events `subagent:spawned` / `subagent:finished`; parent signals `sub-agent` to the state machine (C014) while any child runs.

## Out of scope
- Cross-machine agents (agents of other members): session layer.
- Merging a child's branch back: user action / later git lanes.
- Model selection policy and cost limits beyond turn/time caps.
- Sending the payloads over the wire: session lanes.

## Build against (no counterpart needed)
FakeSdkAdapter via the runner (lane C013), worktrees from real git on throwaway repos (lane C017 helpers) and the permission engine (lane C015) with synthetic decisions; no network.

## Interfaces (the only surface other lanes may use)
- `createSubagentSpawner(deps: { runner: AgentRunner; worktrees: WorktreeManager; permissions: PermissionEngine; bus: AgentBus; ids: IdGenerator; clock: Clock; config: SubagentConfig }): SubagentSpawner`
- `interface SubagentSpawner { spawn(parent: AgentId, spec: { task: string; isolation?: 'shared'|'worktree'; tools?: string[]; model?: string; label?: string }): Promise<SubagentHandle>; list(parent: AgentId): SubagentHandle[]; cancelAll(parent: AgentId): Promise<void> }`
- `interface SubagentHandle { id: AgentId; parent: AgentId; depth: number; result(): Promise<SubagentResult> }`; `SubagentResult = { outcome: 'ok'|'error'|'canceled'; text: string; truncated: boolean; error_code?: string }`.
- `spawnPayload(h): { clear: { agent_id; owner; mode }; secret: { label?; branch?; worktree?; model? } }`; `exitPayload(h, r): { clear: { agent_id; outcome; error_code? }; secret: { detail? } }`.

## Acceptance criteria
1. Depth limit: a child at depth 2 attempting to spawn fails with `SubagentDepthExceeded`; the 5th concurrent child of one parent rejects with `SubagentLimit`; with `agent.max_parallel=4` and 3 running agents only 1 child can start.
2. Tool intersection: parent allows [Read, Grep], spec requests [Read, Edit, Bash] -> child gets [Read] only; `bypassPermissions` on the parent yields child mode `default`.
3. Child approval requests are tagged with the parent id and appear in the engine's `pending()`; `resolveApproval` called with the child's own member/agent identity is rejected.
4. `cancelAll(parent)` or parent `stop()` stops 4 children within 5 s (fake clock) and each emits `agent:exited{outcome:'canceled'}`; no timers remain.
5. A child exceeding 15 min is stopped with `outcome:'error', error_code` set to a local code string of <= 200 chars and the parent receives an error result.
6. Result text longer than 8 KiB is truncated to 8192 bytes with a marker and `truncated:true`.
7. Worktree isolation: child cwd is its own worktree path; on child exit with no changes the worktree is removed, with changes it is kept and reported in the secret payload `branch`.
8. Payloads pass the generated `agent.spawn` and `agent.exit` clear-schema validators; the clear part contains no label, branch, path or model.

## Guardrails (MUST / MUST NOT)
- A child MUST NEVER hold more privilege than its parent (tools, permission mode, filesystem root); privilege only narrows.
- Children MUST NOT approve their own or any ancestor's requests; approvals route to the same humans as the parent's.
- Clear payloads MUST NOT carry label, branch, worktree path or model name (privacy budget; those are in the encrypted part).
- MUST enforce depth, concurrency and time limits with the injected clock and MUST clean up worktrees/timers on every exit path (including crash).
- MUST NOT let a child run with cwd outside the parent's root.

## Failure modes
- Runner at capacity -> `SubagentLimit` returned to the parent as a tool error; parent continues.
- Worktree creation fails -> spawn fails with the worktree error; no half-started child.
- Parent crashes -> children are cancelled on runner cleanup, never orphaned.
## Notes
Mode in `agent.spawn` is `command_post` or `branch` (the session mode), not the isolation mode; the spawner takes the session mode from the parent's context. Defaults for depth/concurrency are product choices.
