## Goal
Run a fleet of N agents, each an engine process started through the runner in its own git worktree and branch, with naming, a concurrency limit from entitlements/config, lifecycle and cleanup, native-subagent children in the fleet view, and merge-back readiness hooks.

## In scope
- `FleetManager.spawn(spec)` creates a worktree via C017 (`WorktreeManager.create`), then starts an engine process through the runner (C013) with `cwd` = that worktree and the chosen engine (`claude-code` or `codex`); one agent = one worktree = one branch; branch name `centcom/<ownerSlug>/<label-slug>-<id6>`, label default `agent-<n>`; `ownerSlug` and label sanitised to `[a-z0-9-]`, max 48 chars.
- Concurrency limit = `min(entitlements.limits.max_parallel_agents, config fleet.max_parallel (default 8))`; extra spawns wait in a FIFO queue (max 32 queued, then `FleetQueueFull`); fairness: round-robin across owners when several members share the host, so no owner holds more than `ceil(limit / activeOwners)` slots while others wait.
- Provider pacing: because parallel agents can hit CLI plan limits quickly, a per-engine spawn stagger (config `fleet.stagger_ms`, default 1 500) and automatic pause of new spawns for that engine when any agent reports `provider_cap_reached` or `provider_rate_limited` (running agents are not killed); resumed manually or after the engine's reported reset time.
- Lifecycle states `queued|starting|running|waiting|done|failed|canceled`; `stop(id)` uses the engine's interrupt (SIGINT for Claude, protocol interrupt for Codex) then terminates after 5 s; `stopAll()` finishes within 8 s; per-agent wall clock cap `fleet.max_minutes` (default 60, 0 = none).
- Cleanup: on exit, a worktree with no changes is removed (C017); one with changes is kept and the agent is marked `branch ready` when it has commits ahead of base and a clean tree, otherwise `needs attention`; crash recovery on startup lists orphaned worktrees from the previous run (`prune` offered, never automatic deletion of changed worktrees).
- Native subagents: engine events carrying `parent_tool_use_id` (Claude `--agents`, `--forward-subagent-text`) are mapped to child nodes under the parent agent in the fleet tree (`FleetNode { id, parent?, kind: 'agent'|'subagent', state, label }`); children share the parent's worktree, do not count against the concurrency limit, and raise the parent's `sub-agent` state signal for C014 while any child runs.
- Merge-back helper hooks: `onBranchReady(handler)` fires `{ agentId, branch, ahead, files }` when an agent finishes with commits; helper `mergePreview(agentId)` calls C017 `detectConflict` against the base and returns the conflicting paths; Centcom never merges, pushes or deletes branches by itself.
- Wire payload builders: `agent.spawn` clear `{ agent_id, owner, mode, runs_on, provider }` and secret `{ label, branch, worktree, model }`; `agent.exit` clear `{ agent_id, outcome, error_code? }`; native subagents are not sent as separate `agent.spawn` events (they appear only in the encrypted detail of the parent's transcript events).

## Out of scope
- Worktree creation internals, locks and conflict detection: C017, C018. Engine process IO and approvals: C013, C101-C103, C015.
- Agents on other members' machines: the session layer (a member's own FleetManager runs their agents). Sending payloads over the wire: session lanes.
- Merging, pushing, opening PRs or deleting branches automatically: user action or later lanes.
- Choosing models or cost policy; who-pays banners and the command-post gate: C105.

## Acceptance criteria
1. With `max_parallel_agents` 4 in the entitlements fixture and 6 spawns, exactly 4 engines start, 2 are `queued`, and when one finishes the oldest queued starts within one tick; 33 queued spawns beyond the limit reject the 33rd with `FleetQueueFull`.
2. Each started agent's engine process cwd equals its own distinct worktree path, and branch names match `^centcom/[a-z0-9-]+/[a-z0-9-]{1,48}-[a-z0-9]{6}$`; two agents with the same label get different branches.
3. Spawns for one engine are separated by >= 1 500 ms (fake clock); after a `provider_cap_reached` event from one Claude agent, further Claude spawns throw `FleetEnginePaused` while a Codex spawn still succeeds and running agents are not interrupted.
4. With three owners and limit 6, no owner exceeds 2 running agents while another owner has a queued spawn (property test over 1 000 random schedules).
5. `stopAll()` with 8 running fake engines completes within 8 s (fake clock): interrupt first, terminate after 5 s for the unresponsive one, and `fleet:node` shows all `canceled`; no timers or child processes remain (pid check).
6. An agent that finishes with 2 commits and a clean tree fires `onBranchReady` once with `ahead: 2`; one with no changes has its worktree removed; one with uncommitted changes is kept, marked `needs attention`, and never auto-removed.
7. A transcript event with `parent_tool_use_id` creates a `FleetNode kind:'subagent'` under the right parent, does not consume a concurrency slot (limit test), and the parent signals `sub-agent` until the child's end event.
8. Payloads pass the generated `agent.spawn` and `agent.exit` clear-schema validators; the clear part contains no label, branch, path or model, and `provider` is `anthropic` for `claude-code` and `openai` for `codex`.
9. `recoverOrphans` after a simulated crash lists the 3 leftover worktrees and removes none.

## Guardrails (MUST / MUST NOT)
- MUST give every agent its own worktree; two engines MUST NEVER share a cwd, and a cwd MUST stay inside the repo's worktree root.
- MUST NOT delete a worktree or branch that has uncommitted or unmerged work, and MUST NOT merge, push or force anything automatically.
- Clear payloads MUST NOT carry label, branch, worktree path or model name (privacy budget); those stay in the encrypted part.
- MUST enforce the concurrency limit from entitlements on the host (the relay also checks) and MUST NOT retry aggressively after a provider limit event: pause and show the CLI's own message.
- Each agent runs on its owner's engine login only (CT-PROVIDER rule 4); the fleet MUST NOT start an agent on behalf of another member unless C105 allows the mode.
- Every exit path (crash, stop, timeout) MUST clear timers and release the worktree slot with the injected clock.

## Failure modes
- Worktree creation fails (`NotAGitRepo`, `BranchExists`, `GitTimeout`) -> spawn fails with that error, no half-started engine, slot released.
- Engine fails to start (`provider_not_installed`, `provider_not_signed_in`) -> agent `failed` with the engine's message shown verbatim; the worktree is removed if untouched.
- Runner daemon dies -> agents marked `failed`, worktrees kept, `recoverOrphans` offered on next start.
## Notes
Replaces the earlier in-process SubagentSpawner (path packages/agent/src/subagents/ is now packages/agent/src/fleet/). Native subagents are the engine's own feature, so depth, tools and permissions of children are the engine's; Centcom only displays them. `mode` in `agent.spawn` is the session mode (`command_post` or `branch`) taken from the session context. Defaults (8, 1 500 ms, 60 min) are product choices. SPLIT? the fairness scheduler could be its own lane if it grows.
