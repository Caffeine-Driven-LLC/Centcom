## Goal
Let the user view, validate and edit the project settings that define the engines' native hooks (Claude Code `settings.json` hooks, Codex equivalents if documented), with ready-made templates and backed-up, confirmed edits. Centcom never executes hooks; the engines do.

## In scope
- Read and edit hook definitions in Claude Code settings files: project `<repo>/.claude/settings.json` (shared), `<repo>/.claude/settings.local.json` (personal) and user `~/.claude/settings.json` (user scope needs extra confirmation); only the `hooks` object is touched, all other keys preserved byte-for-byte via a minimal JSON patch.
- Per-session injection variant: build a `--settings <file-or-json>` payload containing only chosen hooks for a single run (no file written), used by the fleet and by templates marked 'this session only'.
- Codex: show and edit hook-like settings only where the installed Codex documents them (e.g. a `notify` command in the project-scope config); if none are documented for the detected version the Codex tab says so and offers nothing to edit (capability check, no guessing).
- Validation against a local schema: Claude events `PreToolUse`, `PostToolUse`, `UserPromptSubmit`, `Notification`, `Stop`, `SubagentStop`, `PreCompact`, `SessionStart` (the engine's `system/init` or docs-pinned list; unknown events are kept and flagged `unknown_event`); each hook `{ type:'command', command: string, timeout?: number }`, `matcher` string; limits 8 hooks per event, command <= 1 024 chars, timeout 1..600 s.
- Templates (data files in `packages/agent/src/hooks/templates/*.json`): `notify-on-approval` (a Notification hook calling `centcom notify --kind approval`), `run-formatter-after-edit` (PostToolUse on `Edit|Write` running a user-chosen formatter command from a fixed list `prettier --write`, `gofmt -w`, `black`), `block-force-push` (PreToolUse on `Bash` calling a bundled checker script text shown in full), `log-session-stop`. Template commands are shown in full in the diff.
- Safe edit: `plan()` -> diff -> confirmation (hash-bound) -> backup `<file>.centcom-bak.<yyyymmddHHMMSS>` (keep last 5) -> atomic write; 'dry validate' mode runs only schema validation.
- Hook warnings view: lists hooks whose command is not found on PATH (lookup only, no execution) and hooks defined in a shared file that came from a git pull (file hash changed since the user last confirmed), flagged 'review before running'.

## Out of scope
- Running hooks, timeouts, exit-code handling, blocking semantics: the engines' own. Centcom does not wrap or intercept tool calls here.
- The permission engine and approval UI: C015; engine approval bridging: C102, C103.
- A hook marketplace or remote templates; hooks that call model APIs.
- Skills, MCP config and memory files: C020, C021, C023.

## Build against (no counterpart needed)
Temp-dir settings fixtures (with comments-free JSON, extra keys, large files), FakeEngine (C101) status events for the version/capability check; no real CLI.

## Interfaces (the only surface other lanes may use)
- `createHooksManager(deps: { fs: HooksFs; engines: { capabilities(engine: EngineId): CapabilitySet | undefined; settingsPaths(engine: EngineId, scope: 'project'|'local'|'user', root?: string): string | undefined }; clock: Clock; log: Logger }): HooksManager`
- `interface HooksManager { list(root?: string): Promise<HookEntry[]>; validate(entry: HookDef): ValidationIssue[]; templates(): HookTemplate[]; plan(op: { kind: 'add'|'update'|'remove'; engine: EngineId; scope: 'project'|'local'|'user'; event: string; def?: HookDef; index?: number; root?: string }): Promise<HooksPlan>; apply(plan: HooksPlan, confirm: { accepted: true; planHash: string }): Promise<ApplyReport>; sessionSettingsArg(defs: HookDef[]): string }`
- `interface HookDef { matcher?: string; command: string; timeout_s?: number }`; `ValidationIssue = { code: 'unknown_event'|'too_many'|'too_long'|'bad_timeout'|'command_not_found'|'bad_matcher'; message: string }`.
- CLI: `centcom hooks list|add --template <id>|remove|validate [--scope project|local|user]`.

## Acceptance criteria
1. Adding template `run-formatter-after-edit` with `prettier --write` to a settings.json containing `permissions` and `env` keys produces a diff touching only `hooks.PostToolUse`; after apply the other keys are byte-identical and a `.centcom-bak.<ts>` backup exists.
2. A 9th hook for one event yields `ValidationIssue code:'too_many'` and `plan` refuses; a `timeout_s` of 0 or 601 yields `bad_timeout`.
3. A hook event `Frobnicate` is preserved in the file when other hooks are edited and listed with `unknown_event`; it is never deleted by Centcom.
4. `apply` with a stale `planHash` writes nothing (`PlanChanged`); without `accepted: true` writes nothing; user scope requires `confirm.userScope === true`.
5. `sessionSettingsArg` returns a JSON string `{"hooks":{...}}` containing only the given hooks and writes no file (fs write count 0).
6. With a recorded Codex version that documents no hooks, `list` for engine `codex` returns `{ supported: false }` and `plan` for codex throws `CapabilityMissing`.
7. Grep of `packages/agent/src/hooks/` shows no import of `child_process` and no spawn call; a lint test enforces this.
8. Settings JSON larger than 1 MiB or invalid JSON is refused with `SettingsInvalid` and the file is untouched; backup rotation keeps exactly the 5 newest backups after 7 edits.

## Guardrails (MUST / MUST NOT)
- MUST NOT execute, test-run or intercept hooks; they are arbitrary code run by the engine, so every command is shown in full in the diff before confirmation.
- MUST NOT write without a hash-bound confirmation and a backup; MUST NOT touch any key other than `hooks` (or the documented Codex notify setting).
- MUST NOT put secrets in hook commands: `looksLikeSecret` (C005) hits are refused without echoing the content.
- MUST NOT read credential files; only the settings files listed above are opened.
- Hooks in a shared project file that changed since last confirmation are flagged for review rather than silently accepted.

## Failure modes
- Settings file missing -> created with only `{ "hooks": {...} }` after confirmation, directory `.claude/` created 0755.
- Settings file locked or unwritable -> typed `unwritable` error, backup not created, nothing changed.
- Engine version unknown -> allow edits of the documented events, banner 'could not verify against your installed version'.
