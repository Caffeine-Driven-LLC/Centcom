## Goal
A hooks engine that runs user- or project-configured commands at agent lifecycle points (before/after tools, prompt submit, stop, compaction) with strict timeouts, a clear blocking contract, and trust gating for project-supplied hooks.

## In scope
- Config: user `<config dir>/hooks.json` and project `.centcom/hooks.json`: `{ hooks: { <Event>: [{ matcher?: string, command: string[], timeout_ms?: number }] } }`; events `SessionStart`, `UserPromptSubmit`, `PreToolUse`, `PostToolUse`, `Stop`, `SubagentStop`, `PreCompact`, `Notification`.
- Commands are argv arrays executed without a shell; JSON event on stdin (`{ event, agent_id, tool?: { name, input }, result?: ..., cwd }`); defaults: timeout 10 000 ms (max 60 000), stdout/stderr cap 64 KiB each, max 8 hooks per event, run sequentially in config order (user before project).
- Exit-code contract: 0 = continue (stdout JSON optional); 2 = block (stderr text returned to the agent as the reason); any other non-zero = non-blocking error (logged, agent continues). Optional stdout JSON `{ decision: 'allow'|'deny'|'ask', reason?: string, updated_input?: object }` for `PreToolUse`; `deny` blocks, `allow` never overrides a permission-engine deny, `ask` forces approval.
- `matcher` is a tool-name glob (`Bash`, `Edit|Write`, `mcp__github__*`) for tool events.
- Trust gate: project hooks run only when `TrustStore.isTrusted('hooks', sha256(file bytes))`; changed file means untrusted again; `needsTrust` surfaced to the UI.
- Child env: allow-list (PATH, HOME, LANG, TERM, TMPDIR) plus `CENTCOM_HOOK_EVENT`, `CENTCOM_AGENT_ID`; never tokens.
- Integrates as a `PermissionGate` decorator for `PreToolUse` (runs before the permission engine and can only tighten) and as bus listeners for the other events.

## Out of scope
- The permission engine itself: lane C015. Trust store implementation: lane C013.
- A hook marketplace or remote hooks. Hooks that modify model output (not supported).
- UI for authoring hooks.

## Interfaces (the only surface other lanes may use)
- `createHooksEngine(deps: { fs: HooksFs; spawn: SpawnFn; trust: TrustStore; clock: Clock; bus: AgentBus; log: Logger; config: HooksConfig }): HooksEngine`

- `HookOutcome = { blocked: boolean; reason?: string; decision?: 'allow'|'deny'|'ask'; updatedInput?: unknown; errors: number }`.

## Acceptance criteria
1. A `PreToolUse` hook exiting 2 with stderr `no force pushes` blocks the tool and the agent receives exactly that reason text; exit 1 is logged and does not block.
2. A hook printing `{decision:'allow'}` does NOT turn a permission-engine `deny` into allow (integration test with C015 stub): the combined outcome is deny.
3. A hook sleeping 20 s with `timeout_ms: 10000` is killed at 10 000 ms (fake clock; SIGTERM then SIGKILL after 2 s) and counted as a non-blocking error.
4. stdout of 1 MiB is truncated at 64 KiB and the hook is not failed solely for that; invalid JSON stdout from a hook that exited 0 is ignored with a warning.
5. Project hooks file is not executed (spawn count 0) until trusted; modifying one byte of the file untrusts it; user hooks run without prompting.
6. Matcher `Edit|Write` triggers for Edit and Write and not for Bash; `mcp__github__*` matches `mcp__github__create_issue`.
7. The spawned env contains `CENTCOM_HOOK_EVENT` and none of the poisoned variables from the parent (token/secret names).
8. 9th hook for an event is ignored with a warning; execution order equals config order.

## Tests required

## Guardrails (MUST / MUST NOT)
- MUST NOT run project hooks without local trust bound to the file hash; hooks are arbitrary code execution.
- Hooks MUST NOT be able to loosen security: a hook `allow` cannot override a permission-engine or hard `deny`; `updated_input` is re-validated by the permission engine afterwards.
- MUST spawn by argv without a shell; MUST NOT interpolate event data into command strings.
- MUST NOT log hook commands, stdin payloads, stdout/stderr contents or tool inputs; log event name, duration, exit code.
- Every hook is time-limited (default 10 s, max 60 s) and output-capped (64 KiB).

## Failure modes
- Hook binary missing -> non-blocking error `spawn_failed`, agent continues.
- Hook crash/timeouts on `PreToolUse` -> do not block (fail open for hooks only because the permission engine remains the fail-closed control).
- hooks.json invalid -> ignored with a warning; no hooks run.
## Notes
Event names follow the common agent-hook vocabulary; they are internal to the client and not a contract.
